# 项目概况

> [!abstract] 一句话
> JD 商城是一个「==无后端、纯前端==」的 Vue 3 单页应用：页面只有商品列表、商品详情、购物车三个，数据来自两份本地 JSON，核心学习价值在于**组件拆分、路由、响应式状态、父子通信和 localStorage 持久化**的完整串联。

---

## 一、项目定位

这是一个京东风格的商城前端实验项目，包名 `vue_lab2`。它不是完整电商系统，而是一个**结构完整、规模可控的教学样例**：

- 有真实感的数据（61 件商品、600 条评论，包含价格、品牌、店铺、参数、多张图片）
- 有完整的购物主链路（浏览 → 搜索 → 查看详情 → 加购 → 改数量 → 结算）
- 没有后端依赖，`npm install && npm run dev` 即可运行
- 代码全部使用 Vue 3 `<script setup>`，没有 TypeScript，阅读门槛低

> [!info] 适合学习什么
> - Vue 3 Composition API：`ref`、`reactive`、`computed`、`watch`
> - `<script setup>` 与 `defineProps` / `defineEmits`
> - Vue Router 4：动态路由、查询参数、编程式导航
> - 自定义 `v-model`（`NumAddDel`）
> - 模块级共享状态与 `localStorage` 持久化
> - CSS Grid / Flex / 响应式断点 / CSS 变量
> - 从 JSON 到页面的完整数据链路

## 二、功能清单

### 2.1 商品浏览

- 商品列表每页 12 条，共 61 条数据，因此有 6 页
- 卡片展示主图、标题、店铺名、价格
- 点击卡片进入详情页
- 支持关键字搜索（标题、品牌、店铺名、商品参数值）
- 支持上一页 / 页码 / 下一页

### 2.2 商品详情

- 主图轮播（Swiper，自动播放，间隔 3 秒）
- 商品标题、店铺、价格
- 数量选择（1–99）
- 加入购物车
- 商品参数表（`params` 对象逐项展示）
- 商品详情长图（`detailImageUrls`）
- 用户评价：头像、昵称、时间、正文、追评、晒图
- 右侧/左侧固定快速导航：商品信息、商品图片、用户评价、回到顶部

### 2.3 购物车

- 商品列表、单价、数量、数量加减、小计、删除
- 删除前二次确认
- 空购物车状态与「去逛逛」入口
- 固定底部结算栏：总件数、总金额、去结算
- 结算确认后清空购物车并提示「下单成功」
- 刷新页面后购物车仍然保留

### 3.1 分层逻辑

| 目录 | 角色 | 判断标准 |
| --- | --- | --- |
| `views/` | 路由页面 | 每个文件对应路由表里的一个 `component` |
| `components/` | 页面内的业务组件 | 被页面或其它组件引用，不直接对应 URL |
| `components/common/` | 通用组件 | 不依赖具体业务，理论上可搬到别的项目 |
| `api/` | 数据访问层 | 只负责「取数据、转字段」，不关心页面长什么样 |
| `stores/` | 共享状态层 | 跨页面、跨组件共享的可变状态 |
| `router/` | 路由配置 | URL 与页面组件的映射 |
| `database/` | 原始数据 | 模拟后端返回值 |

> [!note] `views` 和 `components` 的区别
> `views` 是「页面」，由路由直接渲染；`components` 是「页面里的零件」。例如 `goods-detail.vue` 是页面，`goods-gallery.vue` 是它里面的轮播零件。详见 [[组件树与职责]]。

## 四、数据说明

### 4.1 商品数据 `products.json`

每条商品的主要字段（原始数据使用下划线命名）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `sku_id` | string | 商品唯一编号，路由参数与购物车主键 |
| `title` | string | 商品标题 |
| `price` | string | 价格（原始为字符串，归一化时转 `Number`） |
| `brand` | string | 品牌 |
| `shop_name` | string | 店铺名 |
| `params` | object | 商品参数，键值都是中文 |
| `main_image_urls` | string[] | 主图列表 |
| `detail_image_urls` | string[] | 详情图列表 |
| `product_url` | string | 原始商品链接 |
| `crawled_at` | string | 抓取时间 |
| `discovery_keyword` | string | 发现该商品时用的关键词 |

数据统计：

```text
商品总数：61
价格范围：¥2.75 – ¥21,999
参数数量：每个商品 3 – 34 项
主图：全部商品至少 1 张
详情图：全部商品至少 1 张
```

### 4.2 评论数据 `comments.json`

| 字段 | 说明 |
| --- | --- |
| `sku_id` | 关联商品 |
| `comment_id` | 评论唯一编号 |
| `user_nickname` | 昵称（带脱敏，如 `云***节`） |
| `user_avatar_url` | 头像 URL |
| `content` | 评论正文 |
| `after_content` | 追评内容，可能为空 |
| `score` | 评分，数据中多为 `null` |
| `comment_time` | 评论时间（如 `10-05`） |
| `images_urls` | 晒图 URL 列表 |

数据统计：

```text
评论总数：600
每个商品评论数：1 – 10 条，平均约 9.8 条
带追评：8 条
```

> [!warning] 一个数据细节
> 评论的 `user_nickname + comment_time` 组合在 600 条数据中有 127 组重复。`comment-list.vue` 用它作为 `v-for` 的 `key`，会产生重复 key，详见 [[商品详情组件]] 与 [[代码质量与改进]]。

## 六、项目边界与设计取舍

### 6.1 没有后端

`src/api/goods.js` 的「接口」实际上是同步查询 + `setTimeout` 包装成 Promise。这样做的好处是：

1. 页面代码可以按真实异步请求来写（`await`、`try/catch/finally`、`loading`）。
2. 将来换成 Axios / fetch 时，页面层几乎不用改。
3. 不需要启动后端服务，适合实验课。

### 6.2 没有 Pinia

购物车状态放在 `src/stores/cart.js`，模块顶层创建 `reactive` 对象，所有组件通过 `useCart()` 拿到同一份引用。对当前规模来说足够；如果项目继续扩大，迁移 Pinia 是自然的下一步，详见 [[代码质量与改进]]。

### 6.3 没有 TypeScript

全部是 JavaScript。`jsconfig.json` 只配置了 `@/*` 路径别名，用于编辑器跳转，不做类型检查。好处是阅读门槛低；代价是字段拼写、参数类型只能靠运行时发现。

### 6.4 视觉优先于工程化

项目在 CSS 上投入较多（渐变头部、卡片阴影、响应式网格、固定结算栏、过渡动画），但没有 ESLint、测试、CI、README 内容。它更像一份「把 Vue 用起来」的作品，而不是生产级工程。

## 七、小结

这个项目的结构可以用一句话概括：

```text
入口（index.html / main.js）
  ↓
外壳（App.vue：TabHeader + RouterView）
  ↓
三个路由页面（views）
  ↓
业务组件（components） + 数据层（api） + 共享状态（stores）
  ↓
本地 JSON（database） + localStorage
```

理解它需要抓住两条主线：

1. **只读数据线**：`products.json` → `normalizeProduct` → `fetchGoodsList` / `fetchGoodsDetail` → 页面 → 组件。
2. **可变状态线**：详情页加购 → `cart.js` 的 `state.items` → `computed` 汇总 → `watch` 写 `localStorage` → 购物车页与角标同步更新。
