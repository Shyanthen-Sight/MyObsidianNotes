# 加入购物车与结算

> [!abstract] 一句话
> 购物车相关的四条交互——==加购、改数量、删除、结算==——都围绕同一份 `state.items`：详情页 `add()` 写入，购物车页 `setCount()` / `remove()` 修改，`FooterFixed` 的 `clear()` 清空；每次变化都会通过 `computed` 更新金额与角标，并通过 `watch` 自动写入 localStorage。

---

## 一、加购流程

### 1.1 起点：详情页数量

`components/detail/goods-info-panel.vue`：

```js
const count = ref(1)
const { add } = useCart()

function increase() {
  count.value = Math.min(count.value + 1, 99)
}
function decrease() {
  count.value = Math.max(count.value - 1, 1)
}
function addToCart() {
  add(props.product, count.value)
}
```

```vue
<button class="add-cart-button" type="button" @click="addToCart">
  加入购物车
</button>
```

### 1.2 `add()` 的两种分支

```js
function add(product, count = 1) {
  const existingItem = state.items.find(
    (item) => item.skuId === product.skuId,
  )

  if (existingItem) {
    existingItem.count = Math.min(existingItem.count + count, 99)
    return
  }

  state.items.push({
    skuId: product.skuId,
    title: product.title,
    cover: product.mainImageUrls[0],
    price: product.price,
    shortInfo: product.shortInfo || '',
    count: Math.min(Math.max(count, 1), 99),
  })
}
```

```text
购物车里已有该 skuId？
  ├─ 是 → 原数量 + 本次数量，上限 99
  └─ 否 → 新建条目，数量夹在 1–99
```

### 1.3 加购时序

```text
用户          GoodsInfoPanel        cart store         CartDot / Cart / Footer
 │                 │                    │                     │
 │ 选数量 2         │                    │                     │
 │ 点「加入购物车」  │                    │                     │
 ├────────────────►│                    │                     │
 │                 │ add(product, 2)    │                     │
 │                 ├───────────────────►│                     │
 │                 │                    │ find(skuId)         │
 │                 │                    │ 不存在 → push       │
 │                 │                    │ count = 2           │
 │                 │                    │                     │
 │                 │                    │ computed 失效        │
 │                 │                    ├────────────────────►│
 │                 │                    │ totalCount = 2      │
 │                 │                    │ totalAmount = …     │
 │                 │                    │ 角标显示 2          │
 │                 │                    │                     │
 │                 │                    │ watch(deep)         │
 │                 │                    │ → localStorage      │
 │◄────────────────┴────────────────────┴─────────────────────┤
```

### 1.4 加购后的表现

| 位置 | 变化 |
| --- | --- |
| 顶部购物车角标 | `totalCount` 增加，显示新数字（>99 显示 `99+`） |
| 购物车页 | 多一行，带淡入动画 |
| 结算栏 | 件数、合计更新 |
| localStorage | 自动写入 |
| 详情页数量 | **保持原值，不重置** |

> [!tip] 数量不重置是特性还是问题？
> 目前加购后 `count` 不变。用户再次点击会继续加同样数量，符合「批量加购」的预期。若希望每次加购后回到 1，可在 `addToCart` 末尾加 `count.value = 1`。另外建议加成功提示：
>
> ```js
> ElMessage.success(`已加入购物车（${count.value} 件）`)
> ```

### 1.5 加购的边界情况

| 情况 | 行为 |
| --- | --- |
| 同一商品重复加购 | 合并数量，不新增行 |
| 已有 98 件再加 5 件 | `Math.min(103, 99)` → 99 |
| `mainImageUrls` 为空 | `cover` 为 `undefined`，购物车破图 |
| 未登录 | 无登录概念，直接加购 |
| 刷新页面 | 购物车从 localStorage 恢复 |

## 二、修改数量流程

### 2.1 组件链路

```text
CartItem
  └─ NumAddDel
       props: modelValue = item.count
       emits: update:modelValue
```

```vue
<NumAddDel
  class="quantity-control"
  :model-value="item.count"
  @update:model-value="setCount"
/>
```

```js
const { remove, setCount: updateCount } = useCart()

function setCount(count) {
  updateCount(props.item.skuId, count)
}
```

### 2.2 `NumAddDel` 的边界

```js
function decrease() {
  emit('update:modelValue', Math.max(props.modelValue - 1, 1))
}
function increase() {
  emit('update:modelValue', Math.min(props.modelValue + 1, 99))
}
```

- 最少 1，最多 99。
- 不会发出 0，因此「减到 0 删除」不会由按钮触发。

### 2.3 store 的 `setCount`

```js
function setCount(skuId, count) {
  const item = state.items.find((item) => item.skuId === skuId)
  if (!item) return

  if (count <= 0) {
    remove(skuId)
    return
  }

  item.count = Math.min(count, 99)
}
```

### 2.4 改数量时序

```text
用户        NumAddDel       CartItem        store          UI
 │             │               │              │             │
 │ 点 +        │               │              │             │
 ├────────────►│               │              │             │
 │             │ emit(count+1) │              │             │
 │             ├──────────────►│              │             │
 │             │               │ setCount(id, n)            │
 │             │               ├─────────────►│             │
 │             │               │              │ item.count = n
 │             │               │              │             │
 │             │               │              │ computed 更新
 │             │               ├──────────────┼────────────►│
 │             │               │              │ 小计/合计/角标
 │             │               │              │             │
 │             │               │              │ watch → 存储 │
 │◄────────────┴───────────────┴──────────────┴─────────────┤
```

### 2.5 联动更新的内容

一个 `item.count` 变化，会同时影响：

```text
item.count
  ├─ NumAddDel 显示的数字
  ├─ 该行小计 = price × count
  ├─ totalCount = Σ count
  ├─ totalAmount = Σ price × count
  ├─ 顶部角标
  ├─ 结算按钮文字「去结算(N)」
  └─ localStorage 内容
```

这就是「单一数据源 + 派生状态」的价值：只改一处，所有显示自动一致。

## 三、删除流程

### 3.1 确认框

```js
async function removeItem() {
  try {
    await ElMessageBox.confirm('确定删除该商品？', '提示', {
      type: 'warning',
    })
    remove(props.item.skuId)
  } catch {
    // 用户取消删除不需要提示
  }
}
```

### 3.2 时序

```text
用户        CartItem          Element Plus         store        CartList
 │             │                   │                 │             │
 │ 点「删除」   │                   │                 │             │
 ├────────────►│                   │                 │             │
 │             │ confirm(...)      │                 │             │
 │             ├──────────────────►│                 │             │
 │             │                   │ 弹出确认框       │             │
 │             │                   │                 │             │
 │ 点「确定」   │                   │                 │             │
 ├─────────────┼──────────────────►│                 │             │
 │             │  Promise resolve  │                 │             │
 │             │◄──────────────────┤                 │             │
 │             │ remove(skuId)                       │             │
 │             ├────────────────────────────────────►│             │
 │             │                   │                 │ splice      │
 │             │                   │                 │ items 变化  │
 │             │                   │                 ├────────────►│
 │             │                   │                 │ TransitionGroup
 │             │                   │                 │ 淡出动画     │
 │             │                   │                 │ 合计/角标更新│
 │◄────────────┴───────────────────┴─────────────────┴─────────────┤
```

### 3.3 取消删除

用户点「取消」或关闭弹窗时，`ElMessageBox.confirm` 的 Promise 会 `reject`，进入 `catch`。空 `catch` 表示「取消不提示」，这是常见的处理方式。

> [!warning] `catch` 范围过宽
> 如果 `remove()` 内部未来出现真实异常，也会被静默吞掉。更精确的写法是只忽略取消：
>
> ```js
> try {
>   await ElMessageBox.confirm(...)
> } catch {
>   return   // 取消
> }
> remove(props.item.skuId)
> ```

### 3.4 删除后的表现

- 该行从列表消失（`TransitionGroup` 淡出）。
- 若删光，`items.length === 0`，切换为 `EmptyState`。
- 合计、件数、角标同步更新。
- localStorage 同步。
- 结算按钮变灰（`totalCount === 0`）。

## 四、结算流程

### 4.1 入口

`components/cart-area/footer-fixed.vue`：

```js
async function checkout() {
  try {
    await ElMessageBox.confirm(
      `共 ${totalCount.value} 件商品，合计 ¥${formatPrice(totalAmount.value)}，确认下单吗？`,
      '确认订单',
      { type: 'warning' },
    )
    clear()
    ElMessage.success('下单成功')
    router.push('/goods')
  } catch {
    // 用户取消结算不需要提示
  }
}
```

### 4.2 时序

```text
用户        FooterFixed        确认框          store          Router
 │             │                 │               │              │
 │ 点「去结算」 │                 │               │              │
 ├────────────►│                 │               │              │
 │             │ confirm(件数/金额)              │              │
 │             ├────────────────►│               │              │
 │             │                 │ 弹出          │              │
 │ 点「确定」   │                 │               │              │
 ├─────────────┼────────────────►│               │              │
 │             │ Promise resolve │               │              │
 │             │◄────────────────┤               │              │
 │             │ clear()                         │              │
 │             ├────────────────────────────────►│              │
 │             │                 │               │ splice(0)    │
 │             │                 │               │ 角标消失      │
 │             │                 │               │ localStorage 清空
 │             │ ElMessage.success('下单成功')    │              │
 │             │ router.push('/goods')           │              │
 │             ├─────────────────────────────────┼─────────────►│
 │             │                 │               │              │ 跳转列表
 │◄────────────┴─────────────────┴───────────────┴──────────────┤
```

### 4.3 结算做了什么、没做什么

**做了：**

- 显示件数与金额的确认框。
- 用户确认后清空购物车。
- 弹出「下单成功」。
- 跳回商品列表。

**没做：**

- 生成订单号 / 订单记录。
- 调用支付接口。
- 扣减库存。
- 地址、发票、优惠券。
- 登录与权限校验。
- 失败回滚。

> [!note] 这是「演示级结算」
> 它验证了「确认 → 清空 → 反馈 → 跳转」的交互闭环，但不具备真实交易能力。若要扩展，可以新增 `/checkout` 页面，在跳转前把购物车快照传给订单确认页，而不是直接清空。

### 4.4 空购物车

```vue
<button type="button" :disabled="totalCount === 0" @click="checkout">
  去结算({{ totalCount }})
</button>
```

- 件数为 0 时按钮禁用。
- 空状态下页面显示 `EmptyState`，但结算栏仍然存在，显示「共 0 件商品 / 合计 ¥0.00」。

### 4.5 取消结算

`ElMessageBox.confirm` reject → 空 `catch` → 什么都不发生，购物车保留。

## 五、四条流程的共同点

```text
┌────────────┬──────────────────────────┬──────────────────────────┐
│ 流程       │ 触发                     │ store 操作               │
├────────────┼──────────────────────────┼──────────────────────────┤
│ 加购       │ GoodsInfoPanel.addToCart │ add(product, count)      │
│ 改数量     │ NumAddDel emit           │ setCount(skuId, count)   │
│ 删除       │ CartItem.removeItem      │ remove(skuId)            │
│ 结算       │ FooterFixed.checkout     │ clear()                  │
└────────────┴──────────────────────────┴──────────────────────────┘
```

所有流程都遵循：

```text
用户操作
  ↓
组件内方法
  ↓
store action（唯一修改 state 的地方）
  ↓
computed 重新计算
  ↓
模板重新渲染
  ↓
watch 持久化
```

> [!important] 关键原则
> **组件不直接修改 `state.items`。** 加购、改数量、删除、清空都调用 store 提供的方法。这样数量上限、合并规则、删除规则只有一份实现，不会在不同组件里产生分歧。

## 六、边界情况汇总

| 场景 | 结果 |
| --- | --- |
| 同一商品重复加购 | 合并为一行，数量累加 |
| 数量加到 99 | 停止增加 |
| 数量减到 1 | 停止减少，不自动删除 |
| 手动调用 `setCount(skuId, 0)` | 删除该商品 |
| 删除最后一件 | 显示空购物车 |
| 结算时取消 | 购物车保持不变 |
| 结算确认 | 清空并跳回列表 |
| 刷新页面 | 从 localStorage 恢复 |
| 手动改 localStorage 为非法 JSON | `try/catch` 捕获，购物车为空 |
| 手动写入重复 skuId | 恢复成重复行（未去重） |

---

## 七、小结

购物车交互的本质是**一份数据的四种写法**：

```text
add       → 增加或合并
setCount  → 修改数量
remove    → 删除条目
clear     → 清空全部
```

而界面上的所有数字——小计、合计、件数、角标——都不是单独维护的，而是从 `state.items` 计算出来的。因此只要 store 改对，界面就不会不同步。
