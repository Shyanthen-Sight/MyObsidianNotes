# 搜索分页与详情流程

> [!abstract] 一句话
> 三条链路共用同一套「==URL / 状态变化 → 页面方法 → 数据层查询 → 响应式赋值 → 组件重渲染==」的模式：**搜索**把关键词写进 query，**分页**改 `currentPage` 再请求，**详情**把 `skuId` 放进动态路由段并在挂载时拉取商品与评论。

---

## 一、搜索流程

### 1.1 起点：顶部搜索框

`components/tab-header.vue`：

```vue
<div class="search-bar">
  <el-icon class="search-icon"><Search /></el-icon>
  <input
    v-model="keyword"
    type="text"
    placeholder="Search for products..."
    @keyup.enter="onSearch"
  />
</div>
```

```js
const keyword = ref('')

function onSearch() {
  const value = keyword.value.trim()
  router
    .push({
      path: '/goods',
      query: value ? { keyword: value } : {},
    })
    .catch(() => {})
}
```

要点：

- `v-model="keyword"`：输入框与 `ref` 双向绑定。
- `@keyup.enter`：只有回车才搜索，没有搜索按钮。
- `.trim()`：去掉首尾空格。
- 空关键词时 `query: {}`，即跳回不带参数的 `/goods`。
- `.catch(() => {})`：吞掉导航失败。Vue Router 4 对「重复导航到相同地址」通常返回失败对象而不是抛错，这个 catch 实际很少触发，但无害。

### 1.2 中间：URL 变成状态

```text
输入「手机」→ 回车
  ↓
router.push({ path: '/goods', query: { keyword: '手机' } })
  ↓
浏览器地址：/goods?keyword=手机
  ↓
route.query.keyword = '手机'
```

### 1.3 终点：列表页监听并请求

`views/goods-list.vue`：

```js
watch(
  () => route.query.keyword,
  () => {
    currentPage.value = 1
    loadGoods()
  },
)
```

```js
const result = await fetchGoodsList({
  keyword: String(route.query.keyword || ''),
  page: currentPage.value,
  pageSize,
})
```

`fetchGoodsList` 内部：

```text
products（61 条）
  ↓ 拼接可搜索文本
    title + brand + shopName + params 的所有值
  ↓ toLowerCase
  ↓ includes(keyword)
  ↓ sort（可选）
  ↓ slice 当前页
  ↓ { list, total }
```

### 1.4 搜索时序

```text
用户            TabHeader          Router           GoodsList            api
 │                 │                 │                 │                  │
 │ 输入 + 回车      │                 │                 │                  │
 ├────────────────►│                 │                 │                  │
 │                 │ push(query)     │                 │                  │
 │                 ├────────────────►│                 │                  │
 │                 │                 │ query 变化       │                  │
 │                 │                 ├────────────────►│                  │
 │                 │                 │                 │ watch 回调        │
 │                 │                 │                 │ currentPage = 1   │
 │                 │                 │                 │ loadGoods()       │
 │                 │                 │                 ├─────────────────►│
 │                 │                 │                 │                  │ filter/slice
 │                 │                 │                 │   { list, total }│
 │                 │                 │                 │◄─────────────────┤
 │                 │                 │                 │ products = list  │
 │                 │                 │                 │ total = 61       │
 │                 │                 │                 │ 重新渲染卡片      │
 │◄────────────────┴─────────────────┴─────────────────┴──────────────────┤
```

### 1.5 搜索的边界情况

| 情况 | 行为 |
| --- | --- |
| 关键词为空 | 跳转 `/goods`，显示全部商品 |
| 关键词只有空格 | `trim()` 后为空，同上 |
| 关键词大小写不同 | 统一 `toLowerCase`，不区分大小写 |
| 匹配到商品参数 | 会命中（参数值也参与搜索） |
| 没有结果 | `products.length === 0`，显示「没有找到相关商品」 |
| 已经在 `/goods` 搜索 | query 变化触发 watch，正常刷新 |
| 搜索词相同再次回车 | URL 不变，watch 不触发；页面保持原状 |
| 快速连续搜索 | 两次请求都可能在 150ms 后返回，存在旧结果覆盖新结果的理论风险 |

> [!warning] 搜索竞争条件
> `fetchGoodsList` 没有取消机制。如果用户先搜 A 再立刻搜 B，A 的请求可能后返回，把 B 的结果覆盖掉。当前延迟固定 150ms，顺序通常与发起顺序一致，因此不易复现。真实网络下应使用请求序号或 `AbortController`：
>
> ```js
> let requestId = 0
> const current = ++requestId
> const result = await fetchGoodsList(...)
> if (current !== requestId) return
> ```

> [!note] 搜索图标不能点击
> `<el-icon class="search-icon"><Search /></el-icon>` 只是装饰，没有绑定点击事件。用户必须按回车。可以给图标加 `@click="onSearch"` 并加 `cursor: pointer`。

## 二、分页流程

### 2.1 页码按钮

```vue
<button
  v-for="page in totalPages"
  :key="page"
  :class="{ active: page === currentPage }"
  :aria-current="page === currentPage ? 'page' : undefined"
  @click="goToPage(page)"
>
  {{ page }}
</button>
```

### 2.2 点击处理

```js
function goToPage(page) {
  if (page < 1 || page > totalPages.value || page === currentPage.value) {
    return
  }

  currentPage.value = page
  loadGoods()
}
```

```text
点击第 3 页
  ↓
边界检查：1 ≤ 3 ≤ 6 且 3 ≠ currentPage
  ↓
currentPage = 3
  ↓
loadGoods()
  ↓
fetchGoodsList({ page: 3, pageSize: 12 })
  ↓
slice(24, 36) → 第 25–36 条
  ↓
products 更新 → 卡片重渲染
  ↓
scrollBehavior 未触发（不是路由跳转），页面滚动位置保持
```

> [!note] 翻页不会回到顶部
> `scrollBehavior` 只在**路由跳转**时生效。点页码是组件内部状态变化，不会滚动。如果商品卡片很高，用户翻页后可能停在页面中部，需要手动上滑。可以在 `loadGoods` 成功后加：
>
> ```js
> window.scrollTo({ top: 0, behavior: 'smooth' })
> ```

### 2.3 分页时序

```text
用户           GoodsList                 api
 │                │                       │
 │ 点击页码 3      │                       │
 ├───────────────►│                       │
 │                │ goToPage(3)           │
 │                │ 边界检查               │
 │                │ currentPage = 3       │
 │                │ loading = true        │
 │                ├──────────────────────►│
 │                │                       │ slice
 │                │  { list(12), total }  │
 │                │◄──────────────────────┤
 │                │ products = list       │
 │                │ loading = false       │
 │                │ 重新渲染               │
 │◄───────────────┴───────────────────────┤
```

### 2.4 分页的边界情况

| 情况 | 行为 |
| --- | --- |
| 第 1 页点「上一页」 | 按钮 `disabled` |
| 最后一页点「下一页」 | 按钮 `disabled` |
| 点击当前页 | `goToPage` 直接 return，不重复请求 |
| 只有 1 页 | `v-if="totalPages > 1"` 不显示分页 |
| 搜索后页码超界 | watch 重置为 1 |
| 刷新页面 | `currentPage` 回到 1（未写 URL） |
| 从详情页返回 | 列表组件重新挂载，回到 1；关键词仍保留在 URL |

> [!tip] 页码写进 URL 的改法
> ```js
> const currentPage = computed({
>   get: () => Number(route.query.page || 1),
>   set: (page) => router.push({ query: { ...route.query, page } }),
> })
> ```
> 这样刷新、分享、后退都能恢复页码。注意要在 query 变化时统一触发 `loadGoods`，避免 `page` 和 `keyword` 两个 watch 重复请求。

## 三、商品详情流程

### 3.1 入口

`goods-card.vue`：

```js
function goToDetail() {
  router.push(`/goods/${props.product.skuId}`)
}
```

`cart-item.vue` 的封面也可以跳：

```js
router.push(`/goods/${props.item.skuId}`)
```

### 3.2 路由匹配与参数传递

```js
{
  path: '/goods/:skuId',
  name: 'goods-detail',
  component: GoodsDetail,
  props: true,
}
```

```text
/goods/100288035468
  ↓
skuId = '100288035468'
  ↓ props: true
<GoodsDetail sku-id="100288035468" />
  ↓
defineProps({ skuId: { type: String, required: true } })
```

### 3.3 加载

```js
onMounted(loadProduct)
```

```js
async function loadProduct() {
  loading.value = true
  error.value = ''
  try {
    product.value = await fetchGoodsDetail(props.skuId)   // 200ms
    comments.value = await fetchComments(props.skuId)     // 150ms
  } catch (requestError) {
    error.value = '商品不存在或加载失败'
  } finally {
    loading.value = false
  }
}
```

### 3.4 详情时序

```text
用户          GoodsCard        Router        GoodsDetail        api
 │               │               │               │               │
 │ 点击卡片       │               │               │               │
 ├──────────────►│               │               │               │
 │               │ push(/goods/…)│               │               │
 │               ├──────────────►│               │               │
 │               │               │ 匹配路由       │               │
 │               │               ├──────────────►│               │
 │               │               │               │ mount         │
 │               │               │               │ loadProduct() │
 │               │               │               ├──────────────►│
 │               │               │               │  product      │
 │               │               │               │◄──────────────┤
 │               │               │               ├──────────────►│
 │               │               │               │  comments     │
 │               │               │               │◄──────────────┤
 │               │               │               │ 渲染 5 个区块  │
 │◄──────────────┴───────────────┴───────────────┴───────────────┤
```

### 3.5 详情的边界情况

| 情况 | 行为 |
| --- | --- |
| `skuId` 不存在 | `fetchGoodsDetail` reject → 显示「商品不存在或加载失败」 |
| 评论接口失败 | 同样进入错误分支（当前实现不会失败） |
| 直接刷新详情 URL | 开发环境 Vite 会回退到 `index.html`，正常；生产需服务器配置 fallback |
| 从详情返回列表 | 列表重新挂载，页码回到 1，关键词保留 |
| 详情页内跳到另一个 skuId | 组件复用，`onMounted` 不触发，**不会重新加载** |
| 图片加载失败 | 显示浏览器破图，无兜底图 |

> [!warning] 最值得注意的详情页缺陷
> 详情页只在 `onMounted` 加载数据。当前没有「详情页 → 另一个详情页」的入口，所以问题不暴露；但浏览器前进/后退在两个详情页之间切换时，也可能复用组件。建议始终加上：
>
> ```js
> watch(() => props.skuId, loadProduct)
> ```
>
> 或在 `App.vue` 中给路由出口加 key：
>
> ```vue
> <RouterView :key="$route.fullPath" />
> ```

## 四、三条链路的共同模式

```text
┌──────────────┬──────────────────────┬──────────────────────────┐
│ 链路         │ 触发                 │ 数据请求                 │
├──────────────┼──────────────────────┼──────────────────────────┤
│ 搜索         │ URL query 变化       │ fetchGoodsList(keyword)  │
│ 分页         │ currentPage 变化     │ fetchGoodsList(page)     │
│ 详情         │ 路由参数 + 组件挂载  │ fetchGoodsDetail(skuId)  │
│              │                      │ + fetchComments(skuId)   │
└──────────────┴──────────────────────┴──────────────────────────┘
```

共同点：

1. **都有一个明确的「状态源」**：query、currentPage、skuId。
2. **都通过 `load*` 函数发请求**，不在模板里直接调用异步函数。
3. **都有 `loading` / `error` / 成功数据三态**（详情页评论没有独立三态）。
4. **成功后赋值给 `ref`**，由 Vue 自动更新 DOM。

## 五、状态丢失与恢复

| 操作 | 搜索词 | 页码 | 详情数据 | 购物车 |
| --- | --- | --- | --- | --- |
| 刷新列表页 | ✅ URL 保留 | ❌ 回到 1 | — | ✅ localStorage |
| 刷新详情页 | — | — | ✅ 重新请求 | ✅ localStorage |
| 刷新购物车页 | — | — | — | ✅ localStorage |
| 列表 → 详情 → 后退 | ✅ URL 保留 | ❌ 回到 1 | — | ✅ |
| 分享列表链接 | ✅ 保留 | ❌ 只到第 1 页 | — | ❌ 对方没有你的购物车 |

> [!important] 结论
> 搜索状态和购物车状态是「可恢复」的；分页状态是「易失」的。把页码同步到 URL 是提升体验最直接的一步。

---

## 六、小结

```text
搜索：输入 → trim → router.query → watch → page=1 → 过滤 → 渲染
分页：点击 → 边界检查 → currentPage → slice → 渲染
详情：点击 → 动态段 skuId → props → onMounted → 商品 + 评论 → 渲染
```

三条链路都没有离开一个中心思想：

> **先改变一个可追踪的状态，再让状态驱动请求和渲染，而不是手动操作 DOM。**
