# 表单校验方案

> 表单校验的目标不是“阻止提交”，而是尽早、准确地告诉用户哪里有问题，并在服务端再次校验前减少无效请求。

## 一、核心概念

- **校验时机**：失焦时校验单个字段、输入时清除错误、提交时校验全部，是体验较好的组合；一输入就报错会打扰用户。
- **客户端校验不等于安全**：前端校验只提升体验，后端必须重新校验所有字段。
- **同步与异步**：必填、长度、格式是同步校验；用户名是否重复、优惠券是否有效是异步校验，需要防抖和竞态处理。
- **字段级与表单级**：字段级规则只依赖当前值；表单级规则可能依赖多个字段，如“确认密码必须与密码一致”。
- **方案选择**：简单表单可以手写校验；复杂表单推荐 VeeValidate + Zod/Yup；需要快速搭建统一表单 UI 时可以考虑 FormKit。
- **可访问性**：错误信息要通过 `aria-describedby` 关联到输入框，并设置 `aria-invalid`，不能只靠红色文字。

## 二、基础语法

手写字段校验：

```js
const errors = reactive({ email: '' })

function validateEmail(value) {
  if (!value) {
    errors.email = '请输入邮箱'
    return false
  }
  if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(value)) {
    errors.email = '邮箱格式不正确'
    return false
  }
  errors.email = ''
  return true
}
```

VeeValidate 4：

```js
import { useField, useForm } from 'vee-validate'

const { handleSubmit, errors } = useForm()

const { value: email } = useField('email', 'required|email')

const onSubmit = handleSubmit((values) => {
  console.log('提交', values)
})
```

```vue
<form @submit="onSubmit">
  <input v-model="email" name="email" />
  <span v-if="errors.email">{{ errors.email }}</span>
  <button type="submit">提交</button>
</form>
```

FormKit：

```vue
<FormKit type="form" @submit="submit">
  <FormKit
    type="email"
    name="email"
    label="邮箱"
    validation="required|email"
    validation-visibility="blur"
  />
</FormKit>
```

## 三、完整示例

下面是一个注册表单，手写字段规则、表单级规则、异步用户名检查和可访问性错误提示，不依赖第三方库：

```vue
<script setup>
import { computed, reactive, ref } from 'vue'

const form = reactive({
  username: '',
  email: '',
  password: '',
  confirmPassword: '',
  agree: false
})

const touched = reactive({
  username: false,
  email: false,
  password: false,
  confirmPassword: false
})

const errors = reactive({
  username: '',
  email: '',
  password: '',
  confirmPassword: '',
  agree: ''
})

const checkingUsername = ref(false)
const submitting = ref(false)
const successMessage = ref('')

let usernameTimer = null

const rules = {
  username(value) {
    if (!value.trim()) return '请输入用户名'
    if (value.trim().length < 3) return '用户名至少 3 个字符'
    if (!/^[a-zA-Z0-9_]+$/.test(value)) return '只能包含字母、数字和下划线'
    return ''
  },
  email(value) {
    if (!value) return '请输入邮箱'
    if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(value)) return '邮箱格式不正确'
    return ''
  },
  password(value) {
    if (!value) return '请输入密码'
    if (value.length < 8) return '密码至少 8 位'
    if (!/[A-Z]/.test(value) || !/[0-9]/.test(value)) {
      return '密码需包含大写字母和数字'
    }
    return ''
  },
  confirmPassword(value) {
    if (!value) return '请再次输入密码'
    if (value !== form.password) return '两次输入的密码不一致'
    return ''
  }
}

const isValid = computed(() => {
  return Object.keys(rules).every((key) => rules[key](form[key]) === '')
    && form.agree
})

function validateField(field) {
  errors[field] = rules[field](form[field])
  touched[field] = true
}

async function checkUsername() {
  const error = rules.username(form.username)
  if (error) {
    errors.username = error
    return
  }

  checkingUsername.value = true

  try {
    // 模拟异步查重，真实项目替换为接口
    await new Promise((resolve) => setTimeout(resolve, 400))
    errors.username = form.username === 'admin' ? '该用户名已被占用' : ''
  } finally {
    checkingUsername.value = false
  }
}

function onUsernameInput() {
  errors.username = ''
  if (usernameTimer) window.clearTimeout(usernameTimer)
  usernameTimer = window.setTimeout(checkUsername, 500)
}

function validateAll() {
  Object.keys(rules).forEach((key) => validateField(key))
  errors.agree = form.agree ? '' : '请阅读并同意服务协议'
  return isValid.value && form.agree
}

async function submit() {
  successMessage.value = ''
  if (!validateAll() || submitting.value) return

  submitting.value = true
  try {
    await new Promise((resolve) => setTimeout(resolve, 800))
    successMessage.value = '注册成功，请前往邮箱完成验证'
  } finally {
    submitting.value = false
  }
}
</script>

<template>
  <section class="register">
    <h1>创建账号</h1>

    <p v-if="successMessage" class="success" role="status">
      {{ successMessage }}
    </p>

    <form novalidate @submit.prevent="submit">
      <label class="field">
        <span>用户名</span>
        <input
          v-model.trim="form.username"
          type="text"
          autocomplete="username"
          :aria-invalid="Boolean(errors.username)"
          aria-describedby="username-error"
          @input="onUsernameInput"
          @blur="validateField('username')"
        />
        <small v-if="checkingUsername" class="hint">正在检查用户名...</small>
        <small v-else-if="errors.username" id="username-error" class="error">
          {{ errors.username }}
        </small>
      </label>

      <label class="field">
        <span>邮箱</span>
        <input
          v-model.trim="form.email"
          type="email"
          autocomplete="email"
          :aria-invalid="Boolean(errors.email)"
          aria-describedby="email-error"
          @blur="validateField('email')"
        />
        <small v-if="errors.email" id="email-error" class="error">
          {{ errors.email }}
        </small>
      </label>

      <label class="field">
        <span>密码</span>
        <input
          v-model="form.password"
          type="password"
          autocomplete="new-password"
          :aria-invalid="Boolean(errors.password)"
          aria-describedby="password-error"
          @blur="validateField('password')"
        />
        <small v-if="errors.password" id="password-error" class="error">
          {{ errors.password }}
        </small>
      </label>

      <label class="field">
        <span>确认密码</span>
        <input
          v-model="form.confirmPassword"
          type="password"
          autocomplete="new-password"
          :aria-invalid="Boolean(errors.confirmPassword)"
          aria-describedby="confirm-error"
          @blur="validateField('confirmPassword')"
        />
        <small v-if="errors.confirmPassword" id="confirm-error" class="error">
          {{ errors.confirmPassword }}
        </small>
      </label>

      <label class="agreement">
        <input v-model="form.agree" type="checkbox" />
        <span>我已阅读并同意服务协议</span>
      </label>
      <small v-if="errors.agree" class="error">{{ errors.agree }}</small>

      <button type="submit" :disabled="submitting">
        {{ submitting ? '提交中...' : '注册' }}
      </button>
    </form>
  </section>
</template>

<style scoped>

}

}

}

  background: #9ca3af;
  cursor: not-allowed;
}
</style>
```

## 四、常见坑 / 注意事项

1. **一输入就校验会让用户烦躁**：建议失焦校验、输入时清除旧错误、提交时校验全部。
2. **异步校验要防抖并处理竞态**：快速输入会发起多个查重请求，应取消旧请求或只接受最后一次结果。
3. **确认密码依赖另一个字段**：只监听确认密码不够，密码修改后也要重新校验确认密码。
4. **前端校验不能替代后端校验**：任何人都可以绕过前端直接调用接口，后端必须重复校验。
5. **错误信息要可访问**：用 `aria-invalid` 和 `aria-describedby` 关联错误文本，不要只依赖颜色。
6. **VeeValidate 的 `useField` 要在 `setup` 中调用**：在异步回调或条件分支中调用会破坏字段注册顺序。
7. **FormKit 的校验可见性要配置**：默认可能在输入时显示错误，`validation-visibility="blur"` 可以改善体验。
8. **提交按钮的禁用条件要与校验一致**：禁用按钮但不给原因，用户会不知道哪里没填；应同时显示字段级错误。

## 六、速查表

| 语法               | 作用                   | 示例                                         |
| ------------------ | ---------------------- | -------------------------------------------- |
| `@blur`            | 失焦触发校验           | `<input @blur="validateField('email')" />`   |
| `novalidate`       | 关闭浏览器默认提示     | `<form novalidate>`                          |
| `aria-invalid`     | 标记字段错误           | `:aria-invalid="Boolean(errors.email)"`      |
| `aria-describedby` | 关联错误文本           | `aria-describedby="email-error"`             |
| `useForm`          | VeeValidate 表单上下文 | `const { handleSubmit, errors } = useForm()` |
