# 第 5 关 · 嵌套路由

> 一句话：`children` 把子页面挂到父路径下，父组件作为「外壳」只渲染一次，内部的第二个 `<router-view />` 负责切换子页面；`path: ''` 的子路由就是默认页。

## 一、本关目标

1. 用 `children` 表达「设置」下的多个子页面；
2. 理解**嵌套层级 = `<router-view />` 层级**：根组件有一个出口，外壳组件里还要再放一个；
3. 用 `path: ''` 定义默认子路由，让 `/settings` 直接有内容；
4. 用 `router-link-exact-active` 解决父级链接在子页面被误高亮的问题。

### 路由表新增

```js
{
  path: '/settings',
  component: SettingsLayout, // 外壳组件，里面有自己的 <router-view>
  children: [
    // path 为空 = 默认子路由：访问 /settings 时渲染它
    { path: '', name: 'settings', component: SettingsProfile },
    // 子路由写相对路径，最终地址是 /settings/security
    { path: 'security', name: 'settings-security', component: SettingsSecurity },
  ],
}
```

- 父记录 `path: '/settings'` **没有 name**；有名字的是默认子路由。
- 子路由 `path` 不带 `/`，是相对父路径拼接；写成 `/security` 会变成绝对路径，脱离父级。

### `src/main.js`

- **作用**：路由表新增嵌套结构，是本关核心。
- **完整路由表**：

```js
routes: [
  { path: '/', name: 'home', component: Home },
  { path: '/about', name: 'about', component: About },
  { path: '/users', name: 'users', component: Users },
  { path: '/users/:id', name: 'user', component: UserDetail, props: true },

  {
    path: '/settings',
    component: SettingsLayout,
    children: [
      { path: '', name: 'settings', component: SettingsProfile },
      { path: 'security', name: 'settings-security', component: SettingsSecurity },
    ],
  },
]
```

- **说明**：
  - 新增导入 `SettingsLayout`、`SettingsProfile`、`SettingsSecurity`。
  - `children` 里的 `path: ''` 表示「父路径本身」；`/settings` 会匹配父记录并同时选中这个默认子路由。
  - `path: 'security'` 拼接后是 `/settings/security`。
  - 父记录没有 `name`，不能直接用名字跳到「只有一个空外壳」的状态；要跳设置页，用默认子路由的名字 `settings`。
  - 嵌套可以继续加深；每一层都需要在对应父组件里放一个 `<router-view />`。

### `src/pages/SettingsLayout.vue`

- **作用**：设置模块的**外壳（布局）组件**，也是本关最关键的页面文件。
- **完整模板**：

```vue
<div class="card">
  <h1>设置</h1>
  <p class="lead">这一层是「外壳」，真正的内容由下面这两个子页面决定。</p>

  <!-- 用 exact 版本，避免父级 /settings 在子页面里也高亮 -->
  <div class="subnav">
    <router-link to="/settings">个人资料</router-link>
    <router-link to="/settings/security">安全</router-link>
  </div>

  <!-- 子路由的出口 -->
  <router-view />

  <p class="muted" style="margin-top: 12px">
    上面这段标题和导航，在两个子页面之间切换时不会消失 —— 因为它们属于父组件，只渲染一次。
  </p>
</div>
```

- **说明**：
  - 没有 `<script>`；所有内容都是静态结构。
  - **第二个 `<router-view />`** 是嵌套路由的出口；没有它，`/settings/security` 能匹配但子组件无处渲染。
  - 二级导航用普通路径字符串即可；也可以写 `:to="{ name: 'settings' }"`。
  - 激活样式：在 `/settings/security` 时，`to="/settings"` 的链接默认仍会带 `router-link-active`（前缀匹配），所以 CSS 里给 `.subnav` 特意用了 `router-link-exact-active`（完全匹配）来高亮当前子页。
  - 切换子页面时，`SettingsLayout` 实例不重建，标题与导航保持不动。

## 三、本关要点与易错点

1. **出口层级要对齐嵌套层级**：根 `App.vue` 一个 `<router-view />`，`SettingsLayout.vue` 再一个；少一个就只显示外壳。
2. **默认子路由**：`path: ''` 让父路径本身有内容；否则访问 `/settings` 时子出口为空。
3. **相对 vs 绝对子路径**：`'security'` → `/settings/security`；`'/security'` → `/security`（脱离父级，通常不是本意）。
4. **父记录可以没有 name**：用默认子路由的 name 作为模块入口更常见。
5. **激活类名**：`router-link-active` 是前缀匹配，父级链接会在所有子页高亮；需要精确高亮时用 `router-link-exact-active`。
6. **父组件不重建**：在子页之间切换只替换子出口，外壳的滚动位置、内部状态都会保留；需要响应子路由变化时用 `watch` 或 `onBeforeRouteUpdate`。
7. **导航与路由是两回事**：本关把「关于」移出导航，但路由仍有效——不要用导航项判断页面是否存在。
