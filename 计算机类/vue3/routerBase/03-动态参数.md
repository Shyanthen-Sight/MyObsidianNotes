# 第 3 关 · 动态参数

> 一句话：把路径中的一段写成 `:id`，同一个 `UserDetail.vue` 就能服务 `/users/1`、`/users/2`、`/users/3`；参数通过 `route.params.id` 读取，且拿到的是**字符串**。

## 一、本关目标

1. 用动态段 `:id` 让一条路由记录匹配一组地址；
2. 在组件里通过 `useRoute().params` 取参数；
3. 观察一个容易误解的现象：**`/users/1` → `/users/2` 时组件实例被复用**，`onMounted` 不会重新执行。

### 路由表新增两条

```js
{ path: '/users', component: Users },          // 列表页
{ path: '/users/:id', component: UserDetail }, // 详情页，:id 是变量
```

- `/users` 与 `/users/:id` 是两条不同记录，匹配 `/users/1` 时只有后者命中。
- 本关链接仍是**手工拼路径**：`'/users/' + user.id`，第 4 关才会改成命名路由。

### `src/main.js`

- **作用**：路由表在本关首次扩充，新增用户列表与详情两条记录。
- **完整路由表**：

```js
const router = createRouter({
  history: createWebHistory(),
  routes: [
    { path: '/', component: Home },
    { path: '/about', component: About },

    // 新增：/users 是列表页
    { path: '/users', component: Users },

    // 新增：:id 表示这一段是变量，/users/1、/users/2 都会匹配到这里
    { path: '/users/:id', component: UserDetail },
  ],
})

createApp(App).use(router).mount('#app')
```

- **说明**：
  - 导入项新增 `Users`、`UserDetail`。
  - 这里把 `/users` 写在 `/users/:id` 前面只是可读性安排；Vue Router 会按匹配优先级排序，静态段优先于动态段，因此顺序不影响结果（**但第 6 关的通配路由不同，必须放最后**）。
  - `:id` 只匹配**单个路径段**（不跨 `/`）；若 `id: 'abc'` 也能匹配到这条路由，只是数据里查不到，需要页面自己兜底。

### `src/pages/Users.vue`

- **作用**：用户列表页，每一行链接到一个带参数的地址。
- **脚本**：

```js
import { users } from '../data/users'
```

- **模板要点**：

```vue
<ul class="list">
  <li v-for="user in users" :key="user.id">
    <!-- 这里直接把 id 拼进路径；第 4 关会改成用名字跳转 -->
    <router-link :to="'/users/' + user.id">
      <span class="avatar">{{ user.name.slice(0, 1) }}</span>
      <span>{{ user.name }}</span>
      <span class="tag">/users/{{ user.id }}</span>
    </router-link>
  </li>
</ul>
```

- **说明**：
  - `:to` 是动态绑定，值是字符串表达式；也可以用模板字符串 `` `/users/${user.id}` ``。
  - `.avatar` 取姓名首字，`.tag` 显示目标路径，方便对照地址栏。
  - `:key="user.id"` 是列表渲染的稳定键。
  - 这种「拼路径」写法的问题是：一旦路由从 `/users/:id` 改成 `/people/:id`，所有拼字符串的地方都要改——第 4 关的命名路由就是为解决这个问题。

### `src/pages/UserDetail.vue`

- **作用**：本关信息量最大的文件——读参数、处理数据不存在、演示组件复用。
- **脚本全文**：

```js
import { computed, ref } from 'vue'
import { useRoute, useRouter } from 'vue-router'
import { users } from '../data/users'

const route = useRoute()
const router = useRouter()

// route.params.id 是字符串：'1'，不是 1，比较时记得转一下
const index = computed(() => users.findIndex(
  (user) => String(user.id) === route.params.id
))
const user = computed(() => users[index.value])
const prev = computed(() => users[index.value - 1])
const next = computed(() => users[index.value + 1])

// 这个小计数器用来证明「组件被复用」：切换用户它不会归零
const clicks = ref(0)

function goto(id) {
  router.push('/users/' + id)
}
```

- **说明**：
  - `route.params` 是响应式的；用 `computed` 派生 `index` / `user` / `prev` / `next`，参数变化时视图自动更新。
  - `findIndex` 找不到时返回 `-1`，`users[-1]` 为 `undefined`，因此模板要用 `v-if="user"` 分支。
  - `prev` / `next` 直接用数组下标，首尾元素会得到 `undefined`；按钮用 `:disabled="!prev"` / `!next` 禁用。
  - `clicks` 计数器是「组件复用」的证据：从 `/users/1` 跳到 `/users/2` 时，计数器不归零。
  - `goto(id)` 用 `router.push('/users/' + id)` 手拼路径；第 4 关会改成 `{ name: 'user', params: { id } }`。
- **模板结构**：
  - `v-if="user"`：标题、职位、上一个/下一个按钮、参数展示、计数器；
  - `v-else`：显示「没有这个人」，并给出回列表的链接。
  - 参数展示特意写了 `{{ typeof route.params.id }}`，用于观察类型。

```vue
<p class="muted">
  <code>route.params</code> 的值：<code>{{ route.params.id }}</code>
  （类型是 {{ typeof route.params.id }}）
</p>
```

- **关键结论**（页面文案）：数字没有归零，说明只是参数变了、组件实例还是同一个，所以 `onMounted` 不会再执行；想跟着参数变化，就要用 `computed` 或 `watch` 盯着它。

## 三、本关要点与易错点

1. **`route.params` 的值永远是字符串**（除非用了自定义正则转换或 props 转换）。数字比较记得 `String()` / `Number()`。
2. **动态段只匹配一段路径**：`/users/:id` 不匹配 `/users/1/edit`；多段变量要写多个 `:xxx`。
3. **找不到数据不等于路由不匹配**：`/users/999` 仍会命中 `UserDetail`，由组件自己渲染兜底内容。
4. **组件复用**：同一路由记录、仅参数变化时，实例被复用；生命周期钩子不会重跑。订阅、请求等副作用要放在 `watch(() => route.params.id, ...)` 或 `onBeforeRouteUpdate` 里。
5. **拼路径耦合**：本关的 `'/users/' + id` 与路由结构强绑定，是第 4 关的改进动机。
