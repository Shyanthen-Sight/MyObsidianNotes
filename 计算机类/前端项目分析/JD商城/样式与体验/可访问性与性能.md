# 可访问性与性能

> [!abstract] 一句话
> 项目在可访问性上有一些==明显用心的小细节==（语义标签、`aria-label`、卡片键盘操作、`focus-visible`、`aria-current`），但头部可点击的 `div`、无标签输入框、无 `aria-live` 仍是缺口；性能上最大的问题是 **Element Plus 全量引入 + 无路由懒加载 + 远程图片无懒加载**，实测构建产物 JS 约 1.92 MB、CSS 约 385 kB。

---

## 一、可访问性（A11y）

### 1.1 做得好的地方

#### 语义化标签

| 标签 | 使用位置 | 作用 |
| --- | --- | --- |
| `<main>` | `App.vue` | 页面主内容区 |
| `<nav>` | 分页、详情快速导航 | 导航区域 |
| `<section>` | 各页面/区块 | 内容分区 |
| `<article>` | 商品卡片、评论、购物车行 | 独立内容单元 |
| `<time>` | 评论时间 | 时间语义 |
| `<dl>/<dt>/<dd>` | 商品参数 | 名值对语义 |
| `<footer>` | 结算栏 | 页脚语义 |
| `<h1>/<h2>` | 标题层级 | 文档结构 |

#### `aria-label`

```vue
<nav class="pagination" aria-label="商品列表分页">
<nav class="detail-nav" aria-label="商品详情快速导航">
<div class="num-add-del" aria-label="商品数量">
<button type="button" aria-label="减少数量">
<button type="button" aria-label="增加数量">
<button type="button" aria-label="回到顶部">
<div class="home-bar" aria-label="返回主页">
```

#### 商品卡片的键盘支持

```vue
<article
  class="goods-card"
  role="link"
  tabindex="0"
  @click="goToDetail"
  @keydown.enter="goToDetail"
  @keydown.space.prevent="goToDetail"
>
```

```css
.goods-card:focus-visible {
  outline: 2px solid #e1251b;
  outline-offset: 3px;
}
```

- `role="link"`：告诉辅助技术这是链接。
- `tabindex="0"`：进入 Tab 顺序。
- 回车 / 空格都能触发。
- `.prevent` 阻止空格滚动页面。
- `focus-visible` 只在键盘聚焦时显示轮廓，不干扰鼠标用户。

#### 分页的当前页

```vue
:aria-current="page === currentPage ? 'page' : undefined"
```

#### 按钮禁用

```vue
<button :disabled="currentPage === 1">上一页</button>
<button :disabled="currentPage === totalPages">下一页</button>
<button :disabled="totalCount === 0">去结算</button>
```

原生 `disabled` 会自动从 Tab 顺序移除，并告知辅助技术不可用。

#### 图片 alt

```vue
<img :src="product.mainImageUrls[0]" :alt="product.title" />
<img :src="image" :alt="`商品图片 ${index + 1}`" />
<img :src="image" :alt="`商品详情图 ${index + 1}`" />
```

商品卡片使用商品标题作为 alt，信息量足够。

#### 页面级

```html
<html lang="zh-CN">
<meta name="viewport" content="width=device-width, initial-scale=1.0">
<meta name="theme-color" content="#e1251b">
```

### 1.2 可访问性缺口

#### 缺口一：头部可点击的 `div`

```vue
<div class="cart-bar" @click="goToCart">
<div class="home-bar" aria-label="返回主页" @click="goToHome">
```

问题：

- `div` 默认不可聚焦，键盘用户无法用 Tab 选中。
- 没有 `role="button"`。
- 没有 `@keydown.enter` / `@keydown.space`。
- 鼠标用户能点，键盘用户不能。

修复：

```vue
<button type="button" class="cart-bar" aria-label="购物车" @click="goToCart">
  <el-icon class="cart-icon"><ShoppingCartFull /></el-icon>
  <CartDot />
</button>

<button type="button" class="home-bar" aria-label="返回主页" @click="goToHome">
  <el-icon class="home-icon"><House /></el-icon>
</button>
```

用 `<button>` 还能获得原生回车/空格支持和焦点样式。

#### 缺口二：搜索框没有标签

```vue
<input
  v-model="keyword"
  type="text"
  placeholder="Search for products..."
  @keyup.enter="onSearch"
/>
```

`placeholder` 不能替代标签：输入后提示消失，屏幕阅读器也不一定朗读。修复：

```vue
<label class="visually-hidden" for="search">搜索商品</label>
<input id="search" v-model="keyword" type="search" ... />
```

或：

```vue
<input aria-label="搜索商品" ... />
```

另外 `type="text"` 可以改成 `type="search"`，获得浏览器的清除按钮和搜索语义。

#### 缺口三：购物车封面可点击但不可聚焦

```vue
<img class="cart-cover" :src="item.cover" :alt="item.title" @click="goToDetail" />
```

键盘用户无法通过封面进入详情。修复：用 `<RouterLink>` 包住图片，或把标题也做成链接：

```vue
<RouterLink :to="`/goods/${item.skuId}`">
  <img class="cart-cover" :src="item.cover" :alt="item.title" />
</RouterLink>
```

#### 缺口四：数量变化没有播报

`NumAddDel` 的数字只是 `<span>{{ modelValue }}</span>`，屏幕阅读器不会主动读出变化。可以加：

```vue
<span aria-live="polite">{{ modelValue }}</span>
```

购物车角标也可以加 `aria-live="polite"`，但要注意不要频繁打扰。

#### 缺口五：缺少「跳到主内容」

页面有常驻头部，但没有 skip link。完整做法：

```html
<a class="skip-link" href="#main">跳到主要内容</a>
```

#### 缺口六：颜色对比度

- `#86909c` 的浅灰文字常用于 12–14px 小字，与白色背景对比度可能低于 WCAG AA 的 4.5:1。
- `#cbce1e` 角标配白字，对比度也偏低。
- 建议用对比度工具核验，必要时加深灰色或改用深色文字。

#### 缺口七：没有 `prefers-reduced-motion`

项目有：

- Swiper 自动播放
- 卡片 hover 上移
- 按钮 hover 上移
- `TransitionGroup` 淡入淡出
- 平滑滚动

对前庭敏感用户，应支持：

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

Swiper 可以通过 `:autoplay="false"` 或媒体查询关闭自动播放。

#### 缺口八：Logo 的 alt 不够描述

```vue
<img src="..." alt="logo">
```

英文 `logo` 信息量低，建议 `alt="京东商城"`。

## 二、性能

### 2.1 实测构建结果

```text
✓ 1674 modules transformed
dist/index.html                   0.48 kB │ gzip:   0.32 kB
dist/assets/index-*.css         385.36 kB │ gzip:  52.57 kB
dist/assets/index-*.js        1,918.74 kB │ gzip: 549.07 kB
```

Vite 警告：

```text
Some chunks are larger than 500 kB after minification.
```

### 2.2 体积来源

| 来源 | 估算影响 | 说明 |
| --- | --- | --- |
| Element Plus 全量注册 | 最大 | `app.use(ElementPlus)` + 完整 CSS |
| Element Plus CSS | 385 kB | 实际只用到消息框、确认框、图标 |
| 路由页面未懒加载 | 大 | 三个页面和所有组件打进同一个 chunk |
| Swiper | 中 | 仅详情页使用，却随首屏加载 |
| JSON 数据 | 中 | 61 条商品 + 600 条评论全部进 bundle |
| 未使用 CSS（`swiper/css/navigation`） | 小 | 导入了但未注册 Navigation 模块 |

> [!example] 优化方向一：按需引入 Element Plus
> 使用 `unplugin-vue-components` + `unplugin-auto-import`：
>
> ```bash
> npm i -D unplugin-vue-components unplugin-auto-import
> ```
>
> ```js
> // vite.config.js
> import AutoImport from 'unplugin-auto-import/vite'
> import Components from 'unplugin-vue-components/vite'
> import { ElementPlusResolver } from 'unplugin-vue-components/resolvers'
>
> export default defineConfig({
>   plugins: [
>     vue(),
>     AutoImport({ resolvers: [ElementPlusResolver()] }),
>     Components({ resolvers: [ElementPlusResolver()] }),
>   ],
> })
> ```
>
> 同时删除 `main.js` 中的 `app.use(ElementPlus)` 和 `import 'element-plus/dist/index.css'`。消息框可以显式引入：
>
> ```js
> import { ElMessage, ElMessageBox } from 'element-plus'
> import 'element-plus/es/components/message/style/css'
> import 'element-plus/es/components/message-box/style/css'
> ```

> [!example] 优化方向二：路由懒加载
> ```js
> // router/index.js
> const GoodsList = () => import('@/views/goods-list.vue')
> const GoodsDetail = () => import('@/views/goods-detail.vue')
> const Cart = () => import('@/views/cart.vue')
> ```
>
> 这样首屏只加载列表页，详情页和购物车页按需下载。Swiper 只会在详情页 chunk 中出现。

> [!example] 优化方向三：图片懒加载
> ```vue
> <img
>   v-for="(image, index) in product.detailImageUrls"
>   :key="image"
>   :src="image"
>   :alt="`商品详情图 ${index + 1}`"
>   loading="lazy"
>   decoding="async"
> />
> ```
>
> 评论晒图同样处理。列表卡片首屏图片不建议 `lazy`，但可以给非首屏图片加。

### 2.3 图片策略

项目图片全部来自京东 CDN：

```text
https://img10.360buyimg.com/...
https://img30.360buyimg.com/...
https://storage.360buyimg.com/...
```

格式包括 `.avif`、`.dpg`、`.jpg`。

| 优点 | 风险 |
| --- | --- |
| 不占用项目仓库体积 | 依赖外部 CDN 可用性 |
| CDN 自带压缩与缓存 | 跨域、防盗链、隐私 |
| AVIF 体积小、质量高 | DPG 格式并非所有浏览器都原生支持 |
| 多尺寸 URL 可用 | 项目没有使用 `srcset` |
| — | 没有破图兜底 |

改进建议：

1. **`loading="lazy"` + `decoding="async"`**：减少首屏请求。
2. **`srcset` / `sizes`**：给不同屏幕提供不同尺寸。
3. **`onerror` 兜底**：加载失败显示占位图。
4. **`referrerpolicy="no-referrer"`**：减少来源信息泄露。
5. **首屏主图预加载**：

```html
<link rel="preload" as="image" href="..." />
```

6. **考虑本地缓存**：若用于长期展示，可把图片下载到 `public/` 或对象存储。

### 2.4 运行时性能

| 方面 | 现状 | 评价 |
| --- | --- | --- |
| 列表渲染 | 每页 12 条 | 很轻 |
| 评论渲染 | 每商品 1–10 条 | 很轻 |
| 计算属性 | 合计、页数 | O(n)，n 很小 |
| 深度 watch | 购物车每次变化全量序列化 | 数据量小，可接受 |
| 图片解码 | 详情长图可能很大 | 需要懒加载 |
| 动画 | CSS transform/opacity | 走合成层，性能好 |
| Swiper | 单个实例 | 轻 |

不需要虚拟列表或 Web Worker。

### 2.5 网络与缓存

- 构建产物文件名带 hash（`index-DGAMi7Xh.js`），可长期缓存。
- 没有配置 `Cache-Control`，由部署平台决定。
- 没有 Service Worker / PWA。
- 没有预取（prefetch）其它路由。

## 三、健壮性与安全

### 3.1 数据结构假设

| 假设 | 位置 | 风险 |
| --- | --- | --- |
| `mainImageUrls` 是非空数组 | 卡片、加购、轮播 | 空数组时 `cover` 为 `undefined` |
| `detailImageUrls` 是数组 | 轮播、长图 | 缺失时 `.slice` 报错 |
| `comment.images` 是数组 | 评论列表 | 缺失时 `.length` 报错 |
| `nickname` 非空 | 头像首字 | 空字符串时显示空白，不报错 |
| `params` 是对象 | 摘要、参数表 | 已用 `|| {}` 兜底 |

建议在 `normalizeProduct` 和 `fetchComments` 中统一补默认值：

```js
mainImageUrls: raw.main_image_urls || [],
detailImageUrls: raw.detail_image_urls || [],
```

```js
images: comment.images_urls || [],
```

### 3.2 重复 key

评论列表使用 `nickname + time` 作为 key，600 条中有 127 组重复。Vue 会警告并可能复用错误的 DOM。修复见 [[商品详情组件]]。

### 3.3 请求竞争

搜索与分页请求没有取消或序号校验。快速操作时旧响应可能覆盖新响应。真实网络下需要处理。

### 3.4 XSS

所有用户可见内容都通过 `{{ }}` 插值，Vue 会自动转义，**没有使用 `v-html`**，因此不存在明显的 XSS 注入点。

### 3.5 localStorage

- 读取有 `try/catch` 和字段校验。
- 写入**没有** `try/catch`，隐私模式或配额满时可能抛错。
- 用户可篡改，但校验能挡住大部分非法结构。
- 不存储敏感信息（只有商品快照）。

### 3.6 外部资源

- 图片来自第三方 CDN，可能记录访问者 IP / Referer。
- 没有配置 CSP。
- 如果 CDN 不可用，页面会出现大量破图。

## 四、优化优先级

| 优先级 | 优化 | 预期收益 |
| --- | --- | --- |
| P0 | Element Plus 按需引入 | JS/CSS 大幅减小 |
| P0 | 路由懒加载 | 首屏 JS 减小 |
| P1 | 详情/评论图片 `loading="lazy"` | 首屏请求与流量减少 |
| P1 | 修复评论重复 key | 消除渲染隐患 |
| P1 | 数据数组默认值 | 消除运行时错误 |
| P2 | 头部改用 `<button>` | 键盘可访问 |
| P2 | 搜索框加 `aria-label` | 屏幕阅读器可识别 |
| P2 | 图片 `onerror` 兜底 | 破图时体验更好 |
| P2 | `prefers-reduced-motion` | 动画可关闭 |
| P3 | `srcset` / 预加载 | 图片加载更精细 |
| P3 | 请求取消 | 消除竞争条件 |

## 五、小结

```text
可访问性：语义化和键盘支持有亮点，
          但可点击 div、无标签输入、无动态播报是主要缺口。

性能：    功能代码本身很轻，
          体积几乎全部来自 Element Plus 全量引入 + 未拆包。

图片：    CDN 资源丰富，但缺少懒加载、尺寸适配和失败兜底。
```

对一个教学项目来说，这些是「知道就能改」的问题；对生产项目来说，P0 两项（按需引入、路由懒加载）应当优先处理。
