# 代码质量与改进

> [!abstract] 一句话
> 从「教学项目」角度看，这个项目的==组件拆分、数据归一化、购物车持久化和响应式运用都相当扎实==；从「生产项目」角度看，主要短板集中在 **打包体积、健壮性、URL 状态、可访问性和工程化**。下面按优先级列出可落地的问题与改法。

---

## 一、先说优点

### 1.1 结构层面

| 优点 | 体现 |
| --- | --- |
| 分层清晰 | `views` / `components` / `api` / `stores` / `router` 各司其职 |
| 页面与展示分离 | 页面取数，展示组件只收 props |
| 业务区域分组 | `goods-area`、`detail`、`cart-area`、`common` |
| 通用组件独立 | `NumAddDel`、`EmptyState`、`CartDot` |
| 命名一致 | 文件名、组件名、变量名基本统一 |

### 1.2 代码层面

| 优点 | 体现 |
| --- | --- |
| 字段转换集中 | `normalizeProduct` 一处处理 snake_case → camelCase |
| 金额格式化集中 | `formatPrice` 统一两位小数与容错 |
| 三态处理 | `loading` / `error` / 成功分支完整 |
| `try/catch/finally` | 详情页、列表页都正确复位 `loading` |
| 单一数据源 | 购物车所有显示都由 `state.items` 派生 |
| 持久化校验 | localStorage 恢复时检查类型与数量范围 |
| 注释适量 | 关键逻辑有中文注释，不影响阅读 |
| 响应式细节 | `aspect-ratio`、`minmax(0,1fr)`、`tabular-nums`、`scroll-margin-top` |

### 1.3 体验层面

- 卡片有 hover 反馈和键盘操作。
- 删除和结算都有二次确认。
- 空购物车有引导。
- 移动端有专门布局。
- 分页有当前页高亮和 `aria-current`。

## 三、P0：打包体积

### 3.1 现状

`main.js`：

```js
import ElementPlus from 'element-plus'
import 'element-plus/dist/index.css'

app.use(ElementPlus)
```

实际只用到：

- `ElMessage`（下单成功）
- `ElMessageBox`（删除/结算确认）
- 4 个图标：`Search`、`ShoppingCartFull`、`House`、`Top`

构建结果：

```text
dist/assets/index-*.css    385.36 kB │ gzip: 52.57 kB
dist/assets/index-*.js   1,918.74 kB │ gzip: 549.07 kB
```

### 3.2 改法：按需引入

```bash
npm i -D unplugin-vue-components unplugin-auto-import
```

```js
// vite.config.js
import AutoImport from 'unplugin-auto-import/vite'
import Components from 'unplugin-vue-components/vite'
import { ElementPlusResolver } from 'unplugin-vue-components/resolvers'

export default defineConfig({
  plugins: [
    vue(),
    AutoImport({ resolvers: [ElementPlusResolver()] }),
    Components({ resolvers: [ElementPlusResolver()] }),
  ],
})
```

```js
// main.js
import { createApp } from 'vue'
import App from './App.vue'
import './style.css'
import router from './router'

const app = createApp(App)
app.use(router)
app.mount('#app')
```

消息框按需引入样式：

```js
import { ElMessage, ElMessageBox } from 'element-plus'
import 'element-plus/es/components/message/style/css'
import 'element-plus/es/components/message-box/style/css'
```

> [!tip] 预期收益
> 只打包实际使用的组件与样式，JS/CSS 通常能下降一个数量级。具体数值取决于构建配置，建议改完后重新 `npm run build` 对比。

### 3.3 路由懒加载

```js
// router/index.js
const GoodsList = () => import('@/views/goods-list.vue')
const GoodsDetail = () => import('@/views/goods-detail.vue')
const Cart = () => import('@/views/cart.vue')
```

好处：

- 首屏只加载列表页。
- Swiper 只进入详情页 chunk。
- 购物车页按需加载。

还可以给路由加 `webpackChunkName` 类似的命名（Vite/Rollup 用注释或 `rollupOptions.output.manualChunks`），便于观察拆包效果。

## 四、P1：正确性与健壮性

### 4.1 详情页参数变化不重载

**现状：**

```js
onMounted(loadProduct)
```

**问题：** Vue Router 在 `/goods/A → /goods/B` 时复用组件，`onMounted` 不执行。

**修复：**

```js
import { watch } from 'vue'

watch(() => props.skuId, loadProduct)
```

或强制重建：

```vue
<RouterView :key="$route.fullPath" />
```

> [!warning] 后者会让所有页面在参数变化时重建，可能丢失局部状态；前者的控制更精细。

### 4.2 评论 key 重复

**证据：** 600 条评论中，`nickname + time` 有 **127 组**重复。

**现状：**

```js
:key="`${comment.nickname}-${comment.time}`"
```

**修复：** 数据层保留 `comment_id`：

```js
// api/goods.js
.map((comment) => ({
  id: comment.comment_id,
  nickname: comment.user_nickname,
  avatar: comment.user_avatar_url,
  content: comment.content,
  after: comment.after_content,
  images: comment.images_urls || [],
  time: comment.comment_time,
}))
```

```vue
:key="comment.id"
```

### 4.3 数组字段无默认值

**风险点：**

| 代码 | 缺失时 |
| --- | --- |
| `product.mainImageUrls[0]` | `undefined` 或报错 |
| `product.mainImageUrls` | `.slice` 报错 |
| `product.detailImageUrls.slice(0, 5)` | 报错 |
| `comment.images.length` | 报错 |

**修复：**

```js
// normalizeProduct
mainImageUrls: raw.main_image_urls || [],
detailImageUrls: raw.detail_image_urls || [],

// fetchComments
images: comment.images_urls || [],
```

卡片图再加兜底：

```vue
<img
  :src="product.mainImageUrls[0] || fallbackImage"
  :alt="product.title"
  @error="onImageError"
/>
```

### 4.4 请求竞争

**现状：**

```js
async function loadGoods() {
  const result = await fetchGoodsList(...)
  products.value = result.list
}
```

**问题：** 快速搜索 A → B 时，A 的响应可能后到并覆盖 B。

**修复：**

```js
let requestId = 0

async function loadGoods() {
  const current = ++requestId
  loading.value = true
  error.value = ''

  try {
    const result = await fetchGoodsList(...)
    if (current !== requestId) return   // 过期响应丢弃
    products.value = result.list
    total.value = result.total
  } catch (requestError) {
    if (current !== requestId) return
    // ...
  } finally {
    if (current === requestId) loading.value = false
  }
}
```

真实 HTTP 请求还可以用 `AbortController`：

```js
const controller = new AbortController()
fetch('/api/products?...', { signal: controller.signal })
```

### 4.5 localStorage 写入异常

**现状：**

```js
watch(state, (newState) => {
  localStorage.setItem(STORAGE_KEY, JSON.stringify(items))
}, { deep: true })
```

**问题：** 隐私模式、存储配额满、被浏览器禁用时 `setItem` 会抛错，可能中断后续逻辑。

**修复：**

```js
watch(
  state,
  (newState) => {
    try {
      const items = newState.items.map((item) => ({ ... }))
      localStorage.setItem(STORAGE_KEY, JSON.stringify(items))
    } catch (error) {
      console.error('保存购物车失败：', error)
    }
  },
  { deep: true },
)
```

## 五、P2：体验与一致性

### 5.1 `sort` 参数未接入

`fetchGoodsList` 支持：

```js
if (sort === 'price-asc') result.sort((a, b) => a.price - b.price)
if (sort === 'price-desc') result.sort((a, b) => b.price - a.price)
```

但 `goods-list.vue` 没传。可以在页面上加：

```vue
<select v-model="sort" @change="onSortChange">
  <option value="default">默认排序</option>
  <option value="price-asc">价格从低到高</option>
  <option value="price-desc">价格从高到低</option>
</select>
```

```js
const sort = ref('default')

async function loadGoods() {
  const result = await fetchGoodsList({
    keyword: String(route.query.keyword || ''),
    page: currentPage.value,
    pageSize,
    sort: sort.value,
  })
  // ...
}
```

### 5.2 页码未进 URL

**现状：** `currentPage` 只是本地 `ref`。

**改法：**

```js
const currentPage = computed({
  get: () => Number(route.query.page) || 1,
  set: (page) => {
    router.push({
      query: { ...route.query, page: page === 1 ? undefined : page },
    })
  },
})
```

```js
watch(
  () => [route.query.keyword, route.query.page],
  () => {
    currentPage.value = Number(route.query.page) || 1
    loadGoods()
  },
)
```

注意避免两个 watch 重复请求，建议合并成一个监听数组的 watch。

### 5.3 头部点击区域

**现状：**

```vue
<div class="cart-bar" @click="goToCart">
<div class="home-bar" aria-label="返回主页" @click="goToHome">
```

**修复：**

```vue
<button type="button" class="cart-bar" aria-label="购物车" @click="goToCart">
  <el-icon class="cart-icon"><ShoppingCartFull /></el-icon>
  <CartDot />
</button>

<button type="button" class="home-bar" aria-label="返回主页" @click="goToHome">
  <el-icon class="home-icon"><House /></el-icon>
</button>
```

同时把 `.cart-bar` / `.home-bar` 的 `border`、`background`、`padding` 等按钮默认样式重置。

### 5.4 头部与页面留白

**现状：**

- `.header-bar` 没有 `position: fixed/sticky`。
- `.page` 有 `padding: 80px 16px 24px`。

**结果：** 头部和内容之间多出约 80px 空白。

**修复方向一：固定头部**

```css
.header-bar {
  position: sticky;
  top: 0;
  z-index: 100;
}
```

**修复方向二：调整留白**

```css
.page {
  padding: 24px 16px;
}
```

### 5.5 CSS 变量未落地

**现状：** `:root` 定义了 8 个变量，实际只用了 `--jd-red`（还在分页里），其余全部硬编码。

**修复：** 要么统一替换：

```css
.goods-price { color: var(--jd-red); }
.card { background: var(--surface); border: 1px solid var(--border-light); }
```

要么删掉未使用变量，避免误导。

### 5.6 数量控件重复

`goods-info-panel.vue` 自己实现了一套加减逻辑。建议：

```vue
<NumAddDel v-model="count" />
```

```js
import NumAddDel from '@/components/common/num-add-del.vue'
const count = ref(1)
```

### 5.7 未使用的代码

| 位置 | 未使用项 |
| --- | --- |
| `stores/cart.js` | `kinds`、`increase`、`decrease`（返回但无调用方） |
| `goods-gallery.vue` | `import 'swiper/css/navigation'`（未注册 Navigation） |
| `api/goods.js` | `sort` 参数（无 UI 入口） |

  :src="image"

### 6.2 测试

当前没有测试。优先补：

1. **数据层单元测试**：`fetchGoodsList` 的搜索、排序、分页边界。
2. **store 单元测试**：`add` 合并、99 上限、`setCount(0)` 删除、持久化校验。
3. **组件测试**：`NumAddDel` 的 emit、`CartItem` 的删除确认。
4. **E2E**：搜索 → 详情 → 加购 → 购物车 → 结算主链路。

### 6.3 ESLint / Prettier

项目没有 lint 配置。建议：

```bash
npm i -D eslint @eslint/js eslint-plugin-vue prettier
```

至少启用 `vue/multi-word-component-names`、未使用变量、`no-unused-vars` 等规则。

### 6.4 TypeScript

当前是 JS。如果要迁移，优先给数据模型加类型：

```ts
interface Product {
  skuId: string
  title: string
  price: number
  brand: string
  shopName: string
  params: Record<string, string>
  mainImageUrls: string[]
  detailImageUrls: string[]
  shortInfo: string
}

interface CartItem {
  skuId: string
  title: string
  cover: string
  price: number
  shortInfo: string
  count: number
}
```

类型能提前发现 `mainImageUrls[0]`、`comment.images.length` 这类问题。

### 6.5 结算闭环

如果要继续扩展，建议新增：

```text
/cart → /checkout（订单确认页）→ /order/success（订单成功页）
```

购物车结算时不要立刻 `clear()`，而是：

1. 生成订单快照。
2. 跳转确认页。
3. 支付成功后清空购物车。
4. 失败时保留购物车。

## 七、架构演进建议

### 7.1 迁移 Pinia

当前 `useCart()` 已经很像 Pinia。迁移成本低：

```js
// stores/cart.js
import { defineStore } from 'pinia'
import { ref, computed, watch } from 'vue'

export const useCartStore = defineStore('cart', () => {
  const items = ref([])

  const totalCount = computed(() =>
    items.value.reduce((sum, item) => sum + item.count, 0),
  )

  const totalAmount = computed(() =>
    Number(items.value.reduce((sum, item) => sum + item.price * item.count, 0).toFixed(2)),
  )

  function add(product, count = 1) { /* ... */ }

  return { items, totalCount, totalAmount, add }
})
```

好处：devtools 调试、SSR 支持、更规范的 store 组合。

### 7.2 接入真实后端

保持 `api/goods.js` 的函数签名不变，把内部换成 HTTP：

```js
export async function fetchGoodsList({ keyword, page, pageSize, sort }) {
  const { data } = await axios.get('/api/products', {
    params: { keyword, page, pageSize, sort },
  })
  return data   // { list, total }
}
```

页面层无需改动。这是当前数据层抽象最大的价值。

### 7.3 组件库按需化

见 P0。对于只用消息框和图标的小项目，甚至可以考虑**完全移除 Element Plus**，用原生 `dialog` 和自写 toast，进一步减小体积。当前项目对 Element Plus 的依赖其实很浅。

## 十、结论

这个项目最值得保留的设计是：

1. **数据层归一化**：把后端字段挡在页面之外。
2. **购物车单一数据源**：所有金额和数量都是派生值。
3. **页面/展示组件分离**：页面管数据，组件管渲染。
4. **持久化闭环**：读取校验 + 深度监听写入。

最值得优先修的三件事是：

1. **减小打包体积**（Element Plus 按需 + 路由懒加载）。
2. **补健壮性**（默认值、重复 key、请求竞争、存储异常）。
3. **补工程化**（README、测试、Lint）。
