## 三、六个「能讲清楚就算学会」的问题

### 问题 1：为什么商品数据只归一化一次？

因为 `productsRaw.map(normalizeProduct)` 位于模块顶层，模块只执行一次，`products` 成为应用级只读数组。页面每次查询都复用这份数组，不重复转换。

### 问题 2：搜索词为什么不放在 `GoodsList` 的 `ref` 里？

因为搜索框在 `TabHeader`，列表页在 `RouterView` 里，两者没有父子关系。把搜索词放进 URL query，任何组件都能通过 `router.push` 写入，列表页通过 `watch(route.query.keyword)` 读取。

### 问题 3：为什么购物车用 `reactive` 而不是 `ref`？

`state` 是一个包含 `items` 数组的对象。`reactive` 会深层代理对象及其属性，`state.items.push(...)`、`item.count = n` 都能被追踪。用 `ref({ items: [] })` 也可以，但访问时要写 `state.value.items`，不如 `reactive` 直观。

### 问题 4：为什么删除用 `splice` 而不是 `filter` 重新赋值？

`Cart` 组件已经把 `state.items` 的数组引用传给 `CartList`。`filter` 会产生新数组，`state.items` 引用改变后，已解构出的 `items` 仍指向旧数组，界面不更新。`splice` 原地修改，所有引用保持一致。

### 问题 5：为什么 `watch` 要加 `deep: true`？

购物车变化不只是「数组增删」，还包括「数组内某个 `item.count` 改变」。`deep: true` 让 watcher 递归追踪嵌套属性，否则修改数量不会触发保存。

### 问题 6：为什么 `NumAddDel` 不直接调用 `useCart()`？

因为它是**通用组件**，不应该知道「购物车」这个业务。它只认 `modelValue` 和 `update:modelValue`，谁使用它，谁决定怎么处理新值。这样它也能被用在「商品详情数量选择」等其它场景。

## 五、这个项目最值得带走的三件事

### 5.1 数据归一化

把后端字段转换成前端模型，集中在 `normalizeProduct`。页面不再关心 `sku_id` 还是 `skuId`，也不关心价格是字符串还是数字。

```text
后端字段 ──normalize──► 前端模型 ──props──► 组件
```

### 5.2 单一数据源 + 派生状态

购物车只有一份 `state.items`。件数、金额、角标、按钮文字全部由它计算，不单独保存。

```text
state.items
  ├─ computed: totalCount
  ├─ computed: totalAmount
  └─ computed: kinds
```

### 5.3 页面 / 展示组件分离

- 页面（`views`）负责：取数、加载状态、错误状态、路由。
- 展示组件（`components`）负责：接收 props、渲染、发出事件。

```text
页面 = 数据 + 状态 + 编排
组件 = 展示 + 交互
```

## 六、最后总结

```text
项目入口
  index.html → main.js → App.vue
        ↓
路由
  /goods → 列表
  /goods/:skuId → 详情
  /cart → 购物车
        ↓
数据
  products.json / comments.json → api/goods.js
        ↓
状态
  页面 ref + 购物车 store
        ↓
交互
  搜索 / 分页 / 加购 / 改数量 / 删除 / 结算
        ↓
持久化
  localStorage('jd_cart_v1')
```

> [!important] 一句话记住这个项目
> **商品是只读快照，购物车是可变单例；页面用 ref 管自己的临时状态，跨页面用 URL 和 store；所有界面变化最终都回到「状态变了，Vue 自动更新 DOM」。**

如果你能不看笔记，独立讲清楚「搜索、分页、详情、加购、结算」五条链路，并且能指出详情页参数复用、评论 key 重复、Element Plus 全量引入这三个问题，那么你已经真正读懂了这个项目。
