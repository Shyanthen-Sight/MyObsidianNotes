# 数据流总图

> [!abstract] 一句话
> 整个项目只有两条主干数据流：==只读的「JSON → 归一化 → 查询 → 页面 → 组件」==和==可变的「用户操作 → store → computed → 界面 + localStorage」==；路由 URL 是第三条辅助状态流，负责把搜索词和商品 ID 在页面之间传递。

## 二、只读数据线

商品和评论是**只读**的：从 JSON 读入后归一化一次，之后只被查询，不被修改。

```text
products.json（61 条，snake_case）
  ↓ import
productsRaw
  ↓ .map(normalizeProduct)
products（camelCase，price 为 number，含 shortInfo）
  ↓
fetchGoodsList({ keyword, page, pageSize, sort })
  ├─ filter：title / brand / shopName / params 值
  ├─ sort：price-asc / price-desc（当前未接入 UI）
  └─ slice：当前页
  ↓ Promise + setTimeout(150ms)
{ list, total }
  ↓
GoodsList.products / GoodsList.total
  ↓ props
GoodsCardLoop.products
  ↓ v-for
GoodsCard.product
  ↓
DOM：图片 / 标题 / 店铺 / 价格
```

详情线：

```text
路由 /goods/:skuId
  ↓ props: true
GoodsDetail.skuId
  ↓ onMounted
fetchGoodsDetail(skuId)（200ms）
  ↓ find
product
  ├─→ GoodsGallery.mainImageUrls + detailImageUrls
  ├─→ GoodsInfoPanel.title / shopName / price
  ├─→ ShowcaseBoard.params
  └─→ GoodsScrollImg.detailImageUrls

fetchComments(skuId)（150ms）
  ↓ filter + map
comments
  └─→ CommentList.comments
```

> [!note] 只读数据不会触发购物车
> 商品对象只作为「快照来源」：加购时 `add()` 从中取 `skuId / title / price / cover / shortInfo` 存入购物车。之后商品数据如何变化，都不会影响已加入购物车的快照。

## 三、可变状态线

购物车是项目里唯一的可变共享状态。

```text
用户点击「加入购物车」
  ↓
GoodsInfoPanel.addToCart()
  ↓ add(product, count)
cart store：
  ├─ 已存在 → item.count = min(item.count + count, 99)
  └─ 不存在 → state.items.push({ skuId, title, cover, price, shortInfo, count })
  ↓
state.items 变化（reactive 追踪）
  ├─→ CartDot.totalCount         → 角标数字
  ├─→ Cart / CartList.items      → 列表行
  ├─→ CartItem.item.count        → 数量显示
  ├─→ FooterFixed.totalCount     → 件数 / 按钮文字
  └─→ FooterFixed.totalAmount    → 合计金额
  ↓
watch(state, save, { deep: true })
  ↓ 白名单 map
localStorage.setItem('jd_cart_v1', JSON.stringify(items))
```

启动时反向恢复：

```text
import stores/cart.js
  ↓
localStorage.getItem('jd_cart_v1')
  ↓ JSON.parse + Array.isArray + 字段校验
state.items.push(...合法项)
  ↓
所有读取购物车的组件立即得到数据
```

## 四、路由状态线

URL 承担了三类状态：

| URL 形态 | 承载状态 | 谁写入 | 谁读取 |
| --- | --- | --- | --- |
| `/goods?keyword=手机` | 搜索词 | `TabHeader.onSearch` | `GoodsList` 的 `watch` |
| `/goods/:skuId` | 商品 ID | `GoodsCard` / `CartItem` | `GoodsDetail` 的 prop |
| `/cart` | 当前页面 | `TabHeader.goToCart` | `App.vue` 的 `route.name` |
| `/` | 重定向 | — | `router` |
| 未知路径 | 重定向 | — | `router` |

```text
TabHeader
  │ router.push('/goods?keyword=手机')
  ▼
Vue Router（URL 变化）
  ▼
GoodsList.watch(() => route.query.keyword)
  ▼
loadGoods()
```

> [!important] URL 是「可分享、可刷新」的状态
> 搜索词放在 query，所以刷新和分享都能恢复；页码只放在组件里，所以刷新会回到第 1 页。这是当前项目状态设计上最明显的不对称。

## 五、五条端到端流程

### 5.1 搜索

```text
输入框 v-model
  → 回车 @keyup.enter
  → trim
  → router.push({ path: '/goods', query })
  → route.query.keyword 变化
  → watch：currentPage = 1
  → loadGoods()
  → fetchGoodsList 过滤
  → products 更新
  → GoodsCardLoop 重渲染
```

### 5.2 分页

```text
点击页码
  → goToPage(page)
  → 边界检查
  → currentPage = page
  → loadGoods()
  → fetchGoodsList slice
  → products 更新
  → 卡片重渲染
```

### 5.3 查看详情

```text
点击商品卡片
  → router.push(`/goods/${skuId}`)
  → 路由匹配 + props
  → GoodsDetail.onMounted
  → fetchGoodsDetail → product
  → fetchComments → comments
  → 五个展示组件渲染
```

### 5.4 加入购物车

```text
选择数量
  → 点击加入购物车
  → add(product, count)
  → state.items 变化
  → computed 更新（件数 / 金额）
  → 角标、购物车页、结算栏同步
  → watch 写 localStorage
```

### 5.5 修改 / 删除 / 结算

```text
NumAddDel emit
  → CartItem.setCount
  → store.setCount
  → item.count 变化
  → 小计 / 合计 / 角标 / 存储更新

删除 → confirm → store.remove → splice → 行消失

结算 → confirm → store.clear → 清空 → 提示 → 跳转 /goods
```

## 六、状态归属表

| 状态 | 所在位置 | 类型 | 生命周期 | 是否持久化 |
| --- | --- | --- | --- | --- |
| `productsRaw` / `commentsRaw` | `api/goods.js` 模块 | 只读数组 | 应用级 | 否（构建进 bundle） |
| `products`（归一化后） | `api/goods.js` 模块 | 只读数组 | 应用级 | 否 |
| `state.items` | `stores/cart.js` 模块 | `reactive` | 应用级 | ✅ localStorage |
| `totalCount` / `totalAmount` / `kinds` | `stores/cart.js` 模块 | `computed` | 应用级 | 否（派生） |
| `loading` / `error` / `products` / `total` / `currentPage` | `goods-list.vue` | `ref` | 页面级 | 否 |
| `product` / `comments` / `loading` / `error` | `goods-detail.vue` | `ref` | 页面级 | 否 |
| `count` | `goods-info-panel.vue` | `ref` | 组件级 | 否 |
| `keyword` | `tab-header.vue` | `ref` | 组件级 | 否（提交后进 URL） |
| `route.query.keyword` | URL | 路由状态 | 导航级 | ✅ URL |
| `route.params.skuId` | URL | 路由状态 | 导航级 | ✅ URL |

> [!tip] 判断状态该放哪
> 1. 只有一个组件用 → 放组件内 `ref`。
> 2. 多个页面共享且需要持久化 → 放 store。
> 3. 需要分享/刷新恢复 → 放 URL。
> 4. 完全由其它状态推导 → 用 `computed`，不要单独存。

## 七、响应式机制对照

| 机制 | 项目中的例子 | 作用 |
| --- | --- | --- |
| `ref` | `loading`、`currentPage`、`count`、`keyword` | 包装基本类型/对象，模板自动解包 |
| `reactive` | `state` | 深层响应式对象 |
| `computed` | `totalPages`、`totalCount`、`totalAmount`、`params`、`images` | 派生数据，依赖变化自动重算 |
| `watch` | 搜索词变化、购物车落盘 | 监听变化执行副作用 |
| `onMounted` | 列表/详情首次加载 | 生命周期钩子 |
| `props` | `product`、`comments`、`items`、`modelValue` | 父 → 子数据流 |
| `emit` | `update:modelValue`、`action` | 子 → 父事件 |
| `v-model` | 搜索框、`NumAddDel`（显式写法） | 双向绑定语法糖 |
| `v-if / v-else-if / v-else` | 加载/错误/成功三态 | 条件渲染 |
| `v-for` | 卡片、评论、购物车行 | 列表渲染 |
| `TransitionGroup` | 购物车行增删 | 列表过渡动画 |

## 九、小结

如果要用一句话描述整个项目的数据流：

> **商品数据是「一次性读入、到处查询」的只读快照；购物车是「集中修改、自动派生、深度监听落盘」的可变单例；URL 是「搜索词和商品 ID」的公共传递通道。**

把这三条线记住，再回头看任何组件，都能快速判断：

- 它的数据从哪来？
- 它的操作会改哪份状态？
- 改完之后谁会更新？
