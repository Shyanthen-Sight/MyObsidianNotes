# 商品列表与卡片

> [!abstract] 一句话
> 列表页 `goods-list.vue` 是典型的「==状态 + 异步加载 + 条件渲染 + 分页==」结构：它持有 5 个状态，调用 `fetchGoodsList` 拿到当前页数据，再把数组交给 `GoodsCardLoop` → `GoodsCard` 递归展示；搜索词变化时通过 `watch` 自动回到第一页重新请求。

---

## 一、页面结构

```text
GoodsList
├─ loading 为真      → <p>正在加载商品...</p>
├─ error 非空        → <p>{{ error }}</p>
└─ 正常
   ├─ products 非空  → <GoodsCardLoop :products="products" />
   ├─ products 为空  → <p>没有找到相关商品</p>
   └─ totalPages > 1 → <nav class="pagination">...</nav>
```

模板使用 `v-if` / `v-else-if` / `v-else` 三态切换，避免加载中、失败、成功三种内容同时出现。

---

## 二、页面状态

```js
const pageSize = 12
const loading = ref(false)
const error = ref('')
const products = ref([])
const total = ref(0)
const currentPage = ref(1)
const totalPages = computed(() => Math.ceil(total.value / pageSize))
```

| 状态 | 类型 | 含义 |
| --- | --- | --- |
| `pageSize` | 常量 | 每页 12 条 |
| `loading` | `ref<boolean>` | 是否正在请求 |
| `error` | `ref<string>` | 错误提示 |
| `products` | `ref<Array>` | 当前页商品 |
| `total` | `ref<number>` | 过滤后的总条数 |
| `currentPage` | `ref<number>` | 当前页码，从 1 开始 |
| `totalPages` | `computed<number>` | `Math.ceil(total / 12)` |

> [!note] 为什么 `totalPages` 用 `computed`
> 它完全由 `total` 和 `pageSize` 推导出来。用计算属性可以保证只要 `total` 变化，页数自动更新，不需要手动同步两个变量。

## 三、数据加载 `loadGoods`

```js
async function loadGoods() {
  loading.value = true
  error.value = ''

  try {
    const result = await fetchGoodsList({
      keyword: String(route.query.keyword || ''),
      page: currentPage.value,
      pageSize,
    })

    products.value = result.list
    total.value = result.total
  } catch (requestError) {
    products.value = []
    total.value = 0
    error.value = '商品加载失败，请稍后重试'
    console.error('商品列表加载失败：', requestError)
  } finally {
    loading.value = false
  }
}
```

执行顺序：

```text
loading = true
error = ''
  ↓
await fetchGoodsList({ keyword, page, pageSize })
  ↓
成功：products = result.list；total = result.total
失败：products = []；total = 0；error = '...'
  ↓
finally：loading = false
```

几个细节：

1. **每次请求前清空 `error`**，避免上一次的错误一直显示。
2. **失败时清空列表和总数**，防止旧数据与错误提示同时出现。
3. **`finally` 保证 `loading` 一定复位**，即使 `fetch` 抛错。
4. **`String(route.query.keyword || '')`**：query 可能是 `undefined`、数组或字符串，统一转成字符串。

> [!warning] `fetchGoodsList` 目前不会失败
> 它的 Promise 只有 `resolve`，没有 `reject`。因此 `catch` 分支在当前实现下不会触发，属于「为未来真实接口预留」的代码。

## 四、首次加载与搜索监听

```js
onMounted(loadGoods)

watch(
  () => route.query.keyword,
  () => {
    currentPage.value = 1
    loadGoods()
  },
)
```

- `onMounted(loadGoods)`：页面首次进入时加载第 1 页。
- `watch` 监听 query 中的 `keyword`：
  - 用户在顶部搜索框回车 → `router.push({ path: '/goods', query: { keyword } })`
  - 如果当前已经在 `/goods`，URL query 变化，watch 触发
  - 搜索条件变了，页码必须回到 1，再重新请求

> [!tip] 为什么搜索要回到第 1 页
> 假设用户在第 6 页搜索一个只有 2 条结果的词，如果仍请求第 6 页，会得到空数组。重置到第 1 页是符合直觉的行为。

搜索链路：

```text
TabHeader 输入「手机」
  ↓ 回车
router.push('/goods?keyword=手机')
  ↓
route.query.keyword 变化
  ↓
watch 回调：currentPage = 1
  ↓
loadGoods()
  ↓
fetchGoodsList 过滤 title / brand / shopName / params
  ↓
products 更新 → 卡片重渲染
```

## 五、分页

### 5.1 页码点击

```js
function goToPage(page) {
  if (page < 1 || page > totalPages.value || page === currentPage.value) {
    return
  }
  currentPage.value = page
  loadGoods()
}
```

三重边界判断：

1. 小于 1：无效。
2. 大于总页数：无效。
3. 等于当前页：无需重复请求。

### 5.2 分页 UI

```vue
<nav v-if="totalPages > 1" class="pagination" aria-label="商品列表分页">
  <button :disabled="currentPage === 1" @click="goToPage(currentPage - 1)">
    上一页
  </button>

  <button
    v-for="page in totalPages"
    :key="page"
    :class="{ active: page === currentPage }"
    :aria-current="page === currentPage ? 'page' : undefined"
    @click="goToPage(page)"
  >
    {{ page }}
  </button>

  <button :disabled="currentPage === totalPages" @click="goToPage(currentPage + 1)">
    下一页
  </button>
</nav>
```

- `v-if="totalPages > 1"`：只有一页时不显示分页。
- `:disabled` 控制首尾。
- `:class="{ active: ... }"` 高亮当前页。
- `:aria-current="page"` 告诉屏幕阅读器当前页。
- `v-for="page in totalPages"`：`totalPages` 是数字，Vue 会从 1 迭代到该数字。

当前 61 条数据、每页 12 条 → 6 个页码按钮，全部平铺。如果商品数量增长到几百条，页码会过多，需要改成「省略号 + 当前页附近若干页」的分页组件。

### 5.3 页码没有写进 URL

当前分页只存在组件状态 `currentPage` 中。后果：

- 刷新页面会回到第 1 页。
- 无法分享「第 3 页」的链接。
- 浏览器后退不能回到上一页。

改进方式是把页码也放进 query，例如 `?page=3&keyword=手机`，并让 `currentPage` 从 query 初始化。详见 [[代码质量与改进]]。

## 六、卡片网格 `GoodsCardLoop`

```vue
<template>
  <div class="goods-grid">
    <GoodsCard
      v-for="product in products"
      :key="product.skuId"
      :product="product"
    />
  </div>
</template>

<script setup>
import GoodsCard from './goods-card.vue'

defineProps({
  products: { type: Array, required: true },
})
</script>
```

它本身几乎没有逻辑，只负责：

1. 接收 `products`。
2. 用 `v-for` 渲染卡片。
3. 用 Grid 排列。

```css
.goods-grid {
  display: grid;
  grid-template-columns: repeat(4, minmax(0, 1fr));
  gap: 16px;
}

@media (max-width: 900px) {
  .goods-grid { grid-template-columns: repeat(3, minmax(0, 1fr)); }
}

@media (max-width: 640px) {
  .goods-grid { grid-template-columns: repeat(2, minmax(0, 1fr)); gap: 10px; }
}
```

断点设计：

| 视口宽度 | 列数 |
| --- | --- |
| > 900px | 4 列 |
| 641–900px | 3 列 |
| ≤ 640px | 2 列 |

`minmax(0, 1fr)` 而不是 `1fr`，是为了防止长标题把网格列撑破（Grid 默认 `min-width: auto`，内容过长会溢出）。

> [!note] 为什么没有 1 列
> 手机上 2 列卡片仍然可读，且更接近京东/淘宝的移动端布局。如果商品图很小，可以再增加一个 480px 以下 1 列的断点。

## 七、商品卡片 `GoodsCard`

### 7.1 模板

```vue
<article
  class="goods-card"
  role="link"
  tabindex="0"
  @click="goToDetail"
  @keydown.enter="goToDetail"
  @keydown.space.prevent="goToDetail"
>
  <img class="goods-image" :src="product.mainImageUrls[0]" :alt="product.title" />

  <div class="goods-content">
    <h2 class="goods-title">{{ product.title }}</h2>
    <p class="goods-info"><span>{{ product.shopName }}</span></p>
    <div class="goods-footer">
      <p class="goods-price"><small>¥</small>{{ formatPrice(product.price) }}</p>
      <span class="positive-review">＋</span>
    </div>
  </div>
</article>
```

### 7.2 交互与可访问性

卡片没有使用 `<router-link>`，而是一个 `article` 加上：

- `role="link"`：告诉辅助技术这是一个链接。
- `tabindex="0"`：可以通过 Tab 聚焦。
- `@click`：鼠标点击。
- `@keydown.enter`：回车触发。
- `@keydown.space.prevent`：空格触发，并阻止页面滚动。
- `:focus-visible` 样式：键盘聚焦时显示红色轮廓。

这是一段**做得比较认真的自定义可访问性代码**，比直接给 `div` 加 `@click` 好得多。

> [!tip] 更简单的替代方案
> 可以直接用：
>
> ```vue
> <RouterLink :to="`/goods/${product.skuId}`" class="goods-card">...</RouterLink>
> ```
>
> 浏览器原生支持键盘、右键「在新标签页打开」、状态栏预览 URL。当前写法牺牲了「新标签页打开」等能力。

### 7.3 图片

```vue
<img class="goods-image" :src="product.mainImageUrls[0]" :alt="product.title" />
```

```css
.goods-image {
  display: block;
  width: 100%;
  aspect-ratio: 1;
  object-fit: cover;
  background: #f7f8fa;
}
```

- `aspect-ratio: 1`：保证图片区域是正方形，避免加载时布局跳动。
- `object-fit: cover`：裁剪填满，不变形。
- `background: #f7f8fa`：图片加载前的占位底色。
- `alt` 使用商品标题，利于无障碍和 SEO。

> [!warning] 对 `mainImageUrls` 的强假设
> 代码直接访问 `product.mainImageUrls[0]`。如果某个商品的主图数组为空或字段缺失，会得到 `undefined` 甚至运行时报错。归一化时补一个默认值更安全：
>
> ```js
> mainImageUrls: raw.main_image_urls || [],
> ```

### 7.4 标题与摘要

```css
.goods-title {
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
}
```

标题单行省略。商品标题通常很长（例如包含促销词、颜色、内存），单行可以保证卡片高度一致。

`goods-info` 固定高度 15px，只显示店铺名一行：

```css
.goods-info {
  overflow: hidden;
  height: 15px;
  margin: 0 0 14px;
}
```

### 7.5 价格与「＋」

```vue
<p class="goods-price"><small>¥</small>{{ formatPrice(product.price) }}</p>
<span class="positive-review">＋</span>
```

- 价格统一走 `formatPrice`，保留两位小数。
- 右侧的 `＋` 是一个装饰性的圆形按钮，目前**没有绑定点击事件**，只是视觉元素。若要做「快速加购」，需要给它加点击处理并阻止冒泡（否则会同时触发卡片跳转）。

## 八、列表页的完整数据流

```text
进入 /goods
  ↓
onMounted → loadGoods()
  ↓
fetchGoodsList({ keyword: route.query.keyword, page: 1, pageSize: 12 })
  ↓
Promise（150ms）→ { list, total }
  ↓
products = list；total = 61
  ↓
totalPages = ceil(61 / 12) = 6
  ↓
GoodsCardLoop 渲染 12 张 GoodsCard
  ↓
用户点页码 3
  ↓
goToPage(3) → currentPage = 3 → loadGoods()
  ↓
fetchGoodsList({ page: 3 }) → 第 25–36 条
  ↓
重新渲染
```

## 九、可以改进的点

| 问题 | 影响 | 建议 |
| --- | --- | --- |
| 页码不进 URL | 刷新/分享/后退丢状态 | `?page=` 同步 |
| 排序参数未接入 | `sort` 能力闲置 | 加排序下拉 |
| 空结果只有一行文字 | 体验单薄 | 复用 `EmptyState` |
| 加载只有文字 | 布局会跳动 | 加骨架屏 |
| 卡片用 `article` 模拟链接 | 不能新标签页打开 | 用 `RouterLink` |
| `mainImageUrls[0]` 无兜底 | 缺图报错 | 归一化补 `[]` |
| 页码全部平铺 | 数据多时溢出 | 省略号分页 |
| 请求无取消 | 快速切换可能旧数据覆盖 | 请求序号 / `AbortController` |

---

## 十、小结

列表页的核心只有三句话：

1. **状态驱动 UI**：`loading` / `error` / `products` 决定显示哪一块。
2. **分页是切片**：`currentPage` 决定向数据层请求哪一段。
3. **搜索是 URL 状态**：query 变化 → `watch` → 重置页码 → 重新请求。

卡片则是一个纯展示组件：接收 `product`，渲染图片、标题、店铺、价格，点击后跳详情。
