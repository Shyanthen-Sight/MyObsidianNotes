# 组件树与职责

> [!abstract] 一句话
> 全项目共 ==18 个 `.vue` 文件==（1 个根组件 + 3 个页面 + 14 个业务/通用组件）。通信只有三条通道：**父传子 `props`**、**子传父 `emit`**、**通过 `useCart()` 共享同一份响应式状态**；没有 Pinia、没有 `provide/inject`、没有事件总线。

---

## 一、完整组件树

```text
App.vue
├─ TabHeader（常驻顶部导航）
│  └─ CartDot（购物车角标）
└─ RouterView
   ├─ GoodsList（/goods）
   │  └─ GoodsCardLoop
   │     └─ GoodsCard × N
   │
   ├─ GoodsDetail（/goods/:skuId）
   │  ├─ GoodsGallery（主图轮播）
   │  ├─ GoodsInfoPanel（标题 / 价格 / 数量 / 加购）
   │  ├─ ShowcaseBoard（商品参数）
   │  ├─ GoodsScrollImg（详情长图）
   │  └─ CommentList（用户评价）
   │
   └─ Cart（/cart）
      ├─ CartList
      │  ├─ CartItem × N
      │  │  └─ NumAddDel（数量加减）
      │  └─ EmptyState（空购物车时）
      └─ FooterFixed（固定结算栏）
```

## 二、每个组件的职责与接口

### 2.1 外壳与导航

| 组件 | 父级 | Props | Emits | 职责 |
| --- | --- | --- | --- | --- |
| `App.vue` | — | — | — | 应用外壳；决定购物车页是否全宽 |
| `TabHeader` | `App` | 无 | 无 | Logo、搜索框、购物车入口、首页入口 |
| `CartDot` | `TabHeader` | 无 | 无 | 从 store 读 `totalCount`，显示角标 |

`TabHeader` 自己持有搜索词：

```js
const keyword = ref('')
function onSearch() {
  const value = keyword.value.trim()
  router.push({ path: '/goods', query: value ? { keyword: value } : {} })
}
```

它不把搜索词传给任何子组件，而是通过**路由 query** 交给列表页，这是「用 URL 传递状态」的做法。

### 2.2 商品列表

| 组件 | 父级 | Props | 职责 |
| --- | --- | --- | --- |
| `GoodsList` | `RouterView` | 无 | 页面状态、加载数据、分页、搜索监听 |
| `GoodsCardLoop` | `GoodsList` | `products: Array` | 用 Grid 排列卡片 |
| `GoodsCard` | `GoodsCardLoop` | `product: Object` | 展示单件商品；点击跳详情 |

`GoodsList` 是列表页的**容器组件**，负责：

- `loading` / `error` / `products` / `total` / `currentPage` 五个状态
- 调用 `fetchGoodsList`
- 计算 `totalPages`
- 处理页码点击
- 监听 `route.query.keyword`

`GoodsCard` 是**展示组件**，只接收一个 `product`，不请求数据。

### 2.3 商品详情

| 组件 | 父级 | Props | 职责 |
| --- | --- | --- | --- |
| `GoodsDetail` | `RouterView` | `skuId: String` | 加载商品与评论；编排五个详情区块 |
| `GoodsGallery` | `GoodsDetail` | `product: Object` | Swiper 主图轮播 |
| `GoodsInfoPanel` | `GoodsDetail` | `product: Object` | 标题、店铺、价格、数量、加入购物车 |
| `ShowcaseBoard` | `GoodsDetail` | `product: Object` | 把 `params` 渲染成参数表 |
| `GoodsScrollImg` | `GoodsDetail` | `product: Object` | 渲染全部详情长图 |
| `CommentList` | `GoodsDetail` | `comments: Array` | 渲染评论列表 |

`GoodsDetail` 是详情页的**数据容器**：

```js
async function loadProduct() {
  loading.value = true
  error.value = ''
  try {
    product.value = await fetchGoodsDetail(props.skuId)
    comments.value = await fetchComments(props.skuId)
  } catch (requestError) {
    error.value = '商品不存在或加载失败'
  } finally {
    loading.value = false
  }
}
```

它把 `product` 分发给四个展示组件，把 `comments` 分发给评论组件。展示组件不关心数据从哪来。

### 2.4 购物车

| 组件 | 父级 | Props | Emits | 职责 |
| --- | --- | --- | --- | --- |
| `Cart` | `RouterView` | 无 | 无 | 从 store 取 `items`，组合列表与结算栏 |
| `CartList` | `Cart` | `items: Array` | 无（`EmptyState` 的 `action` 内部处理） | 表头、列表、空状态、过渡动画 |
| `CartItem` | `CartList` | `item: Object` | 无 | 单行商品；改数量、删除、跳详情 |
| `NumAddDel` | `CartItem` | `modelValue: Number` | `update:modelValue` | 通用数量加减器 |
| `EmptyState` | `CartList` | `title` / `description` / `actionText` | `action` | 通用空状态 |
| `FooterFixed` | `Cart` | 无 | 无 | 总件数、总金额、结算 |

购物车页的通信是**混合模式**：

```text
Cart（从 store 读 items）
  │ props: items
  ▼
CartList
  │ props: item
  ▼
CartItem ──直接调用 useCart() 的 setCount / remove──► store
```

也就是说：

- **展示数据**通过 props 往下传（`items` → `item`）。
- **修改数据**不通过 emit 层层上报，而是 `CartItem` 直接调用 store 的方法。

> [!note] 两种风格都成立
> 对「删除一行」这种只影响全局购物车的操作，直接调 store 可以减少一层 `emit` 转发；对「表单输入」这种需要父组件校验的操作，用 `emit` 更合适。项目里 `NumAddDel` 使用 `v-model` 事件，是因为它被设计成通用组件，不应该知道购物车 store 的存在。

## 三、三条通信通道

### 3.1 父传子：Props

典型例子：

```vue
<!-- GoodsList -->
<GoodsCardLoop v-if="products.length > 0" :products="products" />

<!-- GoodsCardLoop -->
<GoodsCard
  v-for="product in products"
  :key="product.skuId"
  :product="product"
/>
```

```js
// goods-card.vue
const props = defineProps({
  product: { type: Object, required: true },
})
```

规则：

- props 是**只读**的，子组件不能直接修改。
- 父组件数据变化时，子组件自动收到新值并重新渲染。
- `:key="product.skuId"` 让 Vue 能正确复用/移动列表项。

### 3.2 子传父：`emit`

项目里标准的 emit 出现在 `NumAddDel`：

```vue
<!-- cart-item.vue -->
<NumAddDel
  :model-value="item.count"
  @update:model-value="setCount"
/>
```

```js
// num-add-del.vue
const props = defineProps({
  modelValue: { type: Number, required: true },
})
const emit = defineEmits(['update:modelValue'])

function increase() {
  emit('update:modelValue', Math.min(props.modelValue + 1, 99))
}
```

数据流：

```text
用户点 +
  ↓
NumAddDel emit('update:modelValue', count + 1)
  ↓
CartItem.setCount(newCount)
  ↓
store.setCount(skuId, newCount)
  ↓
state.items 变化
  ↓
CartItem 收到新的 item.count 并重新渲染
```

`EmptyState` 也是 emit：

```vue
<button type="button" @click="$emit('action')">{{ actionText }}</button>
```

```vue
<EmptyState v-else @action="goShopping" />
```

### 3.3 共享状态：`useCart()`

`stores/cart.js` 在模块顶层创建唯一一份 `state`：

```js
const state = reactive({ items: [] })

export function useCart() {
  return {
    items: state.items,
    totalCount,
    totalAmount,
    kinds,
    add,
    remove,
    setCount,
    increase,
    decrease,
    clear,
  }
}
```

任何组件调用 `useCart()`，拿到的都是**同一份** `state.items`。因此以下三个位置会自动同步：

- `GoodsInfoPanel` 的「加入购物车」
- `TabHeader` 里的 `CartDot` 角标
- `Cart` 页面与 `FooterFixed` 的合计

这就是没有 Pinia 也能跨组件共享状态的原因，详见 [[购物车状态与持久化]]。

### 3.4 路由导航

四个组件直接调用 `router.push`：

| 组件 | 跳转 |
| --- | --- |
| `TabHeader` | `/cart`、`/goods`、`/goods?keyword=...` |
| `GoodsCard` | `/goods/:skuId` |
| `CartItem` | `/goods/:skuId` |
| `EmptyState` 的父级 `CartList` | `/goods` |
| `FooterFixed` | 结算后 `/goods` |

路由跳转也是一种「跨组件通信」：`TabHeader` 通过 URL 把搜索词交给 `GoodsList`，两者没有直接的 props/emit 关系。

## 四、组件分类

### 4.1 按角色

| 类型 | 组件 | 特征 |
| --- | --- | --- |
| 外壳组件 | `App` | 只负责布局与出口 |
| 页面容器 | `GoodsList`、`GoodsDetail`、`Cart` | 持有页面状态、请求数据 |
| 业务展示 | `GoodsCardLoop`、`GoodsCard`、`GoodsGallery`、`GoodsInfoPanel`、`ShowcaseBoard`、`GoodsScrollImg`、`CommentList`、`CartList`、`CartItem`、`FooterFixed` | 绑定具体业务字段 |
| 通用组件 | `NumAddDel`、`EmptyState`、`CartDot` | 不依赖具体商品结构 |

### 4.2 复用情况

- `NumAddDel`：只在购物车使用，但被设计成通用组件（只认 `modelValue`）。
- `EmptyState`：只在购物车使用，支持自定义标题、描述、按钮文字。
- `CartDot`：只在头部使用，但把「读 store」封装在内部。
- `GoodsCard`：在列表中通过 `v-for` 复用。

> [!warning] 有一处逻辑重复
> `goods-info-panel.vue` 自己写了一套数量加减：
>
> ```js
> function increase() { count.value = Math.min(count.value + 1, 99) }
> function decrease() { count.value = Math.max(count.value - 1, 1) }
> ```
>
> 这与 `NumAddDel` 的边界逻辑完全一样，却没有复用组件。可以改成：
>
> ```vue
> <NumAddDel v-model="count" />
> ```
>
> 减少重复，也让详情页和购物车的交互保持一致。

## 五、组件设计评价

### 5.1 做得好的地方

1. **页面与展示分离**：页面负责取数，展示组件只接收 props。
2. **命名清晰**：`goods-list`、`goods-detail`、`cart-item` 一眼能看出用途。
3. **通用组件边界合理**：`NumAddDel` 不依赖 store，`EmptyState` 不依赖路由。
4. **详情页拆分细致**：轮播、信息、参数、长图、评论各自独立，便于单独修改。
5. **购物车用 store 解耦**：角标、列表、结算栏不需要层层传 props。

### 5.2 可以改进的地方

| 问题 | 说明 |
| --- | --- |
| 数量控件重复 | 详情页可复用 `NumAddDel` |
| `CartItem` 直接调 store | 与 `CartList` 的 props 风格混用，但可接受 |
| `EmptyState` 使用范围窄 | 商品列表的空结果用的是普通 `<p>`，可统一 |
| 缺少加载骨架 | 目前只有文字「正在加载...」 |
| 详情页缺少参数变化监听 | 同组件复用时不重新加载 |

这些问题会在 [[代码质量与改进]] 中统一分级。

## 六、小结

```text
数据从哪来？
  ├─ 页面容器：fetchGoodsList / fetchGoodsDetail / fetchComments
  └─ 共享状态：useCart()

数据怎么往下走？
  └─ props（products / product / comments / items / item / modelValue）

用户操作怎么往上走？
  ├─ emit（NumAddDel 的 update:modelValue、EmptyState 的 action）
  ├─ 直接调用 store（CartItem 的 setCount / remove、GoodsInfoPanel 的 add）
  └─ 路由跳转（TabHeader、GoodsCard、CartItem）
```
