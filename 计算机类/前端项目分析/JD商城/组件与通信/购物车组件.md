# 购物车组件

> [!abstract] 一句话
> 购物车页由 ==`Cart` 容器 + `CartList` 表头/列表 + `CartItem` 单行 + `NumAddDel` 数量器 + `FooterFixed` 结算栏==组成。它最值得学习的是：**用同一个 CSS 变量 `--cart-columns` 让表头和数据行共用一套网格**，以及 **`NumAddDel` 用 `v-model` 把「子组件事件」转换成「父组件状态更新」**。

---

## 一、组件结构

```text
Cart（/cart）
├─ CartList :items="items"
│  ├─ 表头（商品信息 / 单价 / 数量 / 小计 / 操作）
│  ├─ items.length > 0
│  │  └─ TransitionGroup
│  │     └─ CartItem × N
│  │        └─ NumAddDel
│  └─ items.length === 0
│     └─ EmptyState（点击「去逛逛」→ /goods）
└─ FooterFixed（固定底部结算栏）
```

`Cart` 组件本身非常薄：

```vue
<template>
  <section class="cart-page">
    <CartList :items="items" />
    <FooterFixed />
  </section>
</template>

<script setup>
import { useCart } from '@/stores/cart'
import CartList from '@/components/cart-area/cart-list.vue'
import FooterFixed from '@/components/cart-area/footer-fixed.vue'

const { items } = useCart()
</script>
```

它只做两件事：从 store 取 `items`，传给 `CartList`；渲染固定结算栏。

## 二、表头与数据行的网格对齐

### 2.1 共享的列定义

`cart-list.vue` 在自己身上定义 CSS 变量：

```css
.cart-list {
  --cart-columns: 90px minmax(0, 1fr) 120px 140px 140px 60px;
}
```

六个列依次是：

| 列 | 宽度 | 含义 |
| --- | --- | --- |
| 1 | `90px` | 商品封面 |
| 2 | `minmax(0, 1fr)` | 商品标题与摘要 |
| 3 | `120px` | 单价 |
| 4 | `140px` | 数量 |
| 5 | `140px` | 小计 |
| 6 | `60px` | 操作（删除） |

### 2.2 表头

```css
.cart-header {
  display: grid;
  grid-template-columns: var(--cart-columns);
  gap: 20px;
  align-items: center;
  padding: 16px 20px;
  background: #f7f8fa;
}
```

「商品信息」跨前两列：

```css
.header-product { grid-column: 1 / 3; }
.header-price { grid-column: 3; text-align: center; }
.header-quantity { grid-column: 4; text-align: center; }
.header-subtotal { grid-column: 5; text-align: center; }
.header-action { grid-column: 6; text-align: center; }
```

### 2.3 数据行

```css
.cart-item {
  display: grid;
  grid-template-columns: var(--cart-columns);
  gap: 20px;
  align-items: center;
  padding: 18px 20px;
  border-top: 1px solid #f0f0f0;
}
```

`CartItem` 的根元素在 `CartList` 内部，因此能读取父元素上的 `--cart-columns`。这就是**表头与每一行严格对齐**的原因。

> [!tip] 这种写法的好处
> 如果以后要调整列宽，只改 `--cart-columns` 一处，表头和所有行同步变化。比在多个选择器里重复写 `grid-template-columns` 更易维护。

## 三、`CartList`

```vue
<section class="cart-list">
  <div class="cart-header">
    <span class="header-product">商品信息</span>
    <span class="header-price">单价</span>
    <span class="header-quantity">数量</span>
    <span class="header-subtotal">小计</span>
    <span class="header-action">操作</span>
  </div>

  <TransitionGroup v-if="items.length" name="list" tag="div">
    <CartItem v-for="item in items" :key="item.skuId" :item="item" />
  </TransitionGroup>

  <EmptyState v-else @action="goShopping" />
</section>
```

### 3.1 条件渲染

```text
items.length > 0 → TransitionGroup + CartItem
items.length === 0 → EmptyState
```

### 3.2 `TransitionGroup`

```vue
<TransitionGroup v-if="items.length" name="list" tag="div">
```

```css
.list-enter-active,
.list-leave-active { transition: opacity 0.2s ease, transform 0.2s ease; }
.list-enter-from,
.list-leave-to { opacity: 0; transform: translateX(20px); }
```

- 新增商品：从右侧淡入。
- 删除商品：向右侧淡出。

`TransitionGroup` 要求每个子项有稳定唯一 key，这里用 `item.skuId`，购物车中同一商品不会重复，因此是安全的。

### 3.3 空状态

```vue
<EmptyState v-else @action="goShopping" />
```

```js
function goShopping() {
  router.push('/goods')
}
```

`EmptyState` 的默认文案：

```js
title: '购物车还是空的'
description: '去挑选一些喜欢的商品吧'
actionText: '去逛逛'
```

## 四、`CartItem`

### 4.1 模板

```vue
<article class="cart-item">
  <img class="cart-cover" :src="item.cover" :alt="item.title" @click="goToDetail" />

  <div class="cart-product">
    <h2>{{ item.title }}</h2>
    <p>{{ item.shortInfo }}</p>
  </div>

  <span class="unit-price">¥{{ formatPrice(item.price) }}</span>

  <NumAddDel
    class="quantity-control"
    :model-value="item.count"
    @update:model-value="setCount"
  />

  <strong class="subtotal">¥{{ formatPrice(item.price * item.count) }}</strong>

  <button class="remove-button" type="button" @click="removeItem">删除</button>
</article>
```

### 4.2 列定位

```css
.unit-price  { grid-column: 3; text-align: center; }
.quantity-control { grid-column: 4; justify-self: center; }
.subtotal    { grid-column: 5; text-align: center; }
.remove-button { grid-column: 6; justify-self: center; }
```

封面和商品信息不显式指定 `grid-column`，按 DOM 顺序占据第 1、2 列。

### 4.3 修改数量

```js
const { remove, setCount: updateCount } = useCart()

function setCount(count) {
  updateCount(props.item.skuId, count)
}
```

```vue
<NumAddDel
  :model-value="item.count"
  @update:model-value="setCount"
/>
```

这里没有用 `v-model` 简写，而是显式写成 `:model-value` + `@update:model-value`。两者等价：

```vue
<NumAddDel v-model="item.count" />
```

但不能直接写 `v-model="item.count"`，因为 `item` 是 prop，直接修改会违反单向数据流。正确做法仍是监听事件后调用 store。

### 4.4 删除

```js
async function removeItem() {
  try {
    await ElMessageBox.confirm('确定删除该商品？', '提示', {
      type: 'warning',
    })
    remove(props.item.skuId)
  } catch {
    // 用户取消删除不需要提示
  }
}
```

流程：

```text
点击「删除」
  ↓
ElMessageBox.confirm 弹出确认框
  ↓ 用户点确定
remove(skuId)
  ↓
state.items.splice(index, 1)
  ↓
CartItem 消失（带 TransitionGroup 动画）
  ↓
totalCount / totalAmount 自动重算
  ↓
localStorage 自动更新
```

`try/catch` 同时捕获了「用户取消」和「确认框自身异常」。当前实现下只有取消会进入 `catch`，因此静默处理是合理的。

### 4.5 跳转详情

```js
function goToDetail() {
  router.push(`/goods/${props.item.skuId}`)
}
```

只有封面绑定了点击；标题没有绑定。可以给标题也加点击，或在整行加「查看详情」入口。

## 五、`NumAddDel` 与自定义 `v-model`

### 5.1 组件实现

```vue
<template>
  <div class="num-add-del" aria-label="商品数量">
    <button type="button" aria-label="减少数量" @click="decrease">−</button>
    <span>{{ modelValue }}</span>
    <button type="button" aria-label="增加数量" @click="increase">+</button>
  </div>
</template>

<script setup>
const props = defineProps({
  modelValue: { type: Number, required: true },
})

const emit = defineEmits(['update:modelValue'])

function decrease() {
  emit('update:modelValue', Math.max(props.modelValue - 1, 1))
}

function increase() {
  emit('update:modelValue', Math.min(props.modelValue + 1, 99))
}
</script>
```

### 5.2 `v-model` 的本质

父组件：

```vue
<NumAddDel :model-value="item.count" @update:model-value="setCount" />
```

`v-model` 是语法糖，等价于：

```vue
<NumAddDel
  :model-value="item.count"
  @update:model-value="item.count = $event"
/>
```

但在购物车里，`item` 是 prop，不能直接赋值，所以父组件把事件交给 store：

```text
用户点 +
  ↓
NumAddDel：emit('update:modelValue', count + 1)
  ↓
CartItem：setCount(newCount)
  ↓
CartItem：updateCount(item.skuId, newCount)
  ↓
store：item.count = Math.min(count, 99)
  ↓
响应式更新 → 数量、小计、合计、角标、localStorage 全部同步
```

### 5.3 边界规则

| 操作 | 规则 |
| --- | --- |
| 减少 | `Math.max(value - 1, 1)`，最小 1 |
| 增加 | `Math.min(value + 1, 99)`，最大 99 |
| store 的 `setCount` | `<= 0` 时删除商品；否则上限 99 |
| 加购 `add` | 合并同商品，上限 99 |

`NumAddDel` 本身不会减到 0，所以「数量减到 0 自动删除」的 store 分支在 UI 上不会触发，但作为 API 仍然有意义。

### 5.4 可访问性

- 两个按钮都有 `aria-label`（「减少数量」「增加数量」）。
- 容器有 `aria-label="商品数量"`。
- 数量值只是 `<span>`，没有 `aria-live`，屏幕阅读器不会主动播报变化。可加 `aria-live="polite"`。

## 六、固定结算栏 `FooterFixed`

```vue
<footer class="footer-fixed">
  <div class="footer-inner">
    <span class="count-text">共 {{ totalCount }} 件商品</span>
    <span class="amount">合计：¥{{ formatPrice(totalAmount) }}</span>
    <button type="button" :disabled="totalCount === 0" @click="checkout">
      去结算({{ totalCount }})
    </button>
  </div>
</footer>
```

```js
const { totalCount, totalAmount, clear } = useCart()

async function checkout() {
  try {
    await ElMessageBox.confirm(
      `共 ${totalCount.value} 件商品，合计 ¥${formatPrice(totalAmount.value)}，确认下单吗？`,
      '确认订单',
      { type: 'warning' },
    )
    clear()
    ElMessage.success('下单成功')
    router.push('/goods')
  } catch {
    // 用户取消结算不需要提示
  }
}
```

### 6.1 布局

```css
.footer-fixed {
  position: fixed;
  right: 0;
  bottom: 0;
  left: 0;
  z-index: 90;
  height: 72px;
  background: #fff;
  box-shadow: 0 -2px 8px rgba(0, 0, 0, 0.08);
}
```

- 固定在视口底部。
- `z-index: 90`，高于普通内容，低于 Element Plus 弹窗（通常 2000+）。
- 购物车页底部预留 `padding-bottom: 96px`，避免最后一行被结算栏遮住。

### 6.2 结算逻辑

```text
点击「去结算」
  ↓
ElMessageBox.confirm 显示件数与金额
  ↓ 用户确认
clear() 清空购物车
  ↓
ElMessage.success('下单成功')
  ↓
router.push('/goods')
```

这是**纯前端模拟**：

- 没有生成订单记录。
- 没有调用支付接口。
- 没有登录校验。
- 清空后无法恢复（除非 localStorage 里还有旧数据，但 `clear()` 会触发 watch 写入空数组）。

> [!note] 一个细节
> 确认框文案里的 `totalCount.value` 和 `totalAmount.value` 在**弹出前**求值。确认框打开期间购物车不会变化（模态遮罩），所以不存在金额过期问题。

### 6.3 禁用状态

```vue
:disabled="totalCount === 0"
```

```css
.footer-inner button:disabled {
  cursor: not-allowed;
  filter: grayscale(1);
}
```

空购物车时按钮变灰且不可点。不过此时 `CartList` 已经显示空状态，结算栏仍然存在（显示「共 0 件商品 / 合计 ¥0.00」）。

> [!tip] 可以更彻底
> 空购物车时可以直接隐藏 `FooterFixed`：
>
> ```vue
> <FooterFixed v-if="items.length" />
> ```
>
> 或者保留但只显示提示，视觉上更干净。

## 七、响应式布局

### 7.1 表头隐藏

```css
@media (max-width: 800px) {
  .cart-header { display: none; }
}
```

手机上没有足够横向空间，表头隐藏，商品行改为卡片式。

### 7.2 商品行重排

```css
@media (max-width: 800px) {
  .cart-item {
    grid-template-columns: 72px minmax(0, 1fr) auto;
    gap: 12px;
  }

  .cart-cover { width: 72px; height: 72px; }

  .unit-price,
  .quantity-control,
  .subtotal,
  .remove-button {
    grid-column: 2;
  }
}
```

移动端变成三列：

```text
[封面 72px] [商品信息 / 单价 / 数量 / 小计 / 删除] [auto]
```

后四个元素都放在第 2 列，但没有指定行号，Grid 会自动把它们依次放到后续行。实际效果是纵向堆叠：

```text
┌──────┬──────────────────────────┐
│ 封面 │ 标题                      │
│      │ 摘要                      │
│      │ ¥单价                     │
│      │ [− 2 +]                   │
│      │ ¥小计                     │
│      │ 删除                      │
└──────┴──────────────────────────┘
```

第三列（`auto`）基本留空，视觉上会显得右侧有未利用空间。

> [!warning] 移动端网格的潜在问题
> 四个元素都指定 `grid-column: 2`，但没有指定行号，Grid 会自动把它们放到后续行。由于 `grid-template-columns` 只有 3 列，第三列几乎不用。视觉上可行，但结构不够精确。更稳妥的是把商品信息单独包一层，在移动端用 flex 排列。

### 7.3 结算栏

```css
@media (max-width: 600px) {
  .footer-fixed { height: auto; }
  .footer-inner { flex-wrap: wrap; gap: 8px 16px; padding: 10px 12px; }
  .footer-inner button { width: 100%; }
}
```

手机上结算按钮独占一行，件数与金额在上方。

## 八、购物车的数据来源

```text
localStorage('jd_cart_v1')
  ↓ 模块加载时读取 + 校验
state.items
  ↓ useCart()
  ├─ Cart 页 → CartList :items
  ├─ CartItem → item prop
  ├─ FooterFixed → totalCount / totalAmount
  └─ CartDot → totalCount
```

注意：`Cart` 传给 `CartList` 的 `items` 是 `state.items` 的**同一个数组引用**。因此 `CartItem` 里调用 store 修改 `item.count` 后，`CartList` 的 `v-for` 会自动更新，不需要额外通知。

## 九、可以改进的点

| 问题 | 影响 | 建议 |
| --- | --- | --- |
| 空购物车仍显示结算栏 | 视觉冗余 | `v-if="items.length"` |
| 数量值无 `aria-live` | 屏幕阅读器不播报 | 加 `aria-live="polite"` |
| 商品标题不可点 | 只有封面能进详情 | 标题加点击/链接 |
| 结算为模拟 | 无订单与支付 | 接入订单接口 |
| 删除确认捕获所有异常 | 真实错误被吞 | 区分取消与失败 |
| 移动端网格不精确 | 依赖自动放置 | 重构为 flex |
| 金额浮点乘法 | 极端小数误差 | 用整数分计算 |
| 无全选/批量删除 | 功能缺失 | 按需增加 |

---

## 十、小结

购物车组件的核心是三点：

1. **布局**：一个 CSS 变量统一表头与数据行的网格。
2. **通信**：`NumAddDel` 用 `emit` 上报数量，`CartItem` 调 store 落库。
3. **状态**：所有显示（小计、合计、角标）都由同一份 `state.items` 派生，天然同步。
