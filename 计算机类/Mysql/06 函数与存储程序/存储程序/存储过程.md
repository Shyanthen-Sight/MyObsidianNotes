# 存储过程 —— 把一组 SQL 打包成可复用的程序

> [!abstract] 一句话
> 存储过程是**保存在数据库里、可以带参数、可以包含流程控制和事务的一段 SQL 程序**。记住五件事：**`DELIMITER` 只是客户端命令**、**`IN` 传入 `OUT` 传出 `INOUT` 双向**、**`DECLARE` 必须写在 `BEGIN...END` 开头**、**游标必须配 `NOT FOUND` 处理器**、**过程能做事务，函数不能**。

---

> [!example] 本篇示例数据
> 沿用 [[条件函数]] 里的 `emp` 表，方便对照。事务部分另建一张 `account` 表。

```sql
DROP TABLE IF EXISTS emp;
CREATE TABLE emp (
    id        INT AUTO_INCREMENT PRIMARY KEY,
    name      VARCHAR(20) NOT NULL,
    dept      VARCHAR(20),
    gender    CHAR(1),
    salary    DECIMAL(10,2),
    hire_date DATE,
    bonus     DECIMAL(10,2)
);

INSERT INTO emp (name, dept, gender, salary, hire_date, bonus) VALUES
('张伟', '研发部', 'M', 12000.00, '2018-03-11', 5000.00),
('李娜', '研发部', 'F',  9000.00, '2020-07-01',    NULL),
('王强', '研发部', 'M', 15000.00, '2019-05-20', 8000.00),
('赵敏', '销售部', 'F',  8000.00, '2021-09-15', 3000.00),
('陈晨', '销售部', 'M',  6500.00, '2022-02-08',    NULL),
('刘洋', '销售部', 'F',  7500.00, '2020-11-30', 3000.00),
('孙悦', '财务部', 'F',  7000.00, '2023-04-01',    NULL),
('周杰', '财务部', 'M',  9500.00, '2020-08-22', 4000.00);

DROP TABLE IF EXISTS account;

    id      INT PRIMARY KEY,
    balance DECIMAL(10,2) NOT NULL
);

INSERT INTO account VALUES (1, 1000.00), (2, 500.00);
```

## 一、存储过程是什么

一段**命名的、带参数的、经过语法检查后保存在数据库里的 SQL 程序**。它由三部分组成：

| 部分 | 内容 |
| --- | --- |
| 参数列表 | `IN` / `OUT` / `INOUT`，MySQL 不支持默认值和重载 |
| 程序体 | `BEGIN ... END`，里面可以写 SQL、变量、流程控制、游标、异常处理、事务 |
| 特征声明 | `DETERMINISTIC`、`SQL SECURITY`、`COMMENT` 等 |

它和前面几篇的"函数"不是一回事：

| 对比项 | 存储过程 | 存储函数 |
| --- | --- | --- |
| 关键字 | `CREATE PROCEDURE` | `CREATE FUNCTION` |
| 返回值 | 通过 `OUT` / `INOUT` 或结果集返回 | 必须有且仅有一个标量返回值 |
| 调用方式 | `CALL p(...)` | 直接写在表达式里 `SELECT f(...)` |
| 能不能出现在 `SELECT` / `WHERE` | 不能 | 能 |
| 返回结果集 | 可以（零到多个） | 不可以 |
| 事务控制 | 可以 `COMMIT` / `ROLLBACK` | 不可以 |
| 动态 SQL | 可以 `PREPARE` / `EXECUTE` | 不可以 |
| 递归 | 可配置 `max_sp_recursion_depth` | 不允许 |

> [!tip] 选型口诀
> **要"做一件事"用过程，要"算一个值"用函数。**
> 过程适合多步写入、批量维护、事务流程；函数适合行级单值转换。两者都不适合承载频繁变更的复杂业务逻辑。

### 1.1 什么时候值得用

- 多条 SQL 必须**原子地**完成（转账、扣库存 + 写流水）。
- 多个应用共用同一套**数据口径**，希望收敛在数据库里。
- 批量运维脚本、定时任务、数据修复。
- 用 `SQL SECURITY DEFINER` 做**统一的权限入口**，只暴露 `EXECUTE`。

### 1.2 什么时候不要用

- 业务逻辑频繁变化：改一次就要 `DROP` + `CREATE`，还难做代码评审。
- 需要单元测试、断点调试、链路追踪：存储过程的工具链远弱于应用代码。
- 需要跨数据库移植：各家语法差异很大。
- 重计算、复杂字符串处理：数据库 CPU 是共享资源，别把它当应用服务器。

## 二、第一个存储过程：`DELIMITER` 与基本语法

```sql
DELIMITER $$

CREATE PROCEDURE p_raise_salary(
    IN p_dept VARCHAR(20),
    IN p_pct  DECIMAL(5,2)
)
BEGIN
    UPDATE emp
       SET salary = salary * (1 + p_pct / 100)
     WHERE dept = p_dept;
END $$

DELIMITER ;

CALL p_raise_salary('研发部', 10);
```

### 2.1 `DELIMITER` 到底在干什么

`mysql` 命令行客户端默认把 **分号 `;`** 当作一条语句的结束符。可存储过程体里本来就有很多分号，客户端会在第一个分号处就把语句截断，于是报语法错误。

`DELIMITER $$` 只是**告诉客户端**："接下来请用 `$$` 作为结束符。" 它**不是 SQL 语句，不会发送给服务器**。

> [!danger] 忘记改回来，后面的语句全会"粘"在一起
> 创建完过程一定要执行 `DELIMITER ;` 恢复默认值。否则下一条普通 SQL 也会被当成过程体的一部分。

> [!warning] 不同客户端的处理方式不一样
> Navicat、DataGrip 等图形客户端通常有自己的分隔符设置；JDBC 根本不认识 `DELIMITER`，驱动会把整段 `CREATE PROCEDURE` 当成一条语句发送。写迁移脚本时不要假设所有环境都能直接跑 `DELIMITER`。

### 2.2 最简形式

过程体只有一条语句时，可以省略 `BEGIN...END`：

```sql
DELIMITER //
CREATE PROCEDURE p_count_emp()
SELECT COUNT(*) FROM emp //
DELIMITER ;

CALL p_count_emp();
```

### 2.3 查看与删除

```sql
-- 列出当前库的过程
SHOW PROCEDURE STATUS WHERE Db = DATABASE();

-- 查看创建语句（\G 是 mysql 客户端排版，不是 SQL）
SHOW CREATE PROCEDURE p_raise_salary\G

-- 从数据字典查
SELECT ROUTINE_NAME, ROUTINE_TYPE, CREATED, LAST_ALTERED
FROM information_schema.ROUTINES
WHERE ROUTINE_SCHEMA = DATABASE()
  AND ROUTINE_TYPE = 'PROCEDURE';

-- 删除
DROP PROCEDURE IF EXISTS p_raise_salary;
```

> [!warning] MySQL 没有 `CREATE OR REPLACE PROCEDURE`
> 这是 Oracle 的习惯。MySQL 要改过程体，只能 `DROP PROCEDURE` 再 `CREATE`。
> 注意：**删除过程会连同它的授权一起丢掉**，重建后要重新 `GRANT EXECUTE`。

## 三、参数：`IN` / `OUT` / `INOUT`

| 模式 | 数据方向 | 过程内初值 | 调用时能传什么 | 典型用途 |
| --- | --- | --- | --- | --- |
| `IN`（默认） | 调用者 → 过程 | 实参的值 | 常量、变量、表达式 | 查询条件、输入值 |
| `OUT` | 过程 → 调用者 | **`NULL`** | 只能是用户变量 `@x` | 返回计数、合计、状态 |
| `INOUT` | 双向 | 实参的值 | 只能是用户变量 `@x` | 累加器、就地修改 |

### 3.1 `OUT`：把结果带回来

```sql
DELIMITER //
CREATE PROCEDURE p_dept_stat(
    IN  p_dept  VARCHAR(20),
    OUT p_count INT,
    OUT p_avg   DECIMAL(10,2)
)
BEGIN
    SELECT COUNT(*), AVG(salary)
      INTO p_count, p_avg
      FROM emp
     WHERE dept = p_dept;
END //
DELIMITER ;

CALL p_dept_stat('研发部', @cnt, @avg);
SELECT @cnt AS 人数, @avg AS 平均工资;
```

```
+--------+--------------+
| 人数   | 平均工资     |
+--------+--------------+
|      3 |     12000.00 |
+--------+--------------+
```

> [!danger] `OUT` 参数不能传字面量
> `CALL p_dept_stat('研发部', 0, 0);` 会报
> `ERROR 1414 (42000): OUT or INOUT argument for routine ... is not a variable`。
> 必须传用户变量 `@cnt`、`@avg`。

> [!note] `OUT` 参数一进过程就是 `NULL`
> 即使调用者传进来的 `@cnt` 原来有值，过程开始时它也会被置成 `NULL`。
> 而 `INOUT` 会保留调用者的原值。

### 3.2 `INOUT`：带进去，再带出来

```sql
DELIMITER //
CREATE PROCEDURE p_double(INOUT x INT)
BEGIN
    SET x = x * 2;
END //
DELIMITER ;

SET @n = 5;
CALL p_double(@n);
SELECT @n;      -- 10
```

### 3.3 参数名的坑

```sql
-- 错误示范：参数名和列名同名
CREATE PROCEDURE p_bad(IN dept VARCHAR(20))
BEGIN
    SELECT COUNT(*) FROM emp WHERE dept = dept;   -- 恒真，等于没过滤
END;
```

MySQL 在名称冲突时**优先解析列名**，`dept = dept` 变成 `emp.dept = emp.dept`。所有参数统一加前缀：

```sql
CREATE PROCEDURE p_good(IN p_dept VARCHAR(20))
BEGIN
    SELECT COUNT(*) FROM emp WHERE dept = p_dept;
END;
```

> [!failure] MySQL 参数没有默认值，也不能重载
> 不支持 `IN p_x INT DEFAULT 0`，也不支持同名不同参数列表的两个过程。
> 需要"可选参数"时，通常传 `NULL` 并在过程里用 `IF p_x IS NULL THEN ...` 分支。

## 四、变量与赋值

存储程序里有三种"变量"，别混：

| 类型 | 写法 | 作用域 | 生命周期 |
| --- | --- | --- | --- |
| 局部变量 | `DECLARE v_x INT DEFAULT 0;` | 所在的 `BEGIN...END` 块 | 块执行期间 |
| 用户变量 | `@x` | 当前会话 | 连接断开为止 |
| 系统变量 | `@@global.x` / `@@session.x` | 全局 / 当前会话 | 按设置 |

### 4.1 `DECLARE` 与 `SET`

```sql
DELIMITER //
CREATE PROCEDURE p_dept_total(IN p_dept VARCHAR(20), OUT p_total DECIMAL(12,2))
BEGIN
    DECLARE v_count INT DEFAULT 0;
    DECLARE v_total DECIMAL(12,2) DEFAULT 0;

    SELECT COUNT(*), SUM(salary)
      INTO v_count, v_total
      FROM emp
     WHERE dept = p_dept;

    SET p_total = IFNULL(v_total, 0);
END //
DELIMITER ;
```

> [!warning] `DECLARE` 必须写在块的最前面
> 变量声明、条件声明、游标声明、异常处理器声明有严格的先后顺序：
> **变量/条件 → 游标 → 处理器**。
> 在 `SET` 之后再 `DECLARE`，直接报 `ERROR 1064` 语法错误。

### 4.2 `SELECT ... INTO`

```sql
SELECT COUNT(*), AVG(salary) INTO @cnt, @avg FROM emp WHERE dept = '研发部';
```

- 聚合查询永远返回一行，所以可以放心 `INTO`。
- 普通查询返回 **0 行**：不报错，变量保持原值，附一条 `warning 1329 No data`。
- 普通查询返回 **多行**：直接报 `ERROR 1172: Result consisted of more than one row`。

需要"没有就取默认"时，用 `SET v = (SELECT ...)`，无行时得到 `NULL`，再 `IFNULL` 兜底：

```sql
SET v_salary = IFNULL((SELECT salary FROM emp WHERE id = 999), 0);
```

### 4.3 用户变量的副作用

```sql
CALL p_dept_stat('研发部', @cnt, @avg);
SELECT @cnt;      -- 过程结束后还在
```

`@x` 属于会话，不随过程结束而消失。两个过程共用一个 `@x` 时容易互相污染。过程内部尽量用 `DECLARE` 局部变量，只把 `OUT` 参数留给调用者。

## 五、流程控制

### 5.1 `IF ... ELSEIF ... ELSE ... END IF`

```sql
DELIMITER //
CREATE PROCEDURE p_level(
    IN  p_salary DECIMAL(10,2),
    OUT p_level  VARCHAR(10)
)
BEGIN
    IF p_salary IS NULL THEN
        SET p_level = NULL;
    ELSEIF p_salary >= 12000 THEN
        SET p_level = '高';
    ELSEIF p_salary >= 8000 THEN
        SET p_level = '中';
    ELSE
        SET p_level = '低';
    END IF;
END //
DELIMITER ;
```

> [!note] 是 `ELSEIF`，不是 `ELSE IF`
> 存储程序里写成一个词 `ELSEIF`；`ELSE IF` 会被解析成嵌套的 `IF`，通常导致 `END IF` 数量对不上。

### 5.2 `CASE`

两种形式，和 [[条件函数]] 里的 `CASE` **表达式**语法相似，但结尾是 `END CASE`：

```sql
-- 简单 CASE：按等值分支
CASE p_dept
    WHEN '研发部' THEN SET p_bonus = 0.20;
    WHEN '销售部' THEN SET p_bonus = 0.30;
    ELSE SET p_bonus = 0.10;
END CASE;

-- 搜索 CASE：按条件分支
CASE
    WHEN p_salary >= 12000 THEN SET p_level = '高';
    WHEN p_salary >= 8000  THEN SET p_level = '中';
    ELSE SET p_level = '低';
END CASE;
```

> [!danger] 存储程序的 `CASE` 没有 `ELSE` 且没匹配上，会报错
> `ERROR 1339 (20000): Case not found for CASE statement`。
> 而 `CASE` **表达式**没匹配上只是返回 `NULL`。两者行为不同，别想当然。

### 5.3 三种循环

| 循环 | 语法 | 判断时机 | 可能一次都不执行 |
| --- | --- | --- | --- |
| `LOOP` | `LOOP ... END LOOP` | 无条件进入，靠 `LEAVE` 退出 | 可以（一开始就 `LEAVE`） |
| `WHILE` | `WHILE cond DO ... END WHILE` | 先判断，后执行 | 可以 |
| `REPEAT` | `REPEAT ... UNTIL cond END REPEAT` | 先执行，后判断 | **不可以**，至少执行一次 |

```sql
-- LOOP：必须自己 LEAVE
DECLARE i INT DEFAULT 1;
cnt_loop: LOOP
    IF i > 5 THEN
        LEAVE cnt_loop;
    END IF;
    SET i = i + 1;
END LOOP cnt_loop;

-- WHILE
WHILE i <= 5 DO
    SET i = i + 1;
END WHILE;

-- REPEAT
REPEAT
    SET i = i + 1;
UNTIL i > 5 END REPEAT;
```

- `LEAVE label` 相当于 `break`。
- `ITERATE label` 相当于 `continue`。
- 标签可以加在 `LOOP` / `WHILE` / `REPEAT` / `BEGIN` 前，格式是 `label: LOOP ... END LOOP label;`。

> [!failure] 死循环最常见的两种写法
> 循环体里**忘记 `SET i = i + 1`**，或者**忘记 `LEAVE`**。
> 真跑飞了只能 `KILL` 连接或等超时；在生产库上执行前，先在小数据量上验证循环边界。

## 六、游标

游标把结果集**一行一行**取出来处理。能用集合 SQL 解决就别用游标，它慢且啰嗦。

```sql
DELIMITER //
CREATE PROCEDURE p_list_emp()
BEGIN
    DECLARE v_done   BOOL DEFAULT FALSE;
    DECLARE v_name   VARCHAR(20);
    DECLARE v_salary DECIMAL(10,2);

    -- 1. 声明游标
    DECLARE cur CURSOR FOR
        SELECT name, salary FROM emp ORDER BY id;

    -- 2. 声明 NOT FOUND 处理器
    DECLARE CONTINUE HANDLER FOR NOT FOUND SET v_done = TRUE;

    OPEN cur;

    read_loop: LOOP
        FETCH cur INTO v_name, v_salary;

        IF v_done THEN
            LEAVE read_loop;
        END IF;

        SELECT CONCAT(v_name, ' -> ', v_salary) AS 明细;
    END LOOP read_loop;

    CLOSE cur;
END //
DELIMITER ;

CALL p_list_emp();
```

### 6.1 四步固定套路

1. `DECLARE cursor_name CURSOR FOR SELECT ...;`
2. `DECLARE CONTINUE HANDLER FOR NOT FOUND SET done = TRUE;`
3. `OPEN` → `FETCH` → 判断 `done` → 处理 → 回到 `FETCH`
4. `CLOSE`

> [!warning] 声明顺序不能乱
> 变量 → 游标 → 处理器。处理器必须写在游标之后，否则报错。

> [!danger] `FETCH` 之后要立刻判断 `done`
> `FETCH` 越界时，`NOT FOUND` 处理器把 `done` 置为 `TRUE`，但 **`INTO` 的变量内容不会变**（还是上一行的值）。
> 如果先处理再判断，最后一行业务数据会被**重复处理一次**。

### 6.2 为什么处理器要用 `CONTINUE`

如果把处理器写成 `EXIT`：

```sql
DECLARE EXIT HANDLER FOR NOT FOUND SET v_done = TRUE;
```

`FETCH` 到末尾时直接退出整个 `BEGIN...END` 块，`IF v_done` 和 `CLOSE` 都不会执行。用 `CONTINUE` 才能让控制权回到循环体里继续判断。

### 6.3 游标的限制

- MySQL 游标是**只读、不可滚动、敏感**的，不能 `UPDATE ... WHERE CURRENT OF`。
- 游标打开期间，别对同一张表做会改变结果集的写操作，否则行为依赖实现。
- 循环里 `SELECT` 会给客户端刷很多结果集；演示可以，生产环境应写入临时表或汇总变量。

```sql
-- 生产写法：先算好再一次性返回
DECLARE v_sum DECIMAL(12,2) DEFAULT 0;
...
SET v_sum = v_sum + v_salary;
...
SELECT v_sum AS 合计;
```

## 七、异常处理

### 7.1 三种处理器

| 处理器 | 行为 |
| --- | --- |
| `CONTINUE` | 执行完处理器语句，**继续**执行后面的语句 |
| `EXIT` | 执行完处理器语句，**退出**当前 `BEGIN...END` 块 |
| `UNDO` | MySQL 不支持，语法保留 |

### 7.2 能捕获什么

| 条件 | 含义 |
| --- | --- |
| `SQLEXCEPTION` | 所有"错误"（SQLSTATE 类不是 `00` / `01` / `02`） |
| `SQLWARNING` | 警告（SQLSTATE 类 `01`） |
| `NOT FOUND` | 没找到数据（SQLSTATE 类 `02`） |
| `1062` | 具体错误码：主键/唯一键冲突 |
| `SQLSTATE '23000'` | 按 SQLSTATE 捕获 |
| 自定义条件名 | `DECLARE duplicate_key CONDITION FOR SQLSTATE '23000';` |

### 7.3 记录错误并回滚

```sql
DELIMITER //
CREATE PROCEDURE p_safe_insert(IN p_id INT, IN p_name VARCHAR(20))
BEGIN
    DECLARE EXIT HANDLER FOR SQLEXCEPTION
    BEGIN
        GET DIAGNOSTICS CONDITION 1
            @sqlstate = RETURNED_SQLSTATE,
            @errno    = MYSQL_ERRNO,
            @msg      = MESSAGE_TEXT;
        ROLLBACK;
        SELECT @sqlstate AS sqlstate, @errno AS errno, @msg AS msg;
    END;

    START TRANSACTION;
    INSERT INTO emp (id, name) VALUES (p_id, p_name);
    COMMIT;
END //
DELIMITER ;
```

`GET DIAGNOSTICS CONDITION 1` 取的是**第一条**诊断信息。更完整的排查还可以取 `SCHEMA_NAME`、`TABLE_NAME`、`COLUMN_NAME`。

### 7.4 主动抛错：`SIGNAL`

```sql
IF p_amount <= 0 THEN
    SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = '金额必须大于 0';
END IF;
```

- `45000` 是"未处理的用户自定义异常"的惯用 SQLSTATE。
- `SIGNAL` 抛出的错误可以被调用者的处理器捕获，也可以直接返回给客户端。

### 7.5 处理完再抛：`RESIGNAL`

```sql
DECLARE EXIT HANDLER FOR SQLEXCEPTION
BEGIN
    ROLLBACK;
    RESIGNAL;
END;
```

`RESIGNAL` 把原错误原样抛给上层，保留错误码和消息。只 `ROLLBACK` 不 `RESIGNAL`，调用者会以为执行成功。

> [!failure] 空的 `CONTINUE HANDLER FOR SQLEXCEPTION` 最危险
> 写一个什么都不做的处理器，等于把所有错误吞掉：事务没回滚、数据写了一半，调用方还收到"成功"。
> 要么 `EXIT` + `ROLLBACK` + `RESIGNAL`，要么明确记录日志。

## 八、存储过程里的事务

存储过程可以写 `START TRANSACTION` / `COMMIT` / `ROLLBACK`，这是它和存储函数的重要区别。

```sql
DELIMITER //
CREATE PROCEDURE p_transfer(
    IN p_from   INT,
    IN p_to     INT,
    IN p_amount DECIMAL(10,2)
)
BEGIN
    DECLARE v_balance DECIMAL(10,2);

    DECLARE EXIT HANDLER FOR SQLEXCEPTION
    BEGIN
        ROLLBACK;
        RESIGNAL;
    END;

    START TRANSACTION;

    -- 锁住转出账户，防止并发超扣
    SELECT balance INTO v_balance
      FROM account
     WHERE id = p_from
       FOR UPDATE;

    IF v_balance < p_amount THEN
        SIGNAL SQLSTATE '45000'
            SET MESSAGE_TEXT = '余额不足';
    END IF;

    UPDATE account SET balance = balance - p_amount WHERE id = p_from;
    UPDATE account SET balance = balance + p_amount WHERE id = p_to;

    COMMIT;
END //
DELIMITER ;

CALL p_transfer(1, 2, 200.00);
```

### 8.1 三个必须知道的点

1. **`SELECT ... FOR UPDATE` 必须在事务里**，否则锁会立刻释放。
2. **`START TRANSACTION` 会隐式提交外层事务**。它没有"嵌套事务"的概念，别以为在应用层事务里再调过程就能一起回滚。
3. **DDL 会隐式提交**。过程里如果执行 `CREATE TABLE`、`ALTER TABLE`、`TRUNCATE` 等，之前的事务已经提交，`ROLLBACK` 救不回来。

> [!warning] 过程不是"事务的保险箱"
> 应用层已经开了事务，再调用一个内部 `START TRANSACTION` 的过程，外层事务会先被提交。
> 想要局部回滚，用 `SAVEPOINT` / `ROLLBACK TO SAVEPOINT`（见 [[SAVEPOINT]]），而不是在过程里再开一个事务。

### 8.2 锁与时长

过程里的事务越长，持有的行锁/间隙锁越久，越容易拖垮并发。批量更新要分批提交：

```sql
-- 每 1000 行提交一次，避免一个大事务
SET @batch = 0;
WHILE ... DO
    ...
    SET @batch = @batch + 1;
    IF @batch % 1000 = 0 THEN
        COMMIT;
    END IF;
END WHILE;
COMMIT;
```

## 九、权限与安全

### 9.1 需要哪些权限

| 权限 | 用途 |
| --- | --- |
| `CREATE ROUTINE` | 创建过程 / 函数 |
| `ALTER ROUTINE` | 修改特征、删除过程 |
| `EXECUTE` | 调用过程 |
| `SUPER` / `SET_USER_ID` | 指定其他用户作为 `DEFINER` 时可能需要 |

```sql
GRANT CREATE ROUTINE, ALTER ROUTINE ON demo.* TO 'dev'@'%';
GRANT EXECUTE ON PROCEDURE demo.p_transfer TO 'app'@'%';

-- 查看当前用户对过程的权限
SHOW GRANTS FOR CURRENT_USER();
```

### 9.2 `SQL SECURITY`

```sql
CREATE PROCEDURE p_x()
SQL SECURITY DEFINER      -- 默认：用创建者的权限执行
BEGIN
    ...
END;

CREATE PROCEDURE p_y()
SQL SECURITY INVOKER      -- 用调用者的权限执行
BEGIN
    ...
END;
```

| 模式 | 执行身份 | 调用者需要什么 |
| --- | --- | --- |
| `DEFINER`（默认） | 定义者 | 只需要 `EXECUTE` |
| `INVOKER` | 调用者 | 还需要过程内涉及的表权限 |

> [!danger] `DEFINER` 是一把双刃剑
> 它能做到"只给 `EXECUTE`，不给表权限"，但如果过程体里有动态 SQL 且拼接了用户输入，就等于给了调用者一个提权入口。
> `DEFINER` 账号被删除后，过程会报 `ERROR 1449: The user specified as a definer ... does not exist`。

### 9.3 动态 SQL 的注入面

```sql
-- 表名、列名不能用 ? 参数化，只能拼接
SET @sql = CONCAT('SELECT * FROM ', p_table);
PREPARE stmt FROM @sql;
EXECUTE stmt;
DEALLOCATE PREPARE stmt;
```

`PREPARE` 只允许在存储过程里用，存储函数和触发器里不允许。拼接标识符前必须做**白名单校验**，值用 `QUOTE()`：

```sql
SET @sql = CONCAT('SELECT * FROM ', p_table, ' WHERE name = ', QUOTE(p_name));
```

## 十、管理与查看

```sql
-- 状态
SHOW PROCEDURE STATUS WHERE Db = DATABASE();

-- 定义
SHOW CREATE PROCEDURE p_transfer\G

-- 数据字典
SELECT ROUTINE_NAME, ROUTINE_TYPE, DTD_IDENTIFIER,
       IS_DETERMINISTIC, SQL_DATA_ACCESS, SECURITY_TYPE
FROM information_schema.ROUTINES
WHERE ROUTINE_SCHEMA = DATABASE()
  AND ROUTINE_TYPE = 'PROCEDURE';

-- 只改特征，不改过程体
ALTER PROCEDURE p_transfer COMMENT '账户转账';

-- 删除
DROP PROCEDURE IF EXISTS p_transfer;
```

> [!note] `ALTER PROCEDURE` 改不了过程体
> 它只能改 `COMMENT`、`SQL SECURITY` 等特征。要改逻辑只能 `DROP` + `CREATE`，所以存储过程**必须纳入版本管理**（把 `CREATE` 脚本放进迁移目录），否则线上定义会逐渐和代码库脱节。

## 十一、常见错误合集

> [!failure] 坑一：忘记 `DELIMITER` 或忘记改回来
> 过程体在第一个 `;` 处被截断；或者改回来后忘了恢复，后面的 SQL 全被黏住。

> [!failure] 坑二：`OUT` / `INOUT` 传字面量
> `CALL p(1, 0)` 报 `1414`。必须传 `@var`。

> [!failure] 坑三：`DECLARE` 写在 `SET` 之后
> 直接 `1064`。声明必须集中在块首，顺序是变量/条件 → 游标 → 处理器。

> [!failure] 坑四：参数名与列名同名
> `WHERE dept = dept` 恒真，过滤条件形同虚设。参数统一加 `p_` 前缀。

> [!failure] 坑五：游标处理器写成 `EXIT`
> `FETCH` 到末尾直接退出过程，一行都没处理。用 `CONTINUE`。

> [!failure] 坑六：`FETCH` 后先处理再判断 `done`
> 最后一行被处理两次。`FETCH` 之后立刻 `IF done THEN LEAVE`。

> [!failure] 坑七：循环忘记自增或 `LEAVE`
> 死循环，只能 `KILL` 连接。

> [!failure] 坑八：以为过程事务可以嵌套
> 过程里的 `START TRANSACTION` 会隐式提交外层事务。局部回滚用 `SAVEPOINT`。

> [!failure] 坑九：过程里执行 DDL 后还想回滚
> DDL 隐式提交，`ROLLBACK` 无效。

> [!failure] 坑十：以为 MySQL 支持重载和默认参数
> 不支持。同名过程只能有一个参数列表；可选参数用 `NULL` 约定。

> [!failure] 坑十一：`DROP` + `CREATE` 后忘了重新授权
> 删除过程会丢掉该过程的 `EXECUTE` 授权。

> [!failure] 坑十二：在过程里 `SELECT` 刷大量结果集
> 应用端可能只取第一个结果集，后续结果集和连接状态都会出问题。过程对外输出尽量用 `OUT` 参数或一张结果表。

## 十二、速查表

| 需求 | 写法 |
| --- | --- |
| 创建过程 | `CREATE PROCEDURE p(IN a INT, OUT b INT) BEGIN ... END` |
| 修改分隔符 | `DELIMITER $$` … `DELIMITER ;` |
| 调用 | `CALL p(1, @out); SELECT @out;` |
| 输入参数 | `IN p_x INT` |
| 输出参数 | `OUT p_x INT`，调用必须传 `@var` |
| 双向参数 | `INOUT p_x INT`，调用必须传 `@var` |
| 局部变量 | `DECLARE v_x INT DEFAULT 0;` |
| 赋值 | `SET v_x = 1;` / `SELECT ... INTO v_x FROM ...;` |
| 条件 | `IF ... THEN ... ELSEIF ... ELSE ... END IF;` |
| 多分支 | `CASE ... WHEN ... THEN ... END CASE;` |
| 循环 | `LOOP` / `WHILE` / `REPEAT` |
| 跳出 / 继续 | `LEAVE label;` / `ITERATE label;` |
| 游标 | `DECLARE c CURSOR FOR SELECT ...; OPEN; FETCH; CLOSE;` |
| 游标结束 | `DECLARE CONTINUE HANDLER FOR NOT FOUND SET done = TRUE;` |
| 异常处理 | `DECLARE EXIT HANDLER FOR SQLEXCEPTION BEGIN ... END;` |
| 主动抛错 | `SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = '...';` |
| 重新抛出 | `RESIGNAL;` |
| 查看定义 | `SHOW CREATE PROCEDURE p\G` |
| 删除 | `DROP PROCEDURE IF EXISTS p;` |
| 授权调用 | `GRANT EXECUTE ON PROCEDURE db.p TO 'app'@'%';` |

> [!question] 自测三连
> 1. `DELIMITER` 是服务器端命令还是客户端命令？JDBC 里需要写吗？
> 2. `OUT` 参数在过程开始时是什么值？为什么 `CALL p(1, 0)` 会报错？
> 3. 过程里写了 `START TRANSACTION`，调用方原本已经开了一个事务，会发生什么？要怎么实现"局部回滚"？

---

> [!quote] 一句话记忆
> **`DELIMITER` 是客户端的分号替换**；**`IN` 进、`OUT` 出、`INOUT` 双向，`OUT/INOUT` 只能传 `@变量`**；**声明顺序：变量 → 游标 → 处理器**；**游标用 `CONTINUE ... NOT FOUND`，`FETCH` 后立刻判断**；**过程能事务、能结果集、能动态 SQL，函数都不能**；**过程里的 `START TRANSACTION` 不嵌套，DDL 会隐式提交**。
