# 第 7 讲：作用域链与词法环境（The Scope Chain, Scope & Lexical Environment）

> [!abstract] 本讲要点
> - JavaScript 中的作用域（Scope）与词法环境（Lexical Environment）直接相关。
> - 词法环境 = 当前执行上下文的本地内存 + 其父级的词法环境。
> - 逐层向父级查找变量的过程称为作用域链（Scope Chain），也叫词法环境链。
> - 内部函数可以访问外层函数中的变量，但外层无法访问内层的局部变量。

## 一、四个案例

- JavaScript 中的**作用域**（Scope）与**词法环境**（Lexical Environment）直接相关。

- 先观察下面几个例子：

```js
// 案例 1
function a() {
  console.log(b); // 10
  // 这里并没有打印 undefined，而是打印了 10，说明函数 a 以某种方式访问到了函数作用域之外的变量 b。
}
var b = 10;
a();
```

```js
// 案例 2
function a() {
  c();
  function c() {
    console.log(b); // 10
  }
}
var b = 10;
a();
```

```js
// 案例 3
function a() {
  c();
  function c() {
    var b = 100;
    console.log(b); // 100
  }
}
var b = 10;
a();
```

```js
// 案例 4
function a() {
  var b = 10;
  c();
  function c() {
    console.log(b); // 10
  }
}
a();
console.log(b); // 报错，Not Defined
```

- 我们逐个分析上面每个案例的输出。
  - **案例 1**：函数 a 能够从全局作用域访问变量 b。
  - **案例 2**：打印 10，说明即使是在嵌套函数内部，也可以访问全局作用域的变量。
  - **案例 3**：打印 100，意味着同名的局部变量优先于全局变量。
  - **案例 4**：函数可以访问全局变量，但全局执行上下文无法访问任何局部变量。

  ```text
  用执行上下文来总结上面的结论：
  call_stack = [GEC, a(), c()]
  现在再为 call_stack 中每个执行上下文分配内存区域。
  c() = [[指向 a() 的词法环境指针]]
  a() = [b:10, c:{}, [指向 GEC 的词法环境指针]]
  GEC = [a:{}, [指向 null 的词法环境指针]]
  ```

## 二、什么是词法环境

- 因此，**词法环境** = 本地内存 + 其父级的词法环境。也就是说，词法环境是本地内存连同其父级词法环境的总和。

- **Lexical**：层级上的、按顺序的。

- 每当创建一个执行上下文时，也会同时创建一个词法环境（Lexical Environment，LE），并在本地的执行上下文（内存空间）中引用它。

- 逐级向上到父级查找值的过程称为作用域链（Scope Chain）或词法环境链（Lexical Environment Chain）。

- ```js
  function a() {
    function c() {
      // 此处为逻辑代码
    }
    c(); // c 在词法上位于 a 内部
  } // a 在词法上位于全局执行上下文内部
  ```

## 三、词法作用域

- 词法作用域（Lexical Scope）或静态作用域（Static Scope）指的是：变量、函数和对象的可访问性取决于它们在源代码中的物理位置。

  ```js
  Global {
      Outer {
          Inner
      }
  }
  // Inner 被 Outer 的词法作用域包围
  ```

- **TLDR**：内部函数可以访问外层函数中的变量，即使内部函数嵌套得很深。除此之外，函数无法访问不在其作用域中的变量。
