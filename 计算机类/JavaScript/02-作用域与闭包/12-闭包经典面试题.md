# 第 12 讲：闭包经典面试题（Famous Interview Questions ft. Closures）

> [!abstract] 本讲要点
> - 闭包是函数与其外层环境的引用的组合体。
> - 闭包的形成与变量的声明顺序无关，也适用于 let、函数参数和多层嵌套。
> - 变量解析遵循作用域链，优先使用最近的同名变量。
> - 闭包可以实现数据隐藏，但滥用会因变量不被垃圾回收而导致内存问题。

> [!question] 本讲是经典闭包面试题合集，共 9 题，建议先自行作答再看解析。

### Q1：JavaScript 中的闭包是什么？

**答**：函数连同对其外层环境的引用一起构成闭包。换句话说，闭包是函数与其词法作用域的组合体。
例如：

```js
function outer() {
  var a = 10;
  function inner() {
    console.log(a);
  } // inner 与 outer 形成闭包
  return inner;
}
outer()(); // 10 // 这里第一个 `()` 会返回 inner 函数，再用第二个 `()` 调用 inner 函数
```

### Q2：下面的代码还会形成闭包吗？

```js
function outer() {
  function inner() {
    console.log(a);
  }
  var a = 10;
  return inner;
}
outer()(); // 10
```

**答**：会，因为 inner 函数与其外层环境形成闭包，所以声明顺序无关紧要。

### Q3：把 var 改成 let，会有区别吗？

```js
function outer() {
  let a = 10;
  function inner() {
    console.log(a);
  }
  return inner;
}
outer()(); // 10
```

**答**：行为仍然相同。

### Q4：inner 函数能访问 outer 函数的参数吗？

```js
function outer(str) {
  let a = 10;
  function inner() {
    console.log(a, str);
  }
  return inner;
}
outer("Hello There")(); // 10 "Hello There"
```

**答**：inner 函数现在会形成闭包，并且可以同时访问 a 和 str。

### Q5：下面的代码中，inner 会和 **outest** 形成闭包吗？

```js
function outest() {
  var c = 20;
  function outer(str) {
    let a = 10;
    function inner() {
      console.log(a, c, str);
    }
    return inner;
  }
  return outer;
}
outest()("Hello There")(); // 10 20 "Hello There"
```

**答**：会，inner 可以访问它所有的外层环境。

### Q6：下面代码的输出及解释？

```js
function outest() {
  var c = 20;
  function outer(str) {
    let a = 10;
    function inner() {
      console.log(a, c, str);
    }
    return inner;
  }
  return outer;
}
let a = 100;
outest()("Hello There")(); // 10 20 "Hello There"
```

**答**：输出仍然相同，inner 函数会引用 inner 中的 a，因此同名冲突在这里没有影响。如果它在 outer 函数内部找不到 a，就会继续向外层查找 a，从而打印 100。也就是说，它会沿作用域链解析变量；如果始终找不到 a，就会抛出 ReferenceError。

### Q7：闭包的优势？

- 模块设计模式
- 柯里化
- 记忆化
- 数据隐藏与封装
- setTimeout 等

### Q8：详细谈谈数据隐藏与封装？

```js
// 不使用闭包
var count = 0;
function increment(){
  count++;
}
// 在上面的代码中，任何人都可以访问并修改 count。

------------------------------------------------------------------

//（使用闭包）-> 把所有东西放进一个函数
function counter() {
  var count = 0;
  function increment(){
    count++;
  }
}
console.log(count); // 这里会报 ReferenceError，因为无法访问 count。现在我们实现了数据隐藏

------------------------------------------------------------------

//（用闭包实现递增函数）真正的函数
function counter() {
  var count = 0;
  return function increment(){
    count++;
    console.log(count);
  }
}
var counter1 = counter(); // counter 函数与 count 变量形成闭包。
counter1(); // 递增计数器

var counter2 = counter();
counter2(); // 这里的 counter2 是 counter 函数的全新副本，不会影响 counter1 的输出

*************************

// 上面的代码不够好，也不具备扩展性——比如你之后想实现递减计数器。
// 为解决这个问题，我们使用*构造函数*

// 加入递减计数器并重构代码：
function Counter() {
// 构造函数。良好的编码习惯是把构造函数首字母大写。
  var count = 0;
  this.incrementCounter = function() { // 匿名函数
    count++;
    console.log(count);
  }
   this.decrementCounter = function() {
    count--;
    console.log(count);
  }
}

var counter1 = new Counter();  // 用 new 关键字调用构造函数
counter1.incrementCounter();
counter1.incrementCounter();
counter1.decrementCounter();
// 返回 1 2 1
```

### Q9：闭包的缺点？

**答**：使用闭包会造成内存过度占用，因为被闭包捕获的变量在程序结束前不会被垃圾回收。因此，创建大量闭包时会累积更多内存，若不处理就可能造成内存泄漏。

**垃圾回收器**（Garbage Collector）：JS 引擎或浏览器中释放未使用内存的程序。在 C++ 或 Java 这类高级语言中，垃圾回收由程序员负责，而在 JS 引擎中是隐式完成的。

```js
function a() {
  var x = 0;
  return function b() {
    console.log(x);
  };
}

var y = a(); // y 是 b() 的副本
y();

// a() 调用结束后，其元素 x 按理应被垃圾回收。但函数 b 闭包引用了 var x，因此 x 的内存无法释放。如果形成更多闭包，就会成为问题。为解决这一点，v8、Chrome 等 JS 引擎有智能的垃圾回收机制。假设上面代码中还有 var x = 0, z = 10，当 console.log 执行时，x 会打印为 0，而 z 会被自动移除。
```
