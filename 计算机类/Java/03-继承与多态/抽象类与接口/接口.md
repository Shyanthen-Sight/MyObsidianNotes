# Java 接口

> 接口（`interface`）是一份==能力契约==：它规定“必须能做什么”，却不关心“由谁做、怎么做”。
> 与[[抽象类]]不同，接口不保存实例状态，因此一个类可以同时实现多个接口，把互不相关的行为组合到一起。

## 1. 为什么需要接口

继续使用薪资系统。假设现在要写一个“统一发工资”的方法：

```java
public static void payAll(Employee[] staff) {
    for (Employee e : staff) {
        System.out.println(e.getName() + "：" + e.calculateSalary());
    }
}
```

如果只依赖 `Employee`，会出现两个限制：

1. ==必须继承 `Employee`==：外部合作方、临时工、外包系统里的类，不一定适合继承公司的员工体系；
2. ==只能单继承==：一个类已经继承了别的父类，就没办法再挤进 `Employee` 体系。

但 `payAll` 真正关心的只有一件事：==这个对象能不能算出工资==。把这个能力单独抽出来，就是接口：

```java
interface Payable {
    double calculateSalary();
}
```

`Payable` 不关心对象是经理、小时工还是外包人员，只要求“能算工资”。任何类只要 `implements Payable`，就能被 `payAll` 处理。

## 2. 接口的定义

```java
interface Payable {
    double calculateSalary();     // 隐式 public abstract
    double TAX_RATE = 0.1;        // 隐式 public static final
}
```

上面的写法等价于把修饰符全部写出来：

```java
interface Payable {
    public abstract double calculateSalary();
    public static final double TAX_RATE = 0.1;
}
```

接口成员的隐式修饰符：

| 成员 | 隐式修饰符 | 说明 |
| --- | --- | --- |
| 抽象方法 | `public abstract` | 实现类必须实现 |
| 常量 | `public static final` | 必须初始化，不能修改 |
| `default` 方法 | `public` | Java 8+，必须有方法体 |
| `static` 方法 | `public` | Java 8+，必须有方法体 |
| `private` 方法 | `private` | Java 9+，只能接口内部调用 |

接口本身还有几条硬性规则：

1. ==不能实例化==：`new Payable()` 编译错误；
2. ==没有构造方法==：接口不负责初始化对象状态；
3. ==不能有实例字段==：所有字段都是 `public static final` 常量；
4. 顶层接口只能是 `public` 或包私有（不写修饰符）。

## 3. 实现接口

类通过 `implements` 实现接口：

```java
interface Payable {
    double calculateSalary();
}

interface Workable {
    void work();
}

class Manager implements Payable, Workable {
    private final String name;
    private final double baseSalary;
    private final double bonus;

    public Manager(String name, double baseSalary, double bonus) {
        this.name = name;
        this.baseSalary = baseSalary;
        this.bonus = bonus;
    }

    @Override
    public double calculateSalary() {
        return baseSalary + bonus;
    }

    @Override
    public void work() {
        System.out.println(name + " 在开会");
    }
}
```

实现接口时要注意：

| 规则 | 说明 |
| --- | --- |
| 一个类可以实现多个接口 | `implements Payable, Workable`，用逗号分隔 |
| 必须实现全部抽象方法 | 否则该类必须声明为 `abstract` |
| 实现方法必须是 `public` | 接口方法隐式 `public`，实现时不能降低可见性 |
| 建议写 `@Override` | 编译期检查方法签名是否写对 |
| 实现类可以额外定义方法 | 接口只规定下限，不限制上限 |

少实现一个方法：

```java
class Manager implements Payable, Workable {
    @Override
    public double calculateSalary() {
        return 7000;
    }
    // 没有实现 work()
}
// 编译错误：Manager 不是抽象的，并且未覆盖 Workable 中的抽象方法 work()
```

如果 `Manager` 声明为 `abstract class`，则可以暂时不实现，交给下一层具体子类。

## 4. 接口继承接口

接口之间也可以继承，而且==可以多继承==：

```java
interface Payable {
    double calculateSalary();
}

interface Workable {
    void work();
}

interface EmployeeAbility extends Payable, Workable {
    void rest();
}
```

`EmployeeAbility` 同时拥有 `calculateSalary()`、`work()`、`rest()` 三个抽象方法。任何实现 `EmployeeAbility` 的具体类，必须把三个方法全部实现。

接口继承的特点：

1. ==可以继承多个父接口==：`extends A, B, C`；
2. ==继承的是契约，不是实现==：抽象方法、常量、`default` 方法都会被子接口继承；
3. ==接口不能继承类==：`interface X extends SomeClass` 编译错误；
4. 如果多个父接口存在冲突的 `default` 方法，子接口必须显式解决，见 [[接口中的方法]]。

```java
interface A {
    default void hello() {
        System.out.println("A");
    }
}

interface B {
    default void hello() {
        System.out.println("B");
    }
}

interface C extends A, B {
    @Override
    default void hello() {
        A.super.hello();       // 必须显式选择，否则编译错误
    }
}
```

## 5. 接口引用与多态

接口和类一样，可以作为引用类型：

```java
Payable p = new Manager("张三", 5000, 2000);
System.out.println(p.calculateSalary());   // 7000.0
```

这段代码的规则与父类引用完全一致：

> **能调用哪些方法，看接口类型；**
> **实际执行哪个版本，看对象的运行时类型。**

```java
Payable p = new Manager("张三", 5000, 2000);

p.calculateSalary();          // ✅ Payable 中声明过
// p.work();                  // ❌ 编译错误：Payable 中没有 work()
// p.getName();               // ❌ 编译错误：接口只暴露自己声明的方法

Workable w = (Workable) p;    // ✅ 对象确实实现了 Workable
w.work();                     // 张三 在开会
```

如果对象没有实现目标接口，强制转型会在运行期抛出 `ClassCastException`：

```java
Payable p = new SalariedEmployee("王五", 5000);
Workable w = (Workable) p;    // ❌ 运行时：ClassCastException
```

### 5.1 接口回调

“把实现类对象交给只依赖接口的代码”，通常称为==接口回调==：

```java
public static void payAll(Payable[] payables) {
    for (Payable p : payables) {
        System.out.println("应发：" + p.calculateSalary());
    }
}

public static void startAll(Workable[] workers) {
    for (Workable w : workers) {
        w.work();
    }
}
```

```java
payAll(new Payable[] {
    new Manager("张三", 5000, 2000),
    new SalariedEmployee("王五", 5000),
    new HourlyEmployee("李四", 20, 100)
});

startAll(new Workable[] {
    new Manager("张三", 5000, 2000),
    new HourlyEmployee("李四", 20, 100)
});
```

`payAll` 和 `startAll` ==完全不认识具体类==，只依赖接口。新增类型时，只要实现对应接口，这两个方法一行都不用改。这就是[[面向抽象编程]]，也是[[开闭原则]]的直接体现。

### 5.2 接口引用指向实现类对象

```java
Payable p = new Manager("张三", 5000, 2000);
```

- `p` 的编译时类型是 `Payable`；
- `p` 的运行时类型是 `Manager`；
- 对象始终是 `Manager`，转型只改变引用的“视角”。

接口引用和父类引用的转型规则相同，详见 [[向上转型与向下转型]]。

## 6. 接口中的方法类型

接口里的方法不止“抽象方法”一种。Java 8 和 Java 9 先后加入了 `default`、`static`、`private` 方法：

| 方法类型 | 引入版本 | 是否有方法体 | 实现类是否必须实现 | 典型用途 |
| --- | --- | --- | --- | --- |
| 抽象方法 | 最初 | 否 | ✅ | 定义核心能力 |
| `default` 方法 | Java 8 | 是 | ❌ | 提供可选默认实现、向后兼容 |
| `static` 方法 | Java 8 | 是 | ❌ | 与接口相关的工具方法 |
| `private` 方法 | Java 9 | 是 | ❌ | 抽取接口内部的公共逻辑 |

```java
interface Payable {
    double calculateSalary();                     // 抽象方法

    default void printPayInfo() {                 // 默认方法
        System.out.println("应发：" + calculateSalary());
    }

    static double afterTax(double amount) {       // 静态方法
        return amount * (1 - TAX_RATE);
    }

    private String format(double amount) {        // 私有方法（Java 9+）
        return String.format("%.2f 元", amount);
    }

    double TAX_RATE = 0.1;
}
```

每种方法的继承规则、调用方式和冲突处理都不相同，完整内容见 [[接口中的方法]]。

## 7. 常见的接口形态

### 7.1 标记接口

没有任何方法的接口称为==标记接口==，用来给类打一个“标签”：

```java
public interface Serializable {
}

public interface Cloneable {
}
```

`implements Serializable` 并不要求类实现任何方法，它的作用是告诉 JVM / 框架：“这个类的对象允许被序列化 / 克隆”。现代代码中，注解（如 `@Deprecated`）常常可以替代标记接口，但 JDK 里仍保留着这类设计。

### 7.2 函数式接口

==只有一个抽象方法的接口==称为函数式接口，可以用 Lambda 表达式实现：

```java
@FunctionalInterface
interface Calculator {
    int calculate(int a, int b);
}
```

```java
Calculator add = (a, b) -> a + b;
Calculator multiply = (a, b) -> a * b;

System.out.println(add.calculate(3, 4));        // 7
System.out.println(multiply.calculate(3, 4));   // 12
```

`@FunctionalInterface` 是编译期检查：如果接口里出现第二个抽象方法，编译直接报错。`default` / `static` / `private` 方法不算抽象方法，不影响函数式接口的判定。

### 7.3 常量接口（反例）

```java
interface Constants {
    int MAX_SIZE = 100;
    String DEFAULT_NAME = "unknown";
}
```

只用来堆放常量的接口称为==常量接口==，属于反模式：

1. 常量会通过实现类“泄漏”到使用方；
2. 接口的语义被污染，不再是“能力契约”；
3. 现代 Java 更推荐用 `enum`、`final class` + 私有构造方法，或直接放在工具类中。

### 7.4 小而专的接口

一个接口只描述一种能力，比“大而全”的接口更灵活：

```java
interface Payable {
    double calculateSalary();
}

interface Workable {
    void work();
}

interface Reportable {
    String report();
}
```

一个类可以按需实现其中几个，调用方也只依赖自己需要的那一个。这就是==接口隔离原则==的基本思想。

## 8. 常见误区

1. **以为接口里只能有抽象方法**：Java 8 起可以有 `default`、`static` 方法，Java 9 起可以有 `private` 方法。
2. **以为接口可以实例化**：`new Payable()` 编译错误；`new Payable() { ... }` 创建的是匿名实现类对象。
3. **以为接口方法可以写成 `protected`**：接口方法隐式 `public`，`protected` 非法；`private` 仅在 Java 9+ 且必须有方法体。
4. **以为接口字段可以不初始化**：接口字段隐式 `public static final`，声明时必须赋值。
5. **以为实现类可以把接口方法写成包私有**：实现方法必须是 `public`，不能降低可见性。
6. **以为一个类只能实现一个接口**：可以 `implements A, B, C`。
7. **以为接口可以继承类**：接口只能继承接口，不能 `extends` 一个类。
8. **以为接口有构造方法**：接口没有构造方法，也不保存实例状态。
9. **以为接口不能有方法体**：这是 Java 8 之前的旧规则，`default` / `static` / `private` 方法都可以有方法体。
10. **以为接口里的常量可以被实现类修改**：常量是 `final`，重新赋值编译错误。

## 9. 小结

* 接口是==能力契约==：只规定“必须能做什么”，不规定“怎么做”；
* 接口方法隐式 `public abstract`，字段隐式 `public static final`；
* 接口不能实例化、没有构造方法、不能有实例字段；
* 一个类可以实现多个接口，接口之间也可以多继承；
* 接口引用可以指向实现类对象，配合[[动态绑定]]实现多态；
* 接口把调用方与具体实现解耦，是[[面向抽象编程]]和[[开闭原则]]的核心工具；
* Java 8/9 之后接口有了 `default`、`static`、`private` 方法，语法能力增强，但==仍然不携带实例状态==。
