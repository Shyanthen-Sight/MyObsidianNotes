# Java 接口中的方法

> 接口的方法经历了三次扩展：==Java 8 之前只有抽象方法；Java 8 加入 `default` 与 `static`；Java 9 又加入 `private`==。
> 这四种方法的调用方式、继承规则和适用场景各不相同，混淆它们是接口相关题目中最常见的失分点。

## 1. 抽象方法：接口的核心契约

接口中最基础的方法是抽象方法：

```java
interface Payable {
    double calculateSalary();      // 隐式 public abstract
}
```

它等价于：

```java
interface Payable {
    public abstract double calculateSalary();
}
```

规则：

| 规则 | 说明 |
| --- | --- |
| 没有方法体 | 以分号结束，写 `{ }` 直接编译错误 |
| 隐式 `public` | 不能写成 `protected`；Java 9 起可以写 `private`，但必须有方法体 |
| 实现类必须实现 | 除非实现类是抽象类 |
| 不能用 `static` | `static` 方法必须有方法体，两者互斥 |
| 不能用 `final` | 接口方法本身就不允许 `final` |
| 不能用 `default` | 那是另一种方法类型 |

```java
class Manager implements Payable {
    @Override
    public double calculateSalary() {
        return 7000;
    }
}
```

> [!note] 接口方法为什么默认是 `public`
> 接口的作用是“对外承诺能力”。如果方法默认包私有，其他包里的调用方就无法通过接口调用它，契约就失去了意义。

## 2. 默认方法 `default`（Java 8）

### 2.1 解决什么问题

假设 `Payable` 已经发布，被很多类实现。现在想给它增加一个“打印工资信息”的方法：

```java
interface Payable {
    double calculateSalary();
    void printPayInfo();           // 新增抽象方法
}
```

这样做的后果是：==所有已有实现类都会编译失败==，因为它们没有实现 `printPayInfo()`。在维护公共 API 时，这种破坏性变更代价极高。

`default` 方法提供了另一种选择：==在接口里给出默认实现，实现类不强制重写==。

```java
interface Payable {
    double calculateSalary();

    default void printPayInfo() {
        System.out.println("应发：" + calculateSalary());
    }
}
```

已有实现类不改一行代码，也能直接调用 `printPayInfo()`：

```java
class Manager implements Payable {
    @Override
    public double calculateSalary() {
        return 7000;
    }
}

Payable p = new Manager();
p.printPayInfo();                  // 应发：7000.0
```

### 2.2 默认方法的规则

| 规则 | 说明 |
| --- | --- |
| 必须有方法体 | `default void f();` 编译错误 |
| 隐式 `public` | 可以显式写 `public`，但不能写 `protected` / `private` |
| 可以被实现类继承 | 实现类不重写时，直接使用接口提供的版本 |
| 可以被实现类重写 | 用 `@Override` 覆盖默认实现 |
| 可以调用接口中的其他方法 | 包括抽象方法、`static` 方法、`private` 方法 |
| 不能访问实现类的实例字段 | 接口没有实例字段，只能访问常量 |
| 不能是 `static` / `abstract` / `final` | `default` 与这三者互斥 |

```java
class Manager implements Payable {
    @Override
    public double calculateSalary() {
        return 7000;
    }

    @Override
    public void printPayInfo() {              // 选择重写默认实现
        System.out.println("经理应发：" + calculateSalary());
    }
}
```

### 2.3 菱形冲突：两个接口有同名默认方法

一个类实现两个接口，而两个接口都提供了同签名的 `default` 方法：

```java
interface A {
    default void hello() {
        System.out.println("A");
    }
}

interface B {
    default void hello() {
        System.out.println("B");
    }
}

class C implements A, B {
}
// ❌ 编译错误：类 C 从 A 和 B 继承了 hello() 的冲突默认实现
```

编译器不会“随便选一个”，必须由程序员显式解决。两种写法：

```java
class C implements A, B {
    @Override
    public void hello() {
        A.super.hello();       // 显式选择 A 的默认实现
        B.super.hello();       // 也可以两个都调用
    }
}
```

或者完全自己实现：

```java
class C implements A, B {
    @Override
    public void hello() {
        System.out.println("C");
    }
}
```

### 2.4 三条冲突解决规则

当多个默认方法或类方法同名时，Java 按以下优先级处理：

| 优先级 | 规则 | 示例 |
| --- | --- | --- |
| 1 | ==类中的方法优先== | 父类有 `hello()`，接口有 `default hello()`，使用父类的 |
| 2 | ==子接口优先于父接口== | `B extends A` 且都定义 `hello()`，使用 `B` 的 |
| 3 | ==仍然冲突则必须显式选择== | 两个无关接口同名，必须 `A.super.hello()` |

“类优先”示例：

```java
class Base {
    public void hello() {
        System.out.println("Base");
    }
}

interface A {
    default void hello() {
        System.out.println("A");
    }
}

class C extends Base implements A {
    // 不重写 hello()，实际使用的是 Base.hello()
}

new C().hello();          // Base
```

“子接口优先”示例：

```java
interface A {
    default void hello() {
        System.out.println("A");
    }
}

interface B extends A {
    @Override
    default void hello() {
        System.out.println("B");
    }
}

class C implements B {
    // B 比 A 更具体，使用 B 的默认实现
}

new C().hello();          // B
```

> [!warning] `InterfaceName.super.method()` 的使用限制
> 只能在==直接实现该接口的类==中使用。如果 `C implements B`，而 `B extends A`，在 `C` 里写 `A.super.hello()` 是非法的，因为 `A` 不是 `C` 的直接父接口。

### 2.5 默认方法不能覆盖 `Object` 的方法

接口不能为 `equals`、`hashCode`、`toString` 提供默认实现：

```java
interface Bad {
    default String toString() {       // ❌ 编译错误
        return "bad";
    }
}
```

原因：这些方法来自 `Object`，而接口并不继承 `Object`。如果允许接口提供默认实现，会与类继承体系中的 `Object` 方法产生无法调和的冲突。接口可以==声明==这些方法（作为抽象方法），但不能给默认实现。

### 2.6 默认方法不等于“接口有状态”

`default` 方法只是把一段行为放进接口，==接口仍然没有实例字段==：

```java
interface Counter {
    // int count = 0;          // ❌ 这是常量，而且必须初始化
    default void increment() {
        // count++;             // ❌ 接口没有实例字段可修改
    }
}
```

因此，默认方法适合放“基于其他方法组合出来的通用行为”，不适合保存每个对象各自的状态。

## 3. 静态方法 `static`（Java 8）

接口可以定义静态方法，作为与接口概念相关的工具方法：

```java
interface Payable {
    double TAX_RATE = 0.1;

    double calculateSalary();

    static double afterTax(double amount) {
        return amount * (1 - TAX_RATE);
    }
}
```

调用时必须通过==接口名==：

```java
double net = Payable.afterTax(7000);   // ✅
System.out.println(net);              // 6300.0
```

规则：

| 规则 | 说明 |
| --- | --- |
| 必须有方法体 | `static void f();` 编译错误 |
| 属于接口本身 | 不属于实现类，也不属于子接口 |
| 不会被继承 | 实现类和子接口都不能“继承”这个静态方法 |
| 不能被重写 | 静态方法不参与多态 |
| 只能通过接口名调用 | `Manager.afterTax(...)`、`manager.afterTax(...)` 都编译错误 |

实现类不能继承接口的静态方法：

```java
class Manager implements Payable {
    @Override
    public double calculateSalary() {
        return 7000;
    }
}

// Manager.afterTax(7000);      // ❌ 编译错误：Manager 中没有 afterTax
Payable.afterTax(7000);         // ✅
```

如果实现类自己定义了一个同名静态方法，那只是==另一个方法==，不是重写：

```java
class Manager implements Payable {
    public static double afterTax(double amount) {
        return amount * 0.8;         // 与 Payable.afterTax 无关
    }
}

Manager.afterTax(7000);          // 调用 Manager 自己的版本
Payable.afterTax(7000);          // 调用接口的版本
```

> [!tip] 静态方法为什么不能被继承
> 静态方法在编译期就按“类名 / 接口名”绑定，不存在运行期按对象类型分派的过程。如果允许继承，`Manager.afterTax()` 到底指哪一个版本会产生歧义，因此 Java 直接规定不继承。

## 4. 私有方法 `private`（Java 9）

### 4.1 解决什么问题

假设多个 `default` 方法需要共用一段格式化逻辑。Java 9 之前只有两种选择：

1. 把公共逻辑复制到每个 `default` 方法里；
2. 在接口里定义一个 `public` 的辅助方法，但这样会把内部实现暴露给所有实现类。

Java 9 加入 `private` 方法，专门用于==接口内部的代码复用==：

```java
interface Payable {
    double calculateSalary();

    default void printPayInfo() {
        System.out.println(formatAmount(calculateSalary()));
    }

    default void printNetPay() {
        System.out.println(formatAmount(Payable.afterTax(calculateSalary())));
    }

    static double afterTax(double amount) {
        return amount * 0.9;
    }

    private String formatAmount(double amount) {      // 实例私有方法
        return String.format("金额：%.2f 元", amount);
    }
}
```

`formatAmount()` 只能在 `Payable` 内部被 `default` 方法调用，实现类既看不到也调不到：

```java
class Manager implements Payable {
    @Override
    public double calculateSalary() {
        return 7000;
    }
}

Manager m = new Manager();
m.printPayInfo();                    // ✅ 间接使用私有方法
// m.formatAmount(7000);             // ❌ 编译错误：方法不可见
```

### 4.2 私有方法的规则

| 规则 | 说明 |
| --- | --- |
| 必须有方法体 | 私有方法不能是抽象的 |
| 不能被实现类继承 | `private` 方法不属于契约的一部分 |
| 不能被实现类调用 | 对接口外部完全不可见 |
| 可以是实例方法 | 供 `default` 方法或其他实例私有方法调用 |
| 可以是 `private static` | 供 `static` 方法、`default` 方法调用 |
| 不能被 `default` / `abstract` 修饰 | 修饰符互斥 |

实例私有方法与静态私有方法的调用范围：

```java
interface Demo {
    default void a() {
        b();              // ✅ 实例私有方法
        c();              // ✅ 静态私有方法
    }

    static void d() {
        // b();           // ❌ 静态上下文不能调用实例方法
        c();              // ✅ 静态私有方法
    }

    private void b() {
    }

    private static void c() {
    }
}
```

> [!note] 私有方法不会扩大接口的 API
> 它只是把 `default` / `static` 方法里的重复代码抽出来，接口对外的契约没有任何变化。这是 Java 9 为接口“补上的一块拼图”。

## 5. 四种方法对比

| 方法类型 | 引入版本 | 方法体 | 实现类必须实现 | 能否被实现类继承 | 调用方式 | 典型用途 |
| --- | --- | --- | --- | --- | --- | --- |
| 抽象方法 | 最初 | ❌ | ✅ | ✅（作为契约） | 实现类对象调用 | 定义核心能力 |
| `default` 方法 | Java 8 | ✅ | ❌ | ✅（可重写） | 实现类对象调用 | 默认实现、向后兼容 |
| `static` 方法 | Java 8 | ✅ | ❌ | ❌ | `接口名.方法()` | 接口相关工具方法 |
| `private` 方法 | Java 9 | ✅ | ❌ | ❌ | 接口内部调用 | 抽取公共逻辑 |

修饰符组合速查：

| 组合 | 是否允许 | 原因 |
| --- | --- | --- |
| `default abstract` | ❌ | 一个有方法体，一个没有 |
| `default static` | ❌ | `default` 是实例方法，`static` 属于接口 |
| `default final` | ❌ | 接口方法不允许 `final` |
| `static abstract` | ❌ | 静态方法必须有实现 |
| `static final` | ❌ | 接口方法不允许 `final` |
| `private abstract` | ❌ | 私有方法必须有实现 |
| `private static` | ✅ | 接口内部的静态工具方法 |
| `private default` | ❌ | `private` 与 `default` 互斥 |

## 6. 常见误区

1. **以为 `default` 方法可以覆盖 `Object` 的方法**：`equals`、`hashCode`、`toString` 不能有接口默认实现，编译错误。
2. **以为实现类会继承接口的 `static` 方法**：不会，必须通过接口名调用。
3. **以为两个 `default` 冲突时编译器会自动选一个**：不会，必须显式重写或用 `A.super.method()` 选择。
4. **以为可以通过实现类名调用接口静态方法**：`Manager.afterTax(...)` 编译错误，除非 `Manager` 自己定义了同名方法。
5. **以为 `default` 方法能访问实现类字段**：接口没有实例字段，默认方法只能调用接口中的其他方法或常量。
6. **以为实现类可以调用接口的 `private` 方法**：私有方法对接口外部不可见。
7. **以为 `default` 方法等同于抽象类的方法**：接口仍然没有实例状态和构造方法，`default` 只是行为上的默认实现。
8. **以为 `A.super.hello()` 在任何地方都能用**：只能在直接实现 `A` 的类中使用，且 `A` 必须是直接父接口。
9. **以为 `default` 方法可以声明为 `final`**：接口方法一律不允许 `final`。
10. **以为接口可以定义构造方法**：接口没有构造方法，也不能实例化。

## 7. 设计建议

| 方法类型 | 建议 |
| --- | --- |
| 抽象方法 | 只放==必须由实现类决定==的核心行为，保持接口小而专 |
| `default` 方法 | 用于==可选的默认行为==或给已发布接口追加方法；不要在接口里堆积业务逻辑 |
| `static` 方法 | 放与接口概念紧密相关的工具方法，如校验、转换、工厂 |
| `private` 方法 | 只在 `default` / `static` 方法之间复用代码，不要试图把它当成员方法用 |

> [!tip] 判断标准
> 如果一段逻辑需要访问对象状态，它就应该放在实现类或抽象类里；接口没有实例字段，`default` 方法只能组合已有方法。接口的边界应该是“行为契约”，而不是“代码仓库”。

## 8. 小结

* 抽象方法是接口的核心，隐式 `public abstract`，实现类必须实现；
* `default` 方法（Java 8）提供可选默认实现，可被继承和重写，冲突时按“类优先 → 子接口优先 → 显式选择”处理；
* `static` 方法（Java 8）属于接口本身，不被继承，必须通过接口名调用；
* `private` 方法（Java 9）用于接口内部复用，对实现类完全不可见；
* 四种方法都不能让接口拥有实例状态，接口仍然不能 `new`、没有构造方法；
* 选择哪种方法，取决于它是“必须实现”“可选实现”“工具方法”还是“内部复用”。
