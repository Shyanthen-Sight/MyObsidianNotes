# Java 抽象类

> 抽象类（`abstract class`）是“未完成的类”：==它可以把一组子类共有的字段和实现先写好，再把必须由子类决定的行为留成抽象方法==。
> 本文继续沿用[[什么是多态|多态]]里的薪资系统：`Employee` 不知道每类人怎么算工资，却能在编译期强制每个具体员工类给出自己的算法。

## 1. 普通父类解决不了的问题

先看一个“看起来能用”的设计：

```java
class Employee {
    protected String name;

    public double calculateSalary() {
        return 0;          // 占位实现
    }
}
```

`Manager`、`HourlyEmployee` 如果没有重写 `calculateSalary()`，编译器不会报错，程序却会打印出 `0.0`。这类错误有三个特点：

1. ==错误发现得晚==：编译期完全正常，运行到发工资才暴露；
2. ==默认值没有业务含义==：`0` 既不是经理的工资，也不是小时工的工资；
3. ==约束只停留在口头上==：“子类记得重写”无法被编译器检查。

把方法声明成“只有名字、没有实现”，问题就交给编译器：

```java
abstract class Employee {
    public abstract double calculateSalary();
}
```

这就是抽象方法：==它只规定“必须有一个这样的方法”，不提供任何实现==。

## 2. 抽象类与抽象方法的语法

- `abstract` 修饰类 → ==抽象类==；
- `abstract` 修饰方法 → ==抽象方法==；
- 抽象方法没有方法体，以分号结束。

```java
abstract class Employee {
    protected final String name;
    protected final double baseSalary;

    protected Employee(String name, double baseSalary) {
        this.name = name;
        this.baseSalary = baseSalary;
    }

    public String getName() {
        return name;
    }

    public double getBaseSalary() {
        return baseSalary;
    }

    public abstract double calculateSalary();   // 只有声明
}
```

三条基本规则：

| 规则            | 说明                                    |
| ------------- | ------------------------------------- |
| 有抽象方法的类必须是抽象类 | 否则编译错误：包含抽象方法的类必须声明为 `abstract`       |
| 抽象类不一定要有抽象方法  | 可以只是“不允许实例化”的基类                       |
| 抽象方法不能有方法体    | `public abstract void f() { }` 直接编译错误 |

> [!tip] 抽象类与普通类的唯一本质差别
> 抽象类只是多了一条“可以声明没有实现的方法”，并因此==不能被实例化==。字段、构造方法、普通方法、静态方法、`final` 方法它全都有。

## 3. 抽象类能做什么、不能做什么

### 3.1 可以拥有的成员

| 成员          | 是否允许 | 说明                             |
| ----------- | ---- | ------------------------------ |
| 实例字段        | ✅    | 和普通类一样，可以保存每个对象的状态             |
| 静态字段        | ✅    | 属于类                            |
| 构造方法        | ✅    | 供子类 `super(...)` 调用，不能直接 `new` |
| 普通方法        | ✅    | 可以包含完整实现，供子类复用                 |
| 抽象方法        | ✅    | 只声明，留给具体子类实现                   |
| `static` 方法 | ✅    | 通过类名调用                         |
| `final` 方法  | ✅    | 禁止子类重写，常用于模板方法                 |
| 内部类         | ✅    | 与普通类相同                         |

### 3.2 不能做的事

| 写法                              | 结果  | 原因                            |
| ------------------------------- | --- | ----------------------------- |
| `new Employee("张三", 5000)`      | ❌   | 抽象类不能实例化                      |
| `abstract final class Employee` | ❌   | `final` 禁止继承，`abstract` 要求被继承 |
| `private abstract void f();`    | ❌   | `private` 对子类不可见，无法重写         |
| `static abstract void f();`     | ❌   | `static` 属于类，抽象方法要求实例实现       |
| `final abstract void f();`      | ❌   | `final` 禁止重写                  |
| `public abstract void f() { }`  | ❌   | 抽象方法不能有方法体                    |

`native`、`synchronized` 也不能与 `abstract` 组合，原因类似：它们都要求方法有实际实现或与实例调用绑定。

> [!warning] `abstract` 与 `final` 语义相反
> `final` 类不能被继承，`abstract` 类只能被继承；`final` 方法不能被重写，`abstract` 方法必须被重写。两者同时出现一定是设计错误。

## 4. 子类必须实现抽象方法

具体子类必须给出所有抽象方法的实现：

```java
class Manager extends Employee {
    private final double bonus;

    public Manager(String name, double baseSalary, double bonus) {
        super(name, baseSalary);
        this.bonus = bonus;
    }

    @Override
    public double calculateSalary() {
        return baseSalary + bonus;
    }
}
```

少写一个抽象方法，编译直接失败：

```java
class Manager extends Employee {
    // 没有实现 calculateSalary()
}
// 编译错误：Manager 不是抽象的，并且未覆盖 Employee 中的抽象方法 calculateSalary()
```

如果子类自己也是抽象类，可以继续把实现往下传：

```java
abstract class AbstractManager extends Employee {
    // 可以不实现 calculateSalary()，交给 AbstractManager 的具体子类
}
```

| 子类类型 | 是否必须实现全部抽象方法 |
| --- | --- |
| 具体类（`class`） | ✅ 必须 |
| 抽象类（`abstract class`） | ❌ 可以继续保留为抽象 |
| 匿名子类（`new Employee(...) { ... }`） | ✅ 必须 |

## 5. 抽象类的构造方法

抽象类不能 `new`，但它==可以有构造方法==，作用是初始化父类字段、校验公共参数，供子类通过 `super(...)` 调用。

```java
abstract class Employee {
    protected final String name;
    protected final double baseSalary;

    protected Employee(String name, double baseSalary) {
        if (name == null || name.trim().isEmpty()) {
            throw new IllegalArgumentException("姓名不能为空");
        }
        if (baseSalary < 0) {
            throw new IllegalArgumentException("基本工资不能为负数");
        }
        this.name = name;
        this.baseSalary = baseSalary;
    }
}
```

创建子类对象时的执行顺序：

```text
Manager 构造方法 → super(...) → Employee 构造方法 → 回到 Manager，初始化自身字段 → 执行 Manager 构造方法体
```

```java
class Manager extends Employee {
    private final double bonus = 2000;   // 字段初始化在 super() 之后

    public Manager(String name, double baseSalary, double bonus) {
        super(name, baseSalary);         // ① 父类构造方法
        this.bonus = bonus;              // ② 当前类字段初始化 + 构造方法体
    }
}
```

> [!warning] 不要在抽象类构造方法中调用可被重写的方法
> 父类构造方法执行时，子类字段还没有初始化。此时若调用被子类重写的方法，会读到 `0` / `null` / `false`。完整分析见 [[父类的构造方法与子类的关系]] 和 [[动态绑定]]。

## 6. 抽象类与多态

抽象类最常见的用法，就是作为多态的“父类型”：

```java
Employee[] staff = {
    new SalariedEmployee("王五", 5000),
    new Manager("张三", 5000, 2000),
    new HourlyEmployee("李四", 20, 100)
};

for (Employee e : staff) {
    System.out.println(e.getName() + "：" + e.calculateSalary());
}
```

输出：

```text
王五：5000.0
张三：7000.0
李四：2000.0
```

这段代码体现了多态的两条规则：

> **能调用哪些成员，看编译时类型；**
> **被重写的方法执行哪一个版本，看运行时类型。**

`e` 的编译时类型是 `Employee`，所以只能调用 `Employee` 上声明过的成员；实际执行的是 `Manager`、`HourlyEmployee` 各自重写的 `calculateSalary()`。详见 [[什么是多态]] 和 [[向上转型与向下转型]]。

注意：抽象类引用不能调用子类特有方法：

```java
Employee e = new Manager("张三", 5000, 2000);
// e.getBonus();                     // ❌ 编译错误：Employee 上没有 getBonus()
System.out.println(((Manager) e).getBonus());   // ✅ 需要向下转型
```

> [!note] 抽象类不是多态的必要条件
> 把 `Employee` 改成普通类，给 `calculateSalary()` 一个默认实现，`Employee e = new Manager(...)` 仍然是多态。抽象类的价值在于==把“子类必须实现什么”从口头约定升级为编译期契约==。

## 7. 模板方法：抽象类最典型的用法

抽象类最擅长“父类定流程、子类填步骤”，也就是==模板方法模式==。

```java
abstract class Employee {
    protected final String name;
    protected final double baseSalary;

    protected Employee(String name, double baseSalary) {
        this.name = name;
        this.baseSalary = baseSalary;
    }

    public String getName() {
        return name;
    }

    // 固定流程：子类不能修改顺序，只能填充变化点
    public final void printPayslip() {
        System.out.println("===== 工资单 =====");
        System.out.println("姓名：" + name);
        System.out.println("岗位：" + getRole());
        System.out.println("应发：" + calculateSalary());
        System.out.println("==================");
    }

    protected abstract String getRole();             // 变化点 1
    public abstract double calculateSalary();        // 变化点 2
}
```

`printPayslip()` 声明为 `final`，子类不能改流程；它调用的 `getRole()`、`calculateSalary()` 会动态绑定到子类实现：

```java
Employee e = new Manager("张三", 5000, 2000);
e.printPayslip();
```

输出：

```text
===== 工资单 =====
姓名：张三
岗位：经理
应发：7000.0
==================
```

模板方法的好处：

1. ==流程只写一次==：所有子类共享同一套工资单格式；
2. ==变化点被隔离==：子类只关心“岗位叫什么、工资怎么算”；
3. ==流程受保护==：`final` 防止子类破坏统一逻辑。

还可以加入“钩子方法”，让子类选择性地改变局部行为：

```java
public final void printPayslip() {
    System.out.println("===== 工资单 =====");
    System.out.println("姓名：" + name);
    System.out.println("岗位：" + getRole());
    System.out.println("应发：" + calculateSalary());
    if (needTaxDetail()) {                       // 钩子：默认关闭
        System.out.println("税后：" + (calculateSalary() * 0.9));
    }
    System.out.println("==================");
}

protected boolean needTaxDetail() {
    return false;                                // 默认实现，子类可按需重写
}
```

> [!tip] 好莱坞原则
> 模板方法的控制方向是“==不要调用我，我会调用你==”：父类掌握流程，在合适的时机回调子类重写的方法。Spring 的 `JdbcTemplate`、Java 的 `AbstractList` 都大量使用这一模式。

## 8. 抽象类与接口的配合

抽象类可以实现接口，并且==可以只实现一部分方法，把剩下的继续留成抽象方法==：

```java
interface Payable {
    double calculateSalary();
}

interface Workable {
    void work();
}

abstract class Employee implements Payable, Workable {
    protected final String name;
    protected final double baseSalary;

    protected Employee(String name, double baseSalary) {
        this.name = name;
        this.baseSalary = baseSalary;
    }

    public String getName() {
        return name;
    }

    // 没有实现 calculateSalary() / work()，继续交给具体子类
}
```

此时 `Employee` 同时是“抽象类”和“接口实现类”，具体子类需要把两个接口方法都补齐：

```java
class Manager extends Employee {
    private final double bonus;

    public Manager(String name, double baseSalary, double bonus) {
        super(name, baseSalary);
        this.bonus = bonus;
    }

    @Override
    public double calculateSalary() {
        return baseSalary + bonus;
    }

    @Override
    public void work() {
        System.out.println(name + " 在开会");
    }
}
```

常见分工是：==接口定契约，抽象类做骨架，具体类填细节==。接口负责“对外承诺能做什么”，抽象类负责“把所有实现者共用的字段、构造方法和流程先写好”。两者的取舍见 [[接口与抽象类的区别]]。

## 9. 常见误区

1. **以为抽象类不能有构造方法**：抽象类可以有构造方法，只是不能直接 `new`，它供子类 `super(...)` 调用。
2. **以为抽象类里只能有抽象方法**：抽象类完全可以有普通方法、字段、静态方法，甚至一个抽象方法都没有。
3. **以为抽象方法可以是 `private`**：`private` 子类不可见，无法重写，编译器直接拒绝。
4. **以为抽象方法可以是 `static`**：`static` 方法属于类，不参与实例多态，也不能被重写。
5. **以为抽象类可以实例化**：`new Employee(...)` 编译错误；`new Employee(...) { ... }` 创建的是==匿名子类==对象，不是抽象类对象。
6. **以为 `abstract` 和 `final` 可以一起用**：语义相反，不能组合。
7. **以为子类一定要实现全部抽象方法**：具体子类必须；抽象子类可以继续保留。
8. **以为抽象方法可以有方法体**：抽象方法只有声明，没有 `{ }`。
9. **以为抽象类必须被继承才有意义**：它的意义正是作为父类型被继承，并配合多态统一处理。
10. **在抽象类构造方法里调用可重写方法**：会触发动态绑定，读到子类尚未初始化的字段。

## 10. 小结

* 抽象类 = ==普通类 + 抽象方法 + 禁止实例化==；
* 抽象方法只声明不实现，具体子类必须实现，抽象子类可以继续传递；
* 抽象类可以有字段、构造方法、普通方法、`static` / `final` 方法；
* `abstract` 不能与 `final`、`private`、`static`（修饰方法时）组合；
* 抽象类的构造方法用于初始化父类状态，不能直接创建对象；
* 抽象类是多态的常见父类型，也是==模板方法模式==的天然载体；
* 抽象类可以实现接口而不实现其方法，形成“接口定契约、抽象类做骨架”的结构。
