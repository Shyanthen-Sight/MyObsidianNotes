# Java 上转型对象与下转型对象

> 关联笔记：[[继承]]、[[重写]]、[[什么是多态]]、[[动态绑定]]、[[instanceof]]、[[向上转型与向下转型]]、[[面向抽象编程]]

## 一句话解释

==**上转型对象**：把子类对象赋给父类引用（子 → 父），自动完成，永远安全。==
==**下转型对象**：把父类引用转回子类引用（父 → 子），必须强制转换，运行期可能失败。==

转型改变的只是「用哪种类型的引用去看对象」，==对象的实际类型从头到尾没有变==。

---

## 一、先分清两个「类型」

Java 的引用变量同时带着两个类型，这是理解全部转型规则的起点：

| 概念 | 含义 | 由谁决定 |
| --- | --- | --- |
| ==编译时类型==（静态类型） | 变量声明时写的类型，编译器只认它 | 变量声明 `Animal a` |
| ==运行时类型==（实际类型） | 引用实际指向的对象的类型 | `new` 出来的对象 |

```java
Animal a = new Dog();
```

- `a` 的编译时类型是 `Animal`；
- `a` 的运行时类型是 `Dog`；
- 堆里只有一个 `Dog` 对象，`a` 只是指向它的一个「`Animal` 视野」的引用。

由此得到贯穿全文的黄金规则：

> [!important] 黄金规则
> **能调用哪些成员，看编译时类型；**
> **方法最终执行哪一个版本，看运行时类型（仅限被重写的实例方法）。**

## 二、上转型对象（Upcasting）

### 2.1 定义与语法

把子类对象赋给父类引用，称为上转型。它是==自动完成==的，不需要强制转换符：

```java
Dog dog = new Dog();
Animal a = dog;              // 隐式上转型

Animal a2 = new Dog();       // 也可以直接写在一起
```

接口同理，实现类对象可以自动赋给接口引用：

```java
interface Swimmable {
    void swim();
}

class Fish extends Animal implements Swimmable {
    @Override
    public void swim() {
        System.out.println("鱼在游泳");
    }
}

Swimmable s = new Fish();    // 实现类 → 接口，自动上转型
```

> [!tip] 为什么叫「向上」
> 继承关系通常画成父类在上、子类在下。从子类转到父类，方向向上，引用能看到的范围==变窄==（子类新增的成员被「遮住」）。

### 2.2 为什么上转型一定安全

因为子类对象==一定是一个父类对象==（is-a 关系）：

- 父类声明的每一个字段，子类对象里都存在；
- 父类声明的每一个可访问方法，子类对象都能响应（继承或重写）。

所以编译器允许自动完成，==上转型永远不会在运行期失败==。

反过来则不成立：父类对象不一定是子类对象（动物不一定是狗），所以下转型必须显式强转，并由运行期检查。

### 2.3 上转型对象的三条核心规则

这是考试和面试最常考的部分：

1. ==上转型对象可以访问父类声明的成员==（继承来的字段和方法）。
2. ==如果子类重写了父类的方法，通过上转型对象调用时，执行的是子类版本==——这就是多态（运行期动态绑定）。
3. ==上转型对象不能访问子类新增的字段和方法==。因为编译器只看编译时类型 `Animal`，而 `Animal` 里根本没有这些成员，直接编译报错。

完整示例：

```java
class Animal {
    String name = "动物";     // 父类字段
    int legs = 4;

    void eat() {
        System.out.println("动物吃东西");
    }

    void sleep() {
        System.out.println("动物睡觉");
    }

    static void info() {
        System.out.println("Animal.info");
    }
}

class Dog extends Animal {
    String name = "狗";        // 与父类同名字段：隐藏，不是覆盖
    int age = 3;               // 子类新增字段

    @Override
    void eat() {               // 重写父类方法
        System.out.println("狗吃骨头");
    }

    void bark() {              // 子类新增方法
        System.out.println("汪汪汪");
    }

    static void info() {       // 隐藏父类静态方法
        System.out.println("Dog.info");
    }
}
```

```java
public class UpcastDemo {
    public static void main(String[] args) {
        Animal a = new Dog();              // 上转型

        System.out.println(a.name);        // 动物（字段看引用类型）
        System.out.println(a.legs);        // 4（继承来的父类字段）
        a.eat();                           // 狗吃骨头（重写 → 动态绑定）
        a.sleep();                         // 动物睡觉（继承自父类）
        a.info();                          // Animal.info（static 按引用类型）

        // a.bark();                       // ❌ 编译错误：Animal 类型没有 bark
        // System.out.println(a.age);      // ❌ 编译错误：Animal 类型没有 age

        System.out.println(a.getClass().getSimpleName()); // Dog（对象没变）
    }
}
```

输出：

```
动物
4
狗吃骨头
动物睡觉
Animal.info
Dog
```

逐行对照规则：

| 成员 | 编译期依据 | 运行期结果 |
| --- | --- | --- |
| 父类方法（子类未重写） | 父类有 → 通过 | 父类版本 |
| 父类方法（子类重写） | 父类有 → 通过 | ==子类版本==（动态绑定） |
| 子类新增方法 | 父类没有 → ==编译错误== | — |
| 父类字段 | 父类有 → 通过 | ==父类那份字段== |
| 子类新增字段 | 父类没有 → ==编译错误== | — |
| 与父类同名的字段 | 父类有 → 通过 | ==父类那份字段==（字段不参与多态） |
| `static` 方法 | 按引用类型选择 | ==引用类型的类==（隐藏，不是重写） |
| `private` / `final` 方法 | 视访问权限 | 父类版本（不能重写） |

> [!tip] 上转型不是「永久失去」子类能力
> 子类新增的成员并没有消失，只是通过父类引用==看不见==。需要时下转型回子类引用，就能重新访问——前提是对象的实际类型确实是该子类。

### 2.4 字段隐藏：字段不参与多态

子类写一个和父类同名的字段，并不会「覆盖」父类字段，而是把父类字段==隐藏==了。通过哪种引用访问，就拿到哪一份：

```java
Dog d = new Dog();
System.out.println(d.name);            // 狗
System.out.println(d.legs);            // 4（继承自 Animal）

Animal a = d;
System.out.println(a.name);            // 动物（看 Animal 引用）
System.out.println(((Dog) a).name);    // 狗（转成 Dog 引用后看到子类字段）
```

> [!warning] 只有方法有多态，字段没有
> 字段在编译期就按引用类型绑定。即使子类有同名字段，通过父类引用拿到的仍是父类那份。这也是为什么字段通常要 `private`，通过 getter 方法访问——方法才能享受多态。

### 2.5 static 方法：按引用类型选择

`static` 方法属于类，不属于对象，不存在动态绑定。子类写同名同参的静态方法叫==隐藏==（hiding），不是重写：

```java
Dog d = new Dog();
d.info();        // Dog.info

Animal a = d;
a.info();        // Animal.info（编译器按 Animal 选）
```

> [!note] 编译器会警告
> 用对象调用静态方法时，`javac` 会给出 `static method should be accessed in a static way` 的警告。实际开发中应直接用类名调用（`Animal.info()` / `Dog.info()`），这里写成 `a.info()` 只是为了演示「按引用类型选择」的规则。

### 2.6 上转型不会创建新对象

```java
Dog d = new Dog();
Animal a = d;

System.out.println(a == d);                    // true，还是同一个对象
System.out.println(a.getClass() == Dog.class); // true，实际类型始终是 Dog
```

上转型只是换了一个「视野更窄的引用」，对象的状态、身份、实际类型都没有任何变化。

### 2.7 上转型的典型用途

#### （1）统一方法参数

```java
public static void feed(Animal a) {
    a.eat();          // 传 Animal 的任意子类都可以
}

feed(new Dog());
feed(new Cat());
```

方法只针对父类写一次，新增子类时==这个方法一行都不用改==。

#### （2）数组与集合

```java
Animal[] zoo = {
    new Dog(),
    new Cat()
};

for (Animal a : zoo) {
    a.eat();          // 各自执行自己的版本
}
```

`List<Animal>`、`Map<String, Animal>` 同理。集合元素类型声明为父类型，槽位里可以放任意子类对象。

#### （3）工厂方法返回父类型

```java
public static Animal create(String type) {
    if ("dog".equals(type)) {
        return new Dog();
    }
    return new Cat();
}
```

调用方只依赖 `Animal`，不关心具体子类，这就是[[面向抽象编程]]的雏形。

#### （4）接口回调

```java
public static void startAll(Swimmable[] swimmers) {
    for (Swimmable s : swimmers) {
        s.swim();     // 调用各实现类自己的版本
    }
}
```

把对象交给框架、线程、监听器时，本质上都是把实现类对象上转型成接口或父类引用。

## 三、下转型对象（Downcasting）

### 3.1 定义与语法

把父类引用转回子类引用，称为下转型。它==必须显式写强制转换==：

```java
Animal a = new Dog();      // 上转型
Dog d = (Dog) a;           // 下转型
d.bark();                  // 汪汪汪
System.out.println(d.age); // 3
```

> [!warning] 下转型的前提
> ==引用实际指向的对象，必须是目标类型（或目标类型的子类）的实例。==
> 编译器只能检查「两个静态类型有没有可能兼容」，真正的对象类型要到运行期才知道，所以下转型==可能抛 `ClassCastException`==。

### 3.2 三种结果

| 情形 | 代码示例 | 编译 | 运行 |
| --- | --- | --- | --- |
| 合法转型 | `Animal a = new Dog(); Dog d = (Dog) a;` | 通过 | 成功 |
| 编译通过、运行失败 | `Animal a = new Animal(); Dog d = (Dog) a;` | 通过 | ==`ClassCastException`== |
| 编译期就拒绝 | `Cat c = new Cat(); Dog d = (Dog) c;` | ==报错== | — |

```java
class Cat extends Animal { }

Animal a1 = new Dog();
Dog d1 = (Dog) a1;           // ✅ 实际对象就是 Dog，成功

Animal a2 = new Animal();
Dog d2 = (Dog) a2;           // ⚠️ 编译通过，运行抛 ClassCastException

Cat c = new Cat();
// Dog d3 = (Dog) c;         // ❌ 编译错误：inconvertible types
```

运行 `d2` 那一行时的异常信息：

```
Exception in thread "main" java.lang.ClassCastException:
class Animal cannot be cast to class Dog
```

为什么第三种在编译期就报错？`Cat` 和 `Dog` 是兄弟类，一个对象不可能同时是这两者，编译器直接判定==不可能兼容==。

但注意下面这种写法能通过编译：

```java
Animal a = new Cat();
Dog d = (Dog) a;             // 编译通过，运行抛 ClassCastException
```

因为引用的静态类型是 `Animal`，编译器只知道「`Animal` 有可能指向 `Dog`」，于是放行；实际对象却是 `Cat`，问题要到运行期才暴露。

### 3.3 接口引用的转型

接口引用和类引用之间也遵循同样的规则：

```java
interface Swimmable {
    void swim();
}

Swimmable s = new Fish();    // 实现类 → 接口，自动上转型
Fish f = (Fish) s;           // 接口 → 实现类，下转型，成功

Animal a = new Fish();
Swimmable s2 = (Swimmable) a; // 父类 → 接口，需要强转，实际实现了接口才成功

Dog d = (Dog) s;             // 编译通过（Dog 非 final，理论上可能实现 Swimmable），运行 CCE
```

编译期放行、运行期失败的原因是：`Dog` 不是 `final` 类，编译器不能排除「将来某个 `Dog` 子类实现 `Swimmable`」的可能。

如果目标类是 `final` 且没有实现该接口，编译器会直接拒绝：

```java
final class Robot { }

Swimmable s = new Fish();
// Robot r = (Robot) s;      // ❌ 编译错误：Robot 是 final 且未实现 Swimmable
```

### 3.4 安全写法：先判断，再转型

#### 写法一：传统 `instanceof` + 强转

```java
if (a instanceof Dog) {
    Dog d = (Dog) a;
    d.bark();
}
```

`instanceof` 在运行期检查实际类型，只有检查通过才强转，==不会抛 `ClassCastException`==。详见 [[instanceof]]。

#### 写法二：模式匹配（Java 16+）

```java
if (a instanceof Dog d) {
    d.bark();          // d 已经完成判断和转型，可以直接用
}
```

编译器自动完成「判断 + 强转 + 声明变量」三件事，作用域被限制在确定匹配的分支里。==推荐使用这种写法==。

### 3.5 null 的特殊情况

```java
Animal a = null;
Dog d = (Dog) a;       // 合法，结果是 null，不会抛 ClassCastException
d.bark();              // NullPointerException
```

==`null` 可以转成任何引用类型==，因为根本没有对象需要检查；但拿着这个 `null` 去调用方法，就会抛空指针异常。转型成功不代表对象可用。

### 3.6 下转型不会创建新对象

```java
Dog d = new Dog();
Animal a = d;
Dog d2 = (Dog) a;

System.out.println(d == d2);   // true
```

全程只有 `new` 出来的那一个对象，向上、向下转型都只是改变引用的类型，==不复制、不包装、不改变对象状态==。

### 3.7 数组的转型

数组也遵循转型规则，而且数组是==协变==的：

```java
Dog[] dogs = { new Dog() };
Animal[] animals = dogs;        // 数组向上转型，自动完成

Dog[] back = (Dog[]) animals;   // 数组向下转型，成功
```

但「实际类型」不匹配时，运行期会失败：

```java
Object[] arr1 = new Object[2];
// String[] strs1 = (String[]) arr1;   // ❌ ClassCastException，实际是 Object[]

Object[] arr2 = new String[2];
String[] strs2 = (String[]) arr2;      // ✅ 实际是 String[]
```

判断依据同样是==数组对象的运行时类型==：`arr2` 真正是 `String[]`，所以能转；`arr1` 真正是 `Object[]`，JVM 不允许把它当成 `String[]`。

## 四、完整案例：支付渠道

```java
abstract class Payment {
    protected String channel = "通用支付";

    public abstract void pay(double amount);

    public void printChannel() {
        System.out.println("渠道：" + channel);
    }
}

class Alipay extends Payment {
    protected String channel = "支付宝";   // 隐藏父类字段

    @Override
    public void pay(double amount) {
        System.out.println("支付宝支付 " + amount + " 元");
    }

    public void signContract() {           // 子类特有方法
        System.out.println("签订支付宝代扣协议");
    }
}

class WechatPay extends Payment {
    @Override
    public void pay(double amount) {
        System.out.println("微信支付 " + amount + " 元");
    }

    public void sendRedPacket() {          // 子类特有方法
        System.out.println("发微信红包");
    }
}
```

```java
public class PaymentDemo {
    public static void main(String[] args) {
        Payment[] payments = {
            new Alipay(),
            new WechatPay()
        };

        // 上转型 + 多态：调用方只依赖 Payment
        for (Payment p : payments) {
            p.pay(100);            // 执行各自重写的版本
            p.printChannel();      // 父类方法，读的是父类字段
            // p.signContract();   // ❌ 编译错误：Payment 类型没有该方法
        }

        // 下转型：确实需要子类特有功能时，先判断再转
        for (Payment p : payments) {
            if (p instanceof Alipay a) {
                a.signContract();
            } else if (p instanceof WechatPay w) {
                w.sendRedPacket();
            }
        }
    }
}
```

输出：

```
支付宝支付 100.0 元
渠道：通用支付
微信支付 100.0 元
渠道：通用支付
签订支付宝代扣协议
发微信红包
```

这段代码体现了转型的正确分工：

- ==默认用上转型 + 多态==完成通用逻辑（支付、打印渠道），调用方不关心具体子类；
- ==确需子类特有方法时==，才用 `instanceof` 检查后下转型；
- `printChannel()` 输出「通用支付」而不是「支付宝」，再次说明==字段不参与多态==。

## 五、编译期规则速查表

| 源引用静态类型 → 目标类型 | 是否需要强转 | 编译 | 运行时 |
| --- | --- | --- | --- |
| 子类 → 父类 | 不需要 | 通过 | ==一定成功== |
| 父类 → 子类 | 需要 | 通过 | 实际对象是目标类型才成功，否则 ==CCE== |
| 兄弟类 → 兄弟类 | 需要 | ==编译错误== | — |
| 无关类（其中一个是 `final`） | 需要 | ==编译错误== | — |
| 非 `final` 类 → 接口 | 需要 | 通过 | 实现了该接口才成功，否则 ==CCE== |
| `final` 类 → 它未实现的接口 | 需要 | ==编译错误== | — |
| `null` → 任意引用类型 | 需要 | 通过 | 结果为 `null`，不抛异常 |
| 子类数组 → 父类数组 | 不需要 | 通过 | 一定成功 |
| 父类数组 → 子类数组 | 需要 | 通过 | 数组实际类型匹配才成功 |

> [!note] 编译期检查的本质
> 编译器只检查「静态类型之间是否存在转换的可能性」：
> - 有继承 / 实现关系 → 放行；
> - 两个 `final` 类且互不相干 → 不可能，直接报错；
> - 父类与子类 → 放行，把检查推迟到运行期。
>
> 因此==编译通过 ≠ 转型一定安全==。

## 六、设计建议：上转型是常态，下转型要克制

上转型让代码依赖抽象，是[[什么是多态|多态]]和[[面向抽象编程]]的基础。下转型则意味着「我现在必须知道对象的具体类型」，会把代码重新绑死在子类上：

```java
// 坏味道：每新增一种支付方式，这里就要加一个分支
for (Payment p : payments) {
    if (p instanceof Alipay a) {
        a.signContract();
    } else if (p instanceof WechatPay w) {
        w.sendRedPacket();
    } else if (p instanceof CreditCard c) {
        c.verify();
    }
}
```

更好的做法是在父类 / 接口中声明统一的方法，让子类自己重写，调用方只依赖抽象：

```java
for (Payment p : payments) {
    p.pay(100);        // 不需要知道具体类型
}
```

这就是[[开闭原则]]：==新增子类时，调用方代码不需要修改==。

下转型仍然有合理场景：

- 使用返回 `Object` 的旧 API 或框架回调；
- 实现 `equals()` 时需要访问同类对象的字段；
- 外部类型不受你控制，无法为其添加多态方法；
- 确实需要子类特有行为，并且已经用 `instanceof` 做了保护。

## 七、常见误区

### 7.1 以为上转型后「对象变成了父类」

```java
Animal a = new Dog();
System.out.println(a.getClass().getSimpleName());   // Dog
```

对象类型自始至终不变，变的只是引用的编译时类型。

### 7.2 以为字段也会多态

```java
Animal a = new Dog();
System.out.println(a.name);   // 动物，不是 狗
```

字段在编译期按引用类型绑定，==只有方法才有多态==。

### 7.3 以为上转型后还能调用子类新增方法

```java
Animal a = new Dog();
// a.bark();      // ❌ 编译错误
```

不是「运行时找不到」，而是==编译期就拒绝==。需要调用时先下转型。

### 7.4 以为编译通过就一定安全

```java
Animal a = new Animal();
Dog d = (Dog) a;              // 编译通过，运行时 CCE
```

下转型前必须确认实际类型，或者直接用 `instanceof` 模式匹配。

### 7.5 兄弟类直接强转

```java
Cat c = new Cat();
// Dog d = (Dog) c;           // ❌ 编译错误：inconvertible types

Animal a = c;
Dog d = (Dog) a;              // 编译通过，运行时 CCE
```

如果确实要通过父类引用中转，记住运行期照样会失败。

### 7.6 对 null 掉以轻心

`(Dog) null` 不抛异常，但随后调用方法会抛 `NullPointerException`。转型成功不代表对象可用。

### 7.7 把 `static` 方法当成重写

```java
Animal a = new Dog();
a.info();        // Animal.info，不是 Dog.info
```

`static` 方法按引用类型静态选择，子类同名静态方法只是把父类方法==隐藏==了。详见 [[重写]]。

### 7.8 把下转型当常规设计手段

如果一个方法里出现大量 `instanceof` + 强转，通常说明抽象没设计好。优先把差异行为放进子类重写，而不是在调用方判断类型。

---

## 八、注意事项

1. **转型不改变对象**，只改变引用的编译时类型。
2. **能调用哪些成员看编译时类型**，被重写的方法执行哪个版本看运行时类型。
3. **上转型自动完成、永远安全**；下转型必须强转、运行期可能抛 `ClassCastException`。
4. **上转型对象不能访问子类新增的字段和方法**，编译期就会报错。
5. **字段不参与多态**：同名字段是隐藏，通过父类引用访问到的是父类那份。
6. **`static` 方法不参与多态**：按引用类型选择，子类同名方法叫隐藏。
7. **`private` / `final` 方法不能被重写**，通过父类引用调用的始终是父类版本。
8. **下转型前先用 `instanceof` 检查**，Java 16+ 优先用 `instanceof T t` 模式匹配。
9. **`null` 可以转成任意引用类型**，但随后调用方法会抛 `NullPointerException`。
10. **兄弟类之间不能直接强转**，编译期报 `inconvertible types`。
11. **接口与类之间要看 `final`**：`final` 类未实现接口时，强转直接编译错误。
12. **数组转型看数组的实际类型**，不是看元素声明的类型。
13. **能用多态解决就不要下转型**，`instanceof` 链变长往往意味着该重构抽象了。

---

## 九、小结

- ==上转型==：子类 → 父类，自动完成、一定安全；用于统一类型、实现多态、面向抽象编程。
- ==下转型==：父类 → 子类，必须强转；运行期检查实际类型，可能失败。
- 上转型对象的三条规则：**能访问父类成员**、**重写方法执行子类版本**、**不能访问子类新增成员**。
- 字段和 `static` 方法都按==编译时类型==绑定，只有被重写的实例方法才有动态绑定。
- 转型只改变引用的编译时类型，==不会创建新对象，也不会改变对象本身==。
- 下转型前先 `instanceof` 检查，Java 16+ 优先用模式匹配；设计上应尽量用多态替代类型判断。
