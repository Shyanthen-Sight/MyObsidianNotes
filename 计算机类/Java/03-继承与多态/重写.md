（Override）

> ==子类把父类中已有的方法重新实现一遍==：方法名、参数列表保持不变，方法体换成子类自己的逻辑。
>
> 重写是多态行为差异的来源，也是[[动态绑定]]能够生效的前提。
>
> 关联笔记：[[继承]]、[[动态绑定]]、[[什么是多态]]、[[重载]]、[[super关键字]]、[[final关键字]]、[[static关键字]]、[[抽象类]]、[[接口]]、[[面向抽象编程]]

## 1. 什么是重写

重写（Override），中文教材里也常叫**覆盖**：在子类中声明一个与父类方法**签名相同**的方法，为同一种行为提供子类自己的实现。

```java
class Employee {
    protected String name;

    public double calculateSalary() {
        return 5000;
    }
}

class Manager extends Employee {
    private double bonus = 2000;

    @Override
    public double calculateSalary() {   // 重写父类方法
        return 5000 + bonus;
    }
}
```

关键点：

* 重写发生在==父子类之间==，或==类与接口之间==，不是同一个类内部；
* ==方法名和参数列表必须完全相同==，否则不是重写；
* 方法体可以完全不同，这正是重写的意义；
* 运行期通过父类引用调用时，执行的是==子类的版本==。

```java
Employee e = new Manager();
System.out.println(e.calculateSalary());   // 7000.0
```

编译时 `e` 的静态类型是 `Employee`，运行期 `e` 指向的是 `Manager` 对象，因此最终执行 `Manager.calculateSalary()`。这正是[[动态绑定]]在做的事。

> [!note] 重写 vs 实现接口方法
> 类实现接口中的抽象方法，本质上也是"用子类型给出父类型声明的行为"，同样属于重写，同样可以加 `@Override`。详见第 13 节。

## 2. 为什么需要重写

1. **实现多态**：父类定义统一接口，子类给出各自实现，调用方只依赖父类。
2. **定制继承来的行为**：父类提供了默认实现，子类不满意时替换掉，例如 `toString()`、`equals()`。
3. **构建扩展点**：框架或模板方法把流程写死，把变化点留给子类重写，例如工资单流程中的 `calculateSalary()`。
4. **履行契约**：抽象方法、接口方法要求子类必须给出实现，否则编译不通过。

如果子类不重写，就直接继承父类的实现，行为不会发生任何变化。

## 3. 重写的完整规则

先给一张速查表，后面逐条展开。

| 规则        | 要求                             | 违反的后果         |
| --------- | ------------------------------ | ------------- |
| 继承 / 实现关系 | ==必须存在==                       | 无从谈起          |
| 方法名       | ==必须相同==                       | 变成重载或新方法      |
| 参数列表      | ==必须完全相同==                     | 变成重载或新方法      |
| 返回类型      | ==相同==，或为父类返回类型的子类型            | 编译错误          |
| 访问权限      | ==不能比父类更严格==                   | 编译错误          |
| 受检异常      | 不能更宽泛，也不能新增                    | 编译错误          |
| 父类方法      | 不能是 `private`、`static`、`final` | 编译错误，或根本不构成重写 |
| 构造方法      | 不能重写                           | 只能重载          |

### 3.1 必须有继承或实现关系

重写的前提是两个字：==继承==。没有 `extends` / `implements`，两个类之间各写一个同名方法只是巧合，不是重写。

```java
class A {
    void show() { }
}

class B {
    void show() { }   // 与 A 无关，只是同名方法
}
```

### 3.2 方法名与参数列表必须完全相同

Java 的方法签名是：

> **方法签名 = 方法名 + 参数类型列表**（泛型按擦除后的类型算）。

重写要求签名==完全一致==，参数的类型、个数、顺序都不能变：

```java
class Parent {
    public void print(String msg) { }
}

class Child extends Parent {
    @Override
    public void print(String msg) { }   // ✅ 重写
}
```

下面这些都不是重写：

```java
class Child extends Parent {
    public void print(Object msg) { }        // 参数类型不同 → 重载
    public void print(String msg, int n) { } // 参数个数不同 → 重载
    public void print() { }                  // 参数列表不同 → 重载
}
```

> [!warning] 参数写错，多态就悄悄失效
> 如果本意是重写，却把参数类型写错，编译器不会阻止（它只是一个新的重载方法），但父类引用调用时仍然走父类版本。第 7 节的 `@Override` 就是专门用来防这个坑的。

### 3.3 返回类型必须相同，或是其子类型（协变）

基本类型必须完全一致：

```java
class Parent {
    public int value() { return 1; }
}

class Child extends Parent {
    // @Override
    // public long value() { return 1L; }   // ❌ 编译错误：基本类型不能协变
}
```

引用类型允许**协变返回**（covariant return type，Java 5+）：子类返回类型可以是父类返回类型的子类型。

```java
class Animal {
    public Animal copy() {
        return new Animal();
    }
}

class Dog extends Animal {
    @Override
    public Dog copy() {      // ✅ Dog 是 Animal 的子类型
        return new Dog();
    }
}
```

```java
class Cat extends Animal {
    // @Override
    // public Object copy() { return new Object(); }   // ❌ Object 不是 Animal 的子类型
}
```

协变返回之所以安全，是因为任何期待 `Animal` 的地方，拿到 `Dog` 都能正常使用。反过来返回更宽的类型就会破坏类型契约，因此被编译器禁止。

> [!note] 为什么返回值不同不能像重载那样共存
> 在同一个类里，两个方法签名相同、返回类型不同，本身就是编译错误；在子类里，签名与父类相同时，返回类型只剩"相同或协变"这一条合法路径。所以==返回值不参与签名，但参与重写的合法性检查==。

### 3.4 访问权限不能比父类更严格

子类重写方法的访问权限可以==相同或更宽==，但不能更窄：

```java
class Parent {
    protected void show() {
        System.out.println("Parent.show");
    }
}

class Child extends Parent {
    @Override
    public void show() {          // ✅ protected → public，放宽
        System.out.println("Child.show");
    }
}
```

```java
class Parent2 {
    public void show() { }
}

class Child2 extends Parent2 {
    // @Override
    // protected void show() { }   // ❌ 编译错误：试图收窄为 protected
}
```

权限顺序：`private` < 默认（包私有） < `protected` < `public`。

| 父类方法的权限 | 子类重写时允许的权限 |
| --- | --- |
| `public` | 只能是 `public` |
| `protected` | `protected`、`public` |
| 默认（包私有） | 同包：默认、`protected`、`public`；跨包：不算重写 |
| `private` | ==不能重写== |

> [!important] 为什么不能收窄
> 父类引用可以指向子类对象。如果父类方法声明为 `public`，调用方就有权通过父类引用调用它；子类若把它改成 `protected`，这次调用就会在运行时"消失"，类型系统不允许这种破坏。

包私有方法还有一个容易忽略的点：==跨包子类根本没有继承它==，写一个同名同参方法不算重写，也不会发生多态。

### 3.5 受检异常不能更宽泛

子类重写方法：

* 可以==不抛出==任何受检异常；
* 可以抛出父类声明异常的==子类型==；
* 不能抛出父类没有声明的受检异常；
* 非受检异常（`RuntimeException`、`Error`）不受此限制。

```java
import java.io.*;

class Parent {
    public void load() throws IOException { }
}

class Child extends Parent {
    @Override
    public void load() throws FileNotFoundException { }   // ✅ 更窄
}

class Child2 extends Parent {
    @Override
    public void load() { }                                // ✅ 不抛
}

class Child3 extends Parent {
    // @Override
    // public void load() throws Exception { }            // ❌ 更宽
}

class Child4 extends Parent {
    @Override
    public void load() throws IllegalArgumentException { } // ✅ 非受检异常
}
```

原因同样和"父类引用指向子类对象"有关：调用方按父类的 `throws` 声明写了 `try-catch`，子类若抛出更宽的异常，调用方就接不住。

### 3.6 父类方法必须能被继承

以下父类成员无法被重写：

| 父类成员 | 子类写同名同参方法的结果 |
| --- | --- |
| `private` 方法 | 子类不可见，只是一个==全新的方法==，不构成重写 |
| `static` 方法 | 子类同名同参静态方法是==隐藏（hide）==，不是重写 |
| `final` 方法 | 编译错误，明确禁止重写 |
| 构造方法 | 不继承，谈不上重写，只能重载 |
| 字段 | 同名字段只是==隐藏==，没有重写 |
| 跨包的包私有方法 | 未被继承，同名方法不是重写 |

`private` 方法尤其容易误会：

```java
class Parent {
    private void secret() {
        System.out.println("Parent.secret");
    }

    public void callSecret() {
        secret();          // 编译期绑定到 Parent.secret
    }
}

class Child extends Parent {
    public void secret() {  // 新方法，不是重写
        System.out.println("Child.secret");
    }
}

new Child().callSecret();   // Parent.secret
```

`Parent.callSecret()` 里的 `secret()` 是私有方法，编译期就锁定为 `Parent.secret`，不会动态分派。

### 3.7 不能重写构造方法

构造方法不参与继承，自然也不能重写。子类只能通过 `super(...)` 调用父类构造方法，或者在自己的类里重载构造方法。

```java
class Parent {
    Parent(String name) { }
}

class Child extends Parent {
    Child(String name) {
        super(name);   // 调用，不是重写
    }

    Child() {
        this("默认");  // 构造方法重载
    }
}
```

### 3.8 哪些修饰符可以改

重写方法在满足前几条规则的前提下，还可以：

* 加 `final`：锁定该方法，禁止再被下级子类重写；
* 加 `synchronized`、`native`、`strictfp`：这些不影响重写关系；
* 放宽访问权限；
* 减少或收窄 `throws` 声明。

不能做的是：

* 把实例方法改成 `static`，或把 `static` 改成实例方法（编译错误）；
* 收窄访问权限；
* 改变返回类型（协变除外）。

## 4. @Override 注解

### 4.1 作用

`@Override` 告诉编译器："这个方法是在重写父类（或接口）中的方法。"

```java
@Override
public double calculateSalary() {
    return baseSalary + bonus;
}
```

它==不改变运行行为==，也不参与动态绑定，作用只有一个：**编译期校验**。

### 4.2 为什么强烈建议总是写

看一个真实场景：本意是重写，参数却写错了。

```java
class Parent {
    public void print(String msg) {
        System.out.println("Parent: " + msg);
    }
}

class Child extends Parent {
    public void print(Object msg) {        // 本意是重写，实际是重载
        System.out.println("Child: " + msg);
    }
}
```

```java
Parent p = new Child();
p.print("hello");    // Parent: hello
```

多态"失效"了，但编译器一声不吭。加上 `@Override` 后：

```java
class Child extends Parent {
    @Override
    public void print(Object msg) {   // ❌ 编译错误：方法不会重写或实现父类型中的方法
        System.out.println("Child: " + msg);
    }
}
```

错误在编译期就被暴露，而不是上线后才发现。

`@Override` 的价值可以总结为三点：

1. **防止签名写错**：把"以为重写了"变成编译错误；
2. **提高可读性**：一眼看出这是父类行为的覆盖；
3. **重构友好**：父类方法改名或改参数后，所有子类会同步报错，提醒逐个检查。

> [!tip] 使用建议
> 只要意图是重写父类方法或实现接口方法，就加 `@Override`。IDE 会自动生成，手写时也不要省。

### 4.3 接口实现也能用

从 Java 6 开始，实现接口方法同样可以标注 `@Override`：

```java
interface Payable {
    double calculateSalary();
}

class Manager implements Payable {
    @Override
    public double calculateSalary() {
        return 7000;
    }
}
```

## 5. 用 super 扩展父类行为

重写不一定是完全替换。如果子类只想在父类行为的基础上追加内容，可以用 `super` 调用父类版本：

```java
class Employee {
    protected String name;

    public String getDetails() {
        return "姓名: " + name;
    }
}

class Manager extends Employee {
    private double bonus;

    @Override
    public String getDetails() {
        return super.getDetails() + ", 奖金: " + bonus;   // 先复用，再扩展
    }
}
```

注意：

* `super.getDetails()` ==在编译期就锁定为父类版本==，不参与动态绑定；
* `super` 只能访问==直接父类==，不能用 `super.super` 跳过层级；
* 子类方法中如果直接写 `getDetails()`，会递归调用自己，必须用 `super` 区分。

关于 `super` 的完整用法，见[[super关键字]]。

## 6. 重写与动态绑定

重写本身只是"子类写了一个同名同参的方法"。真正让父类引用调用到子类版本的，是 JVM 的[[动态绑定]]。

```java
Employee e = new Manager();
e.calculateSalary();
```

分两个阶段看：

| 阶段 | 做的事 |
| --- | --- |
| 编译期 | 检查 `Employee` 中是否存在可访问的 `calculateSalary()`，生成 `invokevirtual` 指令 |
| 运行期 | 取出 `e` 指向对象的实际类型 `Manager`，在方法表中找到重写版本并执行 |

动态绑定要成立，需要同时满足四个条件：

1. 有继承或实现关系；
2. 方法被重写；
3. 父类（或接口）引用指向子类对象；
4. 通过实例方法调用（不是 `static`、`private`、`final`、构造方法）。

少任何一个，都不会发生多态。完整的字节码与方法表分析见[[动态绑定]]。

## 7. 重写 vs 重载

这两个词只共享"方法名相同"一点，其余几乎全部相反。

| 对比项 | **重写（Override）** | **重载（Overload）** |
| --- | --- | --- |
| 发生位置 | 父子类之间，或类与接口之间 | ==同一个类内部==，或父子类之间 |
| 方法名 | 相同 | 相同 |
| 参数列表 | ==必须完全相同== | ==必须不同== |
| 返回值 | 相同，或协变（子类型） | 任意，不参与判断 |
| 访问权限 | ==不能比父类更严格== | 任意 |
| 异常声明 | ==不能比父类更宽泛== | 任意 |
| 绑定时机 | ==运行期（动态绑定）== | ==编译期（静态绑定）== |
| 目的 | 改变父类的行为 | 为同一功能提供多种入参形式 |
| 是否体现多态 | 是（运行时多态） | 否（编译时多态） |
| 注解 | `@Override` | 无专用注解 |

最常见的混淆：在子类里写了一个同名但参数不同的方法。

```java
class Animal {
    void speak() {
        System.out.println("动物叫");
    }
}

class Dog extends Animal {
    @Override
    void speak() {                 // 重写
        System.out.println("汪汪");
    }

    void speak(int times) {        // 重载，不是重写
        for (int i = 0; i < times; i++) {
            speak();
        }
    }
}
```

在 `speak(int times)` 上加 `@Override` 会直接编译报错——父类里没有这个方法。

> [!warning] 重写和重载可以同时存在
> 一个子类既可以重写父类的 `speak()`，也可以重载出 `speak(int)`。调用哪个版本由参数决定（编译期），方法体执行哪份由对象实际类型决定（运行期）。

详见[[重载]]。

## 8. 重写 vs 隐藏

`static` 方法和字段也可以"同名同参"，但它们==不参与重写==，只叫**隐藏（hiding）**。

| 父类成员 | 子类写法 | 结果 | 是否多态 |
| --- | --- | --- | --- |
| 实例方法 | 同名同参实例方法 | ==重写== | 是 |
| `static` 方法 | 同名同参 `static` 方法 | 隐藏 | 否 |
| `static` 方法 | 同名同参实例方法 | 编译错误 | — |
| 实例方法 | 同名同参 `static` 方法 | 编译错误 | — |
| 字段 | 同名字段 | 隐藏 | 否 |
| `private` 方法 | 同名方法 | 新方法 | 否 |

### 8.1 static 方法隐藏

```java
class A {
    static void hello() {
        System.out.println("A.hello");
    }
}

class B extends A {
    static void hello() {          // 隐藏，不是重写
        System.out.println("B.hello");
    }
}

A a = new B();
a.hello();     // A.hello —— 看引用的静态类型
B.hello();     // B.hello —— 看类名
```

静态方法在编译期就按"引用变量的静态类型 / 类名"确定，和对象实际类型无关。

### 8.2 字段隐藏

```java
class A {
    String tag = "A";
}

class B extends A {
    String tag = "B";
}

A a = new B();
System.out.println(a.tag);           // A
System.out.println(((B) a).tag);     // B
```

两个 `tag` 在对象里==同时存在==，`B.tag` 只是隐藏了 `A.tag`，具体读哪个由引用的静态类型决定。

## 9. 重写 Object 类的方法

所有类都直接或间接继承 `java.lang.Object`，因此下面这些方法随时可以重写。

| 方法 | 能否重写 | 说明 |
| --- | --- | --- |
| `toString()` | ✅ | 最常重写，决定打印结果 |
| `equals(Object)` | ✅ | 默认比较引用，常改为比较内容 |
| `hashCode()` | ✅ | 与 `equals` 必须成对重写 |
| `clone()` | ✅（`protected`） | 需实现 `Cloneable`，一般用拷贝构造替代 |
| `finalize()` | ⚠️ 可重写但已弃用 | 不要使用 |
| `getClass()` | ❌ `final` | 运行期类型信息 |
| `notify()` / `notifyAll()` / `wait(...)` | ❌ `final` | 线程协作方法 |

### 9.1 toString()

默认实现输出"类全名 + `@` + 哈希值"，可读性很差：

```java
Employee e = new Manager();
System.out.println(e);   // Manager@1b6d3586
```

重写后：

```java
@Override
public String toString() {
    return "Manager{name='" + name + "', bonus=" + bonus + "}";
}
```

```java
System.out.println(e);   // Manager{name='张三', bonus=2000.0}
```

`System.out.println(obj)`、字符串拼接都会隐式调用 `toString()`。

### 9.2 equals() 与 hashCode()

`Object.equals()` 默认比较==引用是否相同==，即 `==`。业务上往往需要按内容比较，就要重写：

```java
import java.util.Objects;

public class Student {
    private String id;
    private String name;

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;                        // 同一引用
        if (o == null || getClass() != o.getClass()) return false;
        Student student = (Student) o;
        return Objects.equals(id, student.id);
    }

    @Override
    public int hashCode() {
        return Objects.hash(id);
    }
}
```

`equals` 必须满足的契约：

* **自反性**：`x.equals(x)` 为 `true`；
* **对称性**：`x.equals(y)` 与 `y.equals(x)` 结果一致；
* **传递性**：`x.equals(y)`、`y.equals(z)` 为真，则 `x.equals(z)` 为真；
* **一致性**：对象未修改时，多次调用结果不变；
* **非空性**：`x.equals(null)` 必须为 `false`。

> [!warning] 重写 equals 必须同时重写 hashCode
> 契约要求：==两个 equals 相等的对象，hashCode 必须相等==。
> 如果只重写 `equals`，`HashMap`、`HashSet` 会先用 `hashCode` 定位桶，再在桶内用 `equals` 比较；哈希值不同，两个"相等"的对象会被放进不同的桶，导致 `contains`、去重全部失效。

### 9.3 一个经典陷阱：equals 写成了重载

```java
public class Student {
    private String id;

    // ❌ 参数写成了 Student，这是重载 Object.equals(Object)
    public boolean equals(Student other) {
        return other != null && Objects.equals(id, other.id);
    }
}
```

这段代码能编译，但 `List.contains`、`HashMap` 内部调用的都是 `equals(Object)`，永远不会走到这个版本。加上 `@Override` 会立刻报错：

```java
@Override
public boolean equals(Student other) {   // ❌ 编译错误：不会重写父类方法
    ...
}
```

正确写法必须是 `equals(Object o)`。

## 10. 抽象方法与接口方法的重写

### 10.1 实现抽象方法

`abstract` 方法没有方法体，具体子类必须重写它，否则子类自己也必须声明为 `abstract`：

```java
abstract class Employee {
    public abstract double calculateSalary();
}

class Manager extends Employee {
    @Override
    public double calculateSalary() {   // 必须实现
        return 7000;
    }
}
```

```java
class Intern extends Employee {
    // 没有实现 calculateSalary()
    // ❌ 编译错误：Intern 不是抽象类，且未实现抽象方法
}
```

### 10.2 重写 default 方法

接口的 `default` 方法可以像普通父类方法一样被重写：

```java
interface Payable {
    default double calculateSalary() {
        return 5000;
    }
}

class Manager implements Payable {
    @Override
    public double calculateSalary() {   // 重写 default 实现
        return 7000;
    }
}
```

### 10.3 多个接口的 default 冲突

如果一个类实现了两个接口，而它们提供了签名相同的 `default` 方法，编译器无法替你选择，必须显式重写：

```java
interface A {
    default void hello() { System.out.println("A"); }
}

interface B {
    default void hello() { System.out.println("B"); }
}

class C implements A, B {
    @Override
    public void hello() {
        A.super.hello();   // 显式选择 A 的默认实现
    }
}
```

不重写会直接编译错误：`class C inherits unrelated defaults for hello()`。

### 10.4 接口的 static 方法

接口中的 `static` 方法属于接口本身，==不被实现类继承，也不能被重写==，只能通过接口名调用。

## 11. 不能重写的情形

| 成员           | 能否重写 | 原因              |
| ------------ | ---- | --------------- |
| `private` 方法 | ❌    | 子类不可见，同名方法只是新方法 |
| `static` 方法  | ❌    | 属于类，同名同参是隐藏     |
| `final` 方法   | ❌    | 语言层面明确禁止        |
| 构造方法         | ❌    | 不继承，只能重载        |
| 字段           | ❌    | 只能隐藏            |
| `final` 类    | ❌    | 类本身不能被继承        |
| 跨包的包私有方法     | ❌    | 子类没有继承到它        |

`final` 类与 `final` 方法：

```java
final class ImmutableValue { }   // 不能被继承，自然也无法重写其方法

class Parent {
    public final void template() { }   // 子类不能重写
}
```

JDK 中的 `String` 就是 `final` 类的典型例子，所以不能通过继承篡改它的行为。

## 12. 构造方法中调用可重写方法

这是一个和重写紧密相关的经典陷阱：

```java
class Parent {
    Parent() {
        show();          // 构造方法中调用可重写方法
    }

    void show() {
        System.out.println("Parent.show");
    }
}

class Child extends Parent {
    private int value = 42;

    @Override
    void show() {
        System.out.println("Child.show, value=" + value);
    }
}

public class Demo {
    public static void main(String[] args) {
        new Child();
    }
}
```

输出：

```
Child.show, value=0
```

执行顺序是：

1. 分配内存，所有字段先置为默认值（`value = 0`）；
2. 调用 `Parent` 构造方法；
3. 其中的 `show()` 发生动态绑定，实际执行 `Child.show()`；
4. 此时 `Child` 的字段初始化 `value = 42` ==还没有执行==；
5. 最后才执行 `Child` 构造方法体。

> [!warning] 不要在构造方法中调用可重写方法
> * 子类字段尚未初始化，可能读到 `0` / `null` / `false`；
> * 子类重写方法可能依赖自己的初始化逻辑，行为不可预期；
> * 如果一定要调用，把方法声明为 `private` 或 `final`，杜绝被重写。

更完整的分析见[[父类的构造方法与子类的关系]]与[[动态绑定]]。

## 13. 泛型重写与桥接方法

泛型在编译后会类型擦除，这会让重写在字节码层面多出一个**桥接方法（bridge method）**。

```java
class Box<T> {
    void set(T value) { }
}

class StringBox extends Box<String> {
    @Override
    void set(String value) { }   // 源码层面的重写
}
```

`javap -c -p StringBox` 会看到两个方法：

```
void set(java.lang.String);
void set(java.lang.Object);   // 编译器生成的桥接方法，内部强转后调用 set(String)
```

> [!note] 为什么要生成桥接
> 父类擦除后的签名是 `set(Object)`。为了让"父类引用指向子类对象"时仍能调用到子类的 `set(String)`，编译器自动生成一个 `set(Object)` 桥接方法，负责把参数强转为 `String` 再转发。
> 这也是为什么反射遍历 `getDeclaredMethods()` 时可能看到"多出来"的方法，可以用 `Method.isBridge()` 判断。

协变返回类型也可能生成桥接方法，原理相同。

## 14. 重写的设计约束：里氏替换

重写不只是语法问题，还受**里氏替换原则（LSP）**约束：

> 任何使用父类的地方，都应该能透明地替换成子类对象，而程序行为不被破坏。

编译器能帮你检查的：

* 访问权限不能收窄；
* 受检异常不能变宽；
* 返回类型只能协变。

编译器检查不了、需要自觉遵守的：

* 不要削弱父类承诺的后置条件，例如父类承诺返回非 `null`，子类不能返回 `null`；
* 不要增加父类未声明的前置条件，例如父类接受任意正整数，子类不能只接受偶数；
* 不要产生父类文档中未声明的副作用；
* 不要破坏 `equals` / `hashCode` / `compareTo` 的契约。

```java
class Account {
    /** 返回当前余额，永不为负 */
    public double getBalance() {
        return 0;
    }
}

class BadAccount extends Account {
    @Override
    public double getBalance() {
        return -1;   // ❌ 编译通过，但破坏了父类的语义契约
    }
}
```

> [!tip] 模板方法模式
> 父类把流程写成 `final`，把变化点写成可重写方法，子类只重写变化点：
>
> ```java
> public final void printPayslip() {
>     System.out.println("姓名：" + name);
>     System.out.println("应发：" + calculateSalary());   // 变化点，交给子类
> }
> ```
>
> 这样既保证了流程统一，又保留了扩展性，符合[[开闭原则]]。详见[[面向抽象编程]]。

## 15. 常见误区

1. **参数不同以为是重写**：参数列表不同是重载，不是重写，也不会产生多态。
2. **返回值不同以为是重写**：签名相同、返回类型不兼容，直接编译错误；只有协变才合法。
3. **以为可以收窄访问权限**：`public` 不能改成 `protected`，编译器会拦截。
4. **以为 `private` 方法能重写**：子类同名方法只是新方法，父类内部调用仍走父类版本。
5. **以为 `static` 方法能重写**：那是隐藏，调用看引用类型或类名。
6. **以为字段能重写**：字段只能隐藏，具体读哪份由引用静态类型决定。
7. **以为构造方法能重写**：构造方法不继承，只能重载。
8. **以为 `@Override` 是多态的必要条件**：它只是编译期校验，不写也能构成重写，但强烈建议写。
9. **以为重写可以抛更宽的异常**：受检异常只能更窄或更少。
10. **`equals` 参数写成具体类型**：那是重载 `equals(Object)`，集合类根本不会调用它。
11. **只重写 `equals` 不重写 `hashCode`**：`HashMap` / `HashSet` 行为异常。
12. **在构造方法中调用可重写方法**：会读到子类尚未初始化的字段。

## 16. 常见面试题

| 问题 | 答案 |
| --- | --- |
| 重写和重载的区别？ | 重写发生在父子类之间，签名相同、运行期绑定；重载发生在同类或父子类之间，参数不同、编译期绑定 |
| 重写必须满足哪些条件？ | 有继承/实现关系；方法名和参数列表相同；返回类型相同或协变；访问权限不更严；受检异常不更宽；父类方法非 `private`/`static`/`final` |
| 返回值不同能构成重写吗？ | 引用类型可以协变（返回子类型）；基本类型必须完全一致，否则编译错误 |
| 重写能把 `public` 改成 `protected` 吗？ | 不能，访问权限不能比父类更严格 |
| 重写能抛出更宽的异常吗？ | 不能抛出更宽的受检异常，但可以减少、收窄，或抛非受检异常 |
| `private` 方法能被重写吗？ | 不能。子类同名方法只是新方法 |
| `static` 方法能被重写吗？ | 不能，只能隐藏；调用看引用类型或类名 |
| `final` 方法能被重写吗？ | 不能 |
| 构造方法能被重写吗？ | 不能，只能重载 |
| `@Override` 的作用？ | 编译期校验方法确实重写了父类/接口方法，防止签名写错 |
| 重写是编译期还是运行期决定的？ | 重写的方法调用在运行期由动态绑定决定；编译器只检查方法是否存在 |
| 重写 `equals` 为什么必须重写 `hashCode`？ | 契约要求相等的对象哈希值必须相等，否则哈希容器会失效 |
| 字段能被重写吗？ | 不能，只能隐藏 |
| 接口 `default` 方法能被重写吗？ | 能 |
| 子类重写方法能加 `final` 吗？ | 能，表示禁止再被下级子类重写 |

## 17. 最佳实践

* **总是写 `@Override`**：把签名写错变成编译错误，成本最低的防御。
* **重写 `equals` 必重写 `hashCode`**：两者是契约上的绑定关系。
* **遵守里氏替换**：子类不能削弱父类的语义承诺，否则多态会在意想不到的地方出错。
* **不要在构造方法中调用可重写方法**：必要时把方法声明为 `private` 或 `final`。
* **用 `super` 复用父类逻辑**：扩展行为时先调用父类版本，避免复制粘贴。
* **重写要收敛变化点**：模板方法模式中，只重写父类预留的钩子方法，不要试图改 `final` 流程。
* **保持行为一致**：重写方法的异常、副作用、线程安全性应与父类声明保持一致。
* **不要为了"看起来像重写"而强行继承**：没有 is-a 关系时优先用组合。

## 18. 小结

* 重写 = ==子类对父类同名同参方法的重新实现==，是运行时多态的行为基础；
* 核心规则：==签名相同、返回类型相同或协变、权限不收窄、受检异常不变宽==；
* `private`、`static`、`final` 方法、构造方法、字段都==不能重写==，`static` 和字段只能隐藏；
* `@Override` 不改变运行行为，但能在编译期拦住签名写错的 Bug；
* 重写方法的调用由[[动态绑定]]在运行期按对象实际类型决定；
* 重写受里氏替换原则约束，应保持父类契约，而不是只满足语法。
