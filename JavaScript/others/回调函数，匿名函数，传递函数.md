# 回调函数、匿名函数、传递函数

> 一句话：这三件事其实是同一个故事的不同侧面——**函数在 JS 里是「值」**，所以可以**传递**（把函数当参数交给别人）；交给别人之后，别人在合适的时机**回过头来调用**它，它就是**回调函数**；而这个函数往往只用一次，不需要名字，于是就地写成**匿名函数**。

```js
// 一个例子同时占齐三者
button.addEventListener('click', function () {
  console.log('被点击了');
});
// ① 传递函数：把匿名函数作为第二个参数交给 addEventListener
// ② 回调函数：点击发生时，浏览器反过来调用它
// ③ 匿名函数：这个函数没有名字
```

---

## 一、共同前提：函数是「值」

要理解这三个词，先要接受一件事：**JS 里的函数不是语法结构，而是一个可以到处传递的值**（对象）。

```js
function add(a, b) {
  return a + b;
}

const fn = add;              // 赋给变量
const arr = [add, fn];       // 放进数组
const obj = { add: add };    // 放进对象

console.log(fn(1, 2));       // 3
console.log(arr[0](2, 3));   // 5
console.log(obj.add(3, 4));  // 7
```

### 1.1 函数名 vs 函数调用

这是后面所有坑的根源，必须先分清：

```js
add;      // 函数本身（一个值，类型是 function）
add(1, 2); // 调用 add，得到它的返回值 3
```

| 写法 | 含义 | 结果 |
| --- | --- | --- |
| `add` | 引用函数对象 | `function add(...)` |
| `add(1, 2)` | 立刻执行函数 | `3` |

**传函数时写名字，不写括号；写括号就是当场执行并把结果传过去。**

### 1.2 这也是「高阶函数」的基础

- **高阶函数（Higher-Order Function）**：接收函数作为参数，或返回一个函数的函数。
- 内置的 `map`、`filter`、`forEach`、`sort`、`setTimeout`、`addEventListener` 全是高阶函数。

```js
function runTwice(fn) {   // 接收函数 → 高阶函数
  fn();
  fn();
}

runTwice(function () {
  console.log('hi');
});
```

## 二、传递函数：把函数当参数交出去

> **传递函数**不是 JS 的专有名词，它描述的只是一个动作：**把函数本身作为实参，传给另一个函数。**

```js
function greet() {
  console.log('你好');
}

function callTwice(fn) {
  fn();
  fn();
}

callTwice(greet); // ✅ 把函数本身传进去，输出两次「你好」
```

`callTwice` 不关心 `fn` 里面写了什么，它只负责「调用两次」。具体做什么，由**调用者传进来**决定——这就是把「做什么」参数化了。

### 2.1 最典型的错误：传成了调用结果

```js
callTwice(greet()); // ❌
```

执行过程：

1. 实参先求值：`greet()` 立即执行，打印一次「你好」，返回 `undefined`；
2. 真正传给 `callTwice` 的是 `undefined`；
3. 函数体里执行 `fn()`，相当于 `undefined()` → **TypeError**。

```js
callTwice(greet);   // ✅ 传函数
callTwice(greet()); // ❌ 传函数的返回值
```

> 记住：**传函数不加括号，加括号是调用。**

### 2.2 带参数地传递

真正有用的场景，是把「具体算法」作为参数传进去：

```js
function calculate(a, b, operation) {
  return operation(a, b);
}

calculate(2, 3, function (x, y) {
  return x + y;
}); // 5

calculate(2, 3, (x, y) => x * y); // 6
```

同一个 `calculate`，换一个函数就换一种运算：

```js
const add = (a, b) => a + b;
const sub = (a, b) => a - b;

calculate(10, 4, add); // 14
calculate(10, 4, sub); // 6
```

### 2.3 返回函数也是「传递」

函数不仅能当参数，还能当返回值：

```js
function multiplier(n) {
  return function (x) {
    return x * n;
  };
}

const double = multiplier(2);
const triple = multiplier(3);

console.log(double(5)); // 10
console.log(triple(5)); // 15
```

`multiplier` 把「乘以几」记住，再返回一个函数。这是闭包的常见用法。

## 三、回调函数：传出去，等别人来调用

> **回调函数 = 作为参数传给另一个函数，并由那个函数在某个时机「回过头来」调用的函数。**

「回调」两个字拆开看：

- **回**：函数是交出去的，控制权在对方手里；
- **调**：对方在合适的时机调用它。

```js
function doSomething(callback) {
  console.log('1. 我开始做事');
  callback();                    // 2. 反过来调用你交给我的函数
  console.log('3. 我继续做');
}

doSomething(function () {
  console.log('2. 回调被调用了');
});

// 输出顺序：
// 1. 我开始做事
// 2. 回调被调用了
// 3. 我继续做
```

在上面这段代码里：

- 你写的匿名函数 → **回调函数**
- `doSomething` → **调用回调的函数**（也常被叫作「宿主函数」）
- 把匿名函数写进参数列表 → **传递函数**

### 3.1 回调不一定是异步的

很多人以为「回调 = 异步」，其实不是。**回调只说明「由别人来调用」，同步异步都可以。**

**同步回调**——调用者立刻在内部循环调用：

```js
const nums = [1, 2, 3];

nums.forEach(function (n) {
  console.log(n); // 1、2、3，全部在当前这段代码里执行完
});

nums.map(function (n) {
  return n * 2;
}); // [2, 4, 6]
```

**异步回调**——先交出去，未来某个时刻才被调用：

```js
setTimeout(function () {
  console.log('1 秒后执行'); // 现在不执行，1 秒后才执行
}, 1000);

button.addEventListener('click', function () {
  console.log('点击时执行'); // 点击发生时才执行
});
```

| | 同步回调 | 异步回调 |
| --- | --- | --- |
| 何时被调用 | 宿主函数执行过程中立刻调用 | 未来某个事件/时间点调用 |
| 例子 | `map`、`filter`、`forEach`、`sort` | `setTimeout`、事件、`fetch`、Node 文件 IO |
| 执行顺序 | 可预测，按代码顺序 | 需要等，顺序由事件循环决定 |

### 3.2 为什么需要回调

把**通用流程**和**具体步骤**分开：

```js
// 通用流程：遍历数组
function myForEach(arr, callback) {
  for (let i = 0; i < arr.length; i++) {
    callback(arr[i], i);
  }
}

// 具体步骤：由调用者决定
myForEach([10, 20, 30], function (value, index) {
  console.log(index, value);
});
```

`myForEach` 只负责「遍历」，至于每个元素要做什么，交给回调。这就是内置数组方法的实现思路。

### 3.3 控制反转

回调的本质是**控制反转（Inversion of Control）**：

> 你把一段代码交给别人，**什么时候执行、执行几次、传什么参数，都由别人决定**。

```js
// 你只能决定「做什么」，不能决定「何时做」
setTimeout(function () {
  console.log('我无法决定这一行什么时候执行');
}, 1000);
```

这既是回调的强大之处，也是它的问题来源（回调地狱、错误处理分散等）。

### 3.4 Node 风格：error-first 回调

Node.js 早期 API 的约定：**回调的第一个参数是错误对象，第二个才是数据。**

```js
const fs = require('fs');

fs.readFile('a.txt', 'utf8', function (err, data) {
  if (err) {
    console.error('读取失败', err);
    return; // 提前返回，避免继续执行
  }
  console.log(data);
});
```

看到 `function (err, data)` 这种签名，基本就是 error-first 回调。

### 3.5 回调嵌套：回调地狱

当多个异步操作有先后依赖时，回调会一层套一层：

```js
step1(function (a) {
  step2(a, function (b) {
    step3(b, function (c) {
      step4(c, function (d) {
        console.log(d);
      });
    });
  });
});
```

这叫**回调地狱（Callback Hell）**：缩进越来越深、错误处理重复、流程难以阅读。Promise 和 `async/await` 就是为了解决它而出现的。

```js
// Promise 写法：从「嵌套」变成「链式」
step1()
  .then(step2)
  .then(step3)
  .then(step4)
  .then(console.log);
```

> 详见 [[11.1 简介：回调|11]]。

## 四、匿名函数：回调最常见的写法

回调函数往往**只用一次**，而且逻辑就写在调用处，给它起名字反而多此一举，所以通常写成匿名函数。

> **匿名函数 = 没有名字的函数表达式**，必须作为「值」使用（赋给变量、作为参数、立即执行）。详见 [[匿名函数|匿名函数]]。

同一个回调，三种写法：

```js
// ① 具名函数：先定义，再传递
function log(n) {
  console.log(n);
}
[1, 2, 3].forEach(log);

// ② 匿名函数表达式：就地写
[1, 2, 3].forEach(function (n) {
  console.log(n);
});

// ③ 箭头函数：匿名函数的简写
[1, 2, 3].forEach(n => console.log(n));
```

三者功能一样，区别在写法、复用性和 `this`。

### 4.1 什么时候用哪一种

| 情况 | 推荐写法 | 原因 |
| --- | --- | --- |
| 逻辑短、只用一次 | 匿名函数 / 箭头函数 | 不污染命名空间，意图集中 |
| 多处复用 | 具名函数 | 可复用，可测试 |
| 需要递归 | 具名函数声明或 NFE | 匿名函数没有稳定名字可引用 |
| 需要 `removeEventListener` | 具名函数或先存引用 | 移除时必须传同一个函数对象 |
| 需要 `this` 指向元素/调用者 | 普通函数 | 箭头函数没有自己的 `this` |
| 想继承外层 `this` | 箭头函数 | 词法作用域绑定 |
| 对象方法 | 方法简写 `say() {}` | 有名字，`this` 正确 |

```js
// 需要复用 → 具名
function isAdult(user) {
  return user.age >= 18;
}
users.filter(isAdult);
users.some(isAdult);

// 只用一次 → 箭头
users.filter(user => user.age >= 18);

// 需要移除 → 必须先存引用
function onClick() {
  console.log('clicked');
}
button.addEventListener('click', onClick);
button.removeEventListener('click', onClick);
```

### 4.2 匿名函数的常见代价

- 调用栈里容易显示 `anonymous`，调试信息弱；
- 没有引用就无法 `removeEventListener`；
- 不能直接按名字递归；
- 太长时塞在参数里可读性差，不如抽成具名函数。

判断标准：**只用一次、逻辑短 → 匿名；要复用、要移除、要递归、逻辑长 → 具名。**

## 五、把三者串起来：一次完整的执行过程

```js
const users = [
  { name: '小明', age: 17 },
  { name: '小红', age: 20 },
  { name: '小刚', age: 25 }
];

// ① 定义：一个普通的具名函数
function isAdult(user) {
  return user.age >= 18;
}

// ② 传递：把函数本身（不加括号）交给 filter
const adults = users.filter(isAdult);

console.log(adults);
// [{ name: '小红', age: 20 }, { name: '小刚', age: 25 }]
```

执行过程：

```
你 ──把 isAdult 传进去──▶ filter
                              │
                              ├─ 取出 users[0] → 调用 isAdult(users[0]) → false
                              ├─ 取出 users[1] → 调用 isAdult(users[1]) → true
                              └─ 取出 users[2] → 调用 isAdult(users[2]) → true
                              │
你 ◀────────── 返回新数组 ────┘
```

对应三个词：

| 词 | 在这段代码里 | 本质 |
| --- | --- | --- |
| **传递函数** | `filter(isAdult)` 把 `isAdult` 交出去 | 一个**动作**：函数作为参数 |
| **回调函数** | `filter` 内部逐个元素调用 `isAdult` | 一个**角色**：被传入、被对方调用 |
| **匿名函数** | 如果写成 `filter(user => user.age >= 18)` | 一种**写法**：没有名字 |

再强调一次：

> **「回调」说的是这个函数的角色，「匿名」说的是这个函数的写法，「传递」说的是把它交出去的动作。** 三者可以同时成立，也可以只占其一。

```js
// 具名回调：是回调，但不是匿名
users.forEach(isAdult);

// 匿名函数但没有被回调：赋给变量即可，没有「被别人调用」
const f = function () {};

// 传递了但不是回调？—— 只要传进去后被对方调用，它就是回调；
// 「传递」是动作，「回调」是结果。
```

## 六、常见坑

### 1. 传函数 vs 传调用结果（最高频）

```js
function handleClick(event) {
  console.log('clicked', event.target);
}

button.addEventListener('click', handleClick);   // ✅ 点击时才调用
button.addEventListener('click', handleClick()); // ❌ 立即执行，传的是 undefined
```

### 2. 回调的参数由调用者决定，不是你想传什么就传什么

数组方法会按固定顺序传参：

```js
[1, 2, 3].map(function (value, index, array) {
  // value：当前元素
  // index：当前下标
  // array：原数组
});
```

所以直接传内置函数要小心：

```js
[1, 2, 3].map(parseInt);
// [1, NaN, NaN]
```

原因：`map` 传的是 `(value, index, array)`，`parseInt` 接收的是 `(string, radix)`。于是变成：

```js
parseInt('1', 0); // 1（radix 0 视为 10）
parseInt('2', 1); // NaN（进制 1 非法）
parseInt('3', 2); // NaN（二进制里没有 3）
```

正确写法是包一层，明确控制参数：

```js
[1, 2, 3].map(n => parseInt(n, 10)); // [1, 2, 3]
```

### 3. 方法当回调传递会丢 `this`

```js
const obj = {
  name: '小明',
  say() {
    console.log(this.name);
  }
};

setTimeout(obj.say, 0);
// ❌ 输出 undefined 或空字符串：
// 函数被「摘」下来单独调用，this 不再指向 obj

setTimeout(obj.say.bind(obj), 0); // ✅ 小明
setTimeout(() => obj.say(), 0);   // ✅ 小明
```

**方法一旦脱离对象单独传递，`this` 就丢了。** 用 `bind` 固定，或用箭头函数包一层。

### 4. `var` 循环里的回调共享同一个变量

```js
for (var i = 0; i < 3; i++) {
  setTimeout(function () {
    console.log(i); // 3 3 3
  }, 0);
}
```

回调执行时循环早已结束，三个回调看到的是同一个 `i` 的最终值。用 `let` 给每次迭代创建独立绑定：

```js
for (let i = 0; i < 3; i++) {
  setTimeout(function () {
    console.log(i); // 0 1 2
  }, 0);
}
```

### 5. 回调里的 `return` 不会返回外层函数

```js
function findAdult(users) {
  users.forEach(function (user) {
    if (user.age >= 18) {
      return user; // ❌ 只是从这一次回调里返回，外层仍是 undefined
    }
  });
}
```

`forEach` 会忽略回调的返回值。想「找到就停」，用 `find`：

```js
function findAdult(users) {
  return users.find(user => user.age >= 18); // ✅
}
```

需要提前中断循环时，`for...of` 比 `forEach` 更合适：

```js
for (const user of users) {
  if (user.age >= 18) return user;
}
```

### 6. 匿名回调无法移除事件监听

```js
// ❌ 两次传入的是两个不同的函数对象，移除不掉
button.addEventListener('click', function () {
  console.log('clicked');
});
button.removeEventListener('click', function () {
  console.log('clicked');
});

// ✅ 保存同一个引用
function onClick() {
  console.log('clicked');
}
button.addEventListener('click', onClick);
button.removeEventListener('click', onClick);
```

### 7. 回调地狱

多层嵌套的异步回调会迅速失控。把回调改成 Promise 链或 `async/await`，见「3.5 回调嵌套」。

### 8. 同步回调里抛出的错误会打断宿主函数

```js
try {
  [1, 2, 3].forEach(function (n) {
    if (n === 2) throw new Error('出错了');
    console.log(n);
  });
} catch (err) {
  console.log('捕获到', err.message);
}
```

同步回调的异常会沿调用栈冒泡。但**异步回调**（如 `setTimeout` 里的）抛错时，宿主函数早已返回，外层的 `try/catch` 捕获不到：

```js
try {
  setTimeout(function () {
    throw new Error('异步错误'); // ❌ 外层 catch 捕获不到
  }, 0);
} catch (err) {
  console.log('不会执行');
}
```

异步错误要在回调内部处理，或用 Promise 的 `.catch`。

## 七、速查表

### 7.1 三个词对照

| 概念 | 是什么 | 判断标准 | 关键词 |
| --- | --- | --- | --- |
| **传递函数** | 把函数当参数传给另一个函数 | 参数位置出现函数名或函数字面量 | 传**引用**，不加 `()` |
| **回调函数** | 被传入、由对方在合适时机调用的函数 | 谁调用它？不是你自己，是宿主函数 | 控制反转 |
| **匿名函数** | 没有名字的函数表达式 | `function` 后面没有名字 / 箭头函数 | 一次性、就地写 |

### 7.2 同一段逻辑的不同写法

```js
// 具名 + 传递
function double(n) { return n * 2; }
[1, 2, 3].map(double);

// 匿名 + 传递
[1, 2, 3].map(function (n) { return n * 2; });

// 箭头 + 传递
[1, 2, 3].map(n => n * 2);
```

### 7.3 传参检查清单

1. 传的是函数，还是函数的**调用结果**？→ 去掉 `()`。
2. 回调的参数顺序，是宿主函数规定的吗？→ 查文档，别想当然。
3. 这个回调需要 `this` 吗？→ 需要就用普通函数 / `bind`。
4. 这个回调需要被移除或复用吗？→ 先存成具名函数。
5. 回调里有 `return`，是返回给谁？→ 只返回给宿主函数。
6. 多层嵌套了吗？→ 考虑 Promise / `async/await`。

> 记忆口诀：**函数是值能传递，传参别加小括号；交给别人等回调，只用一次可匿名；要复用、要移除、要递归，就给它起个名。**
