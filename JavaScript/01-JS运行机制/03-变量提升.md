# 第 3 讲：变量提升（Hoisting in JavaScript）

> [!abstract] 本讲要点
> - 变量和函数可以在声明/赋值之前被访问，这一现象称为变量提升（Hoisting）。
> - 提升源于执行上下文的第一阶段——内存创建阶段。
> - 变量在内存中被初始化为 undefined，函数则是把整段函数代码放入内存。
> - 函数声明与函数表达式的提升行为不同。

## 一、先看一段代码

观察下面的代码及其解释：

```js
getName(); // Namaste Javascript
console.log(x); // undefined
var x = 7;
function getName() {
  console.log("Namaste Javascript");
}
```

在许多其他语言中，这应该直接报错，因为访问一个尚未创建（定义）的东西根本不可能。但在 JS 中，我们知道在==内存创建阶段==，==它会给变量赋 undefined==，并把函数的内容放进函数的内存中；==到了执行阶段，它再执行要求执行的内容==。

这里执行是逐行进行的，而不是编译之后再执行，所以它只能打印 undefined，别的什么也打印不出来。这一现象并不是错误。不过，如果把 `var x = 7;` 去掉，它就会报错：`Uncaught ReferenceError: x is not defined`。

## 二、什么是变量提升

**变量提升（Hoisting）** 是一个概念，它让我们能够==在初始化/赋值之前就取得变量和函数的值，而不会报错==。这得益于执行上下文的第一个阶段（内存创建阶段）。

> [!note] 核心结论
> 变量提升的本质：代码执行之前，内存创建阶段已经把变量初始化为 undefined，把整个函数代码放入内存。

## 三、变量与函数在内存中的初始化

上一讲我们学到，执行上下文分两个阶段创建：在代码执行之前，内存就已经创建好了。因此：

- 对于**变量**，它会被初始化为 `undefined`；
- 对于**函数**，整段函数代码会被放进内存。

例如：

```js
getName(); // Namaste JavaScript
console.log(x); // Uncaught Reference: x is not defined.
console.log(getName); // f getName(){ console.log("Namaste JavaScript); }
function getName() {
  console.log("Namaste JavaScript");
}
```

## 四、函数表达式与函数声明的区别

再观察一个不同的例子，试着理解输出结果：

```js
getName(); // Uncaught TypeError: getName is not a function
console.log(getName);
var getName = function () {
  console.log("Namaste JavaScript");
};
// 第一行本身就会抛出 TypeError，因此代码不会执行。
```

> [!warning] 易错点
> 在函数表达式中，`getName` 在内存创建阶段只是一个值为 `undefined` 的变量，因此调用 `getName()` 会抛出 `TypeError: getName is not a function`。只有函数声明才会把整段函数代码提升到内存中。

| 写法 | 内存创建阶段存了什么 | 能否在定义前调用 |
| --- | --- | --- |
| 函数声明 `function getName() {}` | 整段函数代码 | 可以 |
| 函数表达式 `var getName = function () {}` | `undefined` | 不可以，抛出 TypeError |
