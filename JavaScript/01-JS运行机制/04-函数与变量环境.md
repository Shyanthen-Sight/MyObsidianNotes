# 第 4 讲：函数与变量环境（Functions and Variable Environments）

> [!abstract] 本讲要点
> - 每个函数调用都会创建自己的局部执行上下文，拥有独立的变量环境。
> - 不同执行上下文中的同名变量互不影响。
> - 函数调用时局部上下文入栈，执行完毕后出栈并被删除。
> - 全局执行上下文最后被删除，程序结束。

## 一、示例代码

```js
var x = 1;
a();
b(); // 我们在定义函数之前就调用了它们。由于变量提升，这可以正常工作。
console.log(x); // 3

function a() {
  var x = 10; // 由于有独立的执行上下文，这是局部作用域
  console.log(x); // 1
}

function b() {
  var x = 100;
  console.log(x); // 2
}
```

## 二、输出结果

> 10
>
> 100
>
> 1

## 三、从执行上下文的角度看代码流程

- 全局执行上下文（Global Execution Context，GEC）被创建（即包含内存和代码两个子部分的大盒子），并被压入调用栈。

> Call Stack：GEC

- 在 GEC 的第一阶段（内存阶段），变量 x 为 undefined，a 和 b 的值被初始化为各自完整的函数代码。

- 在 GEC 的第二阶段（执行阶段），当函数被调用时，会创建一个新的局部执行上下文（Local Execution Context）。在 `x = 1` 赋给 GEC 的 x 之后，调用 `a()`。于是 a 的局部执行上下文在 GEC 的代码部分中被创建。

> Call Stack：[GEC, a()]

- 对于局部执行上下文，一个完全不同的 x 变量在第一阶段被赋为 undefined（即 a() 内部的 x），第二阶段它被赋为 10 并在控制台打印。打印之后没有更多命令要执行，所以 a() 的局部执行上下文从 GEC 和调用栈中都被移除。

> Call Stack：GEC

- 光标回到 b() 函数调用处，重复相同的步骤。

> Call Stack：[GEC, b()] -> GEC（在控制台打印了又一个完全不同的 x 值 100 之后）

- 最后 GEC 被删除，并从调用栈中移除，程序结束。

> [!note] 核心结论
> 每个函数执行上下文都有自己的变量环境，因此 a() 和 b() 中的 x 与全局的 x 是三份互不影响的变量。
