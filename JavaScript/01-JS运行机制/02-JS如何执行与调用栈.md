# 第 2 讲：JS 如何执行与调用栈（How JS is executed & Call Stack）

> [!abstract] 本讲要点
> - JS 程序运行时，会先创建一个全局执行上下文（Global Execution Context）。
> - 执行上下文分两个阶段创建：内存创建阶段和代码执行阶段。
> - 每次函数调用都会创建新的执行上下文，函数返回后该上下文被删除。
> - JS 通过调用栈（Call Stack）管理执行上下文的创建与删除。

## 一、执行上下文的两个阶段

运行一个 JS 程序时，会创建一个**全局执行上下文（Global Execution Context）**。执行上下文分两个阶段创建：

- **内存创建阶段（Memory Creation Phase）**：JS 为变量和函数分配内存。
- **代码执行阶段（Code Execution Phase）**。

## 二、示例代码

下面结合这段代码及其执行步骤来说明：

```js
var n = 2;
function square(num) {
  var ans = num * num;
  return ans;
}
var square2 = square(n);
var square4 = square(4);
```

## 三、内存创建阶段

JS 做的**第一件**事就是**内存创建阶段**。它会来到上面代码的第一行，为变量 **'n'** **分配一块内存空间**，然后来到第二行，为**函数 'square'** **分配内存空间**。

- 为 **n** 分配内存时，它存储的是 **'undefined'**——这是给 'n' 的一个特殊值。
- 为 **'square'** 分配内存时，它把**函数的全部代码**存进这块内存空间。

接着，由于 square2 和 square4 也是变量，JS 同样为它们分配内存并存入 'undefined'。至此，第一阶段也就是内存创建阶段结束。

## 四、代码执行阶段

现在进入**第二阶段**，也就是代码执行阶段，JS 开始逐行遍历整个代码。

- 当遇到 `var n = 2` 时，它把 2 赋给 'n'。在此之前，'n' 的值一直是 undefined。
- 对于函数，没有什么需要执行的，因为这些行已经在内存创建阶段处理过了。

来到第 6 行，即 **`var square2 = square(n)`**。这里**函数与其他语言略有不同：会完全创建一个新的执行上下文。** 在这个新的执行上下文中，内存创建阶段会为 num 和 ans 这两个变量分配内存，并放入 undefined。然后在这个执行上下文的代码执行阶段，先把 2 赋给 num；接着 `var ans = num * num` 会把 4 存入 ans；之后 `return ans` 把程序的控制权交还给调用该函数的位置。

![执行上下文第二阶段](phase2.jpg "执行上下文第二阶段")

当遇到 **return** 关键字时，它把控制权返回给调用行，同时**函数的执行上下文会被删除**。

square4 会重复同样的过程；等这一切结束后，全局执行上下文也会被销毁。

## 五、调用栈（Call Stack）

- JavaScript 借助**调用栈（Call Stack）**来管理执行上下文的创建与删除。
- 调用栈是一种机制，用于记录脚本中调用多个函数时所处的位置。
- 调用栈维护执行上下文的执行顺序。它也被称为程序栈（Program Stack）、控制栈（Control Stack）、运行时栈（Runtime Stack）、机器栈（Machine Stack）、执行上下文栈（Execution Context Stack）。

> [!tip] 记忆要点
> 调用栈就是管理执行上下文的后进先出栈：函数调用时入栈，函数返回时出栈。

> [!note] 核心结论
> 全局执行上下文最先创建、最后销毁；每调用一次函数就创建一个新的执行上下文，函数返回后它立即被删除。
