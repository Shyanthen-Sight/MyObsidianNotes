# 第 16 讲：JS 引擎揭秘与 Google V8 架构（JS Engine Exposed, Google's V8 Architecture）

> [!abstract] 本讲要点
> - JS 之所以无处不在，是因为有 JavaScript 运行时环境（JRE）。
> - JRE 包含 JS 引擎、连接外部环境的 API、事件循环、回调队列、微任务队列等。
> - JS 引擎内部的代码要经过解析、编译、执行三个阶段。
> - V8 的解释器叫 Ignition，编译器叫 Turbo Fan，垃圾回收器叫 Orinoco。

## 一、JavaScript 运行时环境（JRE）

- 由于有 JavaScript 运行时环境（JavaScript Runtime Environment，JRE），JS 可以说无处不在：从智能手表到机器人，再到浏览器。
- JRE 就像一个巨大的容器，里面包含了运行 JavaScript 代码所需要的一切。
- JRE 由 JS 引擎（JRE 的心脏 ❤️）、一组用于连接外部环境的 API、事件循环、回调队列、微任务队列等组成。
- 浏览器能够执行 JavaScript 代码，正是因为它拥有 JavaScript 运行时环境。

## 二、ECMAScript 与各家的 JS 引擎

- ECMAScript 是 JS 的规范制定组织。它有一套规则，所有 JS 引擎都要遵循，例如 Chakra（Internet Explorer）、V8 引擎（Edge）、SpiderMonkey（Firefox，由 JS 的创造者本人创建的第一个 JavaScript 引擎）、v8（Chrome）。
- JavaScript 引擎不是一台机器。它是用底层语言（例如 C++）编写的软件，接收 JS 的高层代码，并输出底层的机器码。

## 三、JavaScript 引擎内部的三个阶段

JavaScript 引擎中的代码要经过 3 个步骤：**解析（Parsing）**、**编译（Compilation）**和**执行（Execution）**。

### 1. 解析（Parsing）

代码会被拆分成词法单元（token）。在 `"let a = 7"` 中，`let`、`a`、`=`、`7` 都是 token。此外还有一个语法解析器（syntax parser），它接收代码并转换成 AST（Abstract Syntax Tree，抽象语法树）。AST 是一个 JSON，包含 type、start、end、body 等键值（看起来像 package.json，但描述的是 JS 中的一行代码，其实不太重要）。（可以访问 astexplorer.net，把一行代码转换成 AST。）

### 2. 编译（Compilation）

JS 有一种机制叫即时编译（Just-in-time，JIT）——同时使用解释器和编译器。而且编译与执行是同时进行的。上一步得到的 AST 会交给解释器，解释器把高层代码转换成字节码（byte code）并进入执行。在解释的同时，编译器也协同工作，在运行时编译并生成优化后的代码。**JavaScript 真的会编译吗？** 答案是响亮的**会**。更多信息见：[链接 1](https://github.com/getify/You-Dont-Know-JS/blob/2nd-ed/get-started/ch1.md#whats-in-an-interpretation)、[链接 2](https://web.stanford.edu/class/cs98si/slides/overview.html)、[链接 3](https://blog.greenroots.info/javascript-interpreted-or-compiled-the-debate-is-over-ckb092cv302mtl6s17t14hq1j)。JS 过去只有解释器，但现在同时拥有编译器和解释器来编译与解释代码，这让 JS 成为一门 JIT 编译语言，可谓集两者之长。

> [!note] JavaScript 确实会编译
> JS 引擎同时使用解释器和编译器，编译与执行并肩进行，因此 JS 是一门 JIT 编译语言。

### 3. 执行（Execution）

执行需要两个组件：内存堆（Memory Heap，存放所有内存的地方）和调用栈（Call Stack，与前几讲相同）。此外还有垃圾回收器（Garbage Collector），它使用一种叫**标记清除（Mark and Sweep）**的算法。
