# 第 14 讲：回调函数与事件监听（Callback Functions in JS ft. Event Listeners）

> [!abstract] 本讲要点
> - 回调函数是把函数 A 作为参数传给函数 B，由 B 获得调用 A 的权限。
> - 回调让同步、单线程的 JavaScript 能够完成异步操作。
> - 所有函数都通过调用栈执行，阻塞调用栈就等于阻塞主线程。
> - 事件监听器会形成闭包，不再需要时应移除监听器以便垃圾回收。

## 一、回调函数（Callback Functions）

- 函数是一等公民，也就是说，可以取一个函数 A 并把它传给另一个函数 B。这里的 A 就是回调函数（Callback Function）。本质上，我是把调用函数 A 的权限交给了函数 B。这个回调函数让我们得以在**同步（Synchronous）**世界中拥有整个**异步（Asynchronous）**世界的能力。

```js
setTimeout(function () {
  console.log("Timer");
}, 1000); // 第一个参数是回调函数，第二个参数是定时器时间。
```

- JS 是一门同步且单线程的语言。但借助回调，我们可以在 JS 中做异步的事情。

```js
setTimeout(function () {
  console.log("timer");
}, 5000);
function x(y) {
  console.log("x");
  y();
}
x(function y() {
  console.log("y");
});
// x y timer
```

- 在调用栈中，首先出现的是 x 和 y。代码执行完毕后它们离开，栈变为空。然后在 5 秒之后（从开始算起），一个匿名函数突然出现在栈中，也就是 setTimeout 的回调。
- 这三个函数都是通过调用栈执行的。如果某个操作阻塞了调用栈，就称为**阻塞主线程（blocking the main thread）**。
- 假设 x() 需要运行 30 秒，那么 JS 必须等它结束，因为它只有一个调用栈、一个主线程。**永远不要阻塞主线程。**
- 对于耗时的函数（例如 setTimeout），始终使用**异步**方式。

```js
// 回调的另一个例子
function printStr(str, cb) {
  setTimeout(() => {
    console.log(str);
    cb();
  }, Math.floor(Math.random() * 100) + 1);
}
function printAll() {
  printStr("A", () => {
    printStr("B", () => {
      printStr("C", () => {});
    });
  });
}
printAll(); // A B C // 按顺序输出
```

> [!note] 回调的本质
> 函数 A 被传给函数 B，B 因此获得调用 A 的权限。正是回调让同步的 JS 具备了异步能力。

## 二、事件监听（Event Listener）

- 我们将在 HTML 中创建一个按钮，并给它绑定事件。

```js
// index.html
<button id="clickMe">Click Me!</button>;

// 在 index.js 中
document.getElementById("clickMe").addEventListener("click", function xyz() {
  // 当 click 事件发生时，这个回调函数（xyz）会被放入调用栈
  console.log("Button clicked");
});
```

- 让我们实现一个自增计数器按钮。
  - 使用全局变量（不好，因为任何人都能修改它）

    ```js
    let count = 0;
    document
      .getElementById("clickMe")
      .addEventListener("click", function xyz() {
        console.log("Button clicked", ++count);
      });
    ```

  - 使用闭包实现数据抽象

    ```js
    function attachEventList() {
      // 为闭包创建新的函数
      let count = 0;
      document
        .getElementById("clickMe")
        .addEventListener("click", function xyz() {
          console.log("Button clicked", ++count); // 现在回调函数与外部作用域（count）形成了闭包
        });
    }
    attachEventList();
    ```

## 三、垃圾回收与 removeEventListener

- 事件监听器很重，因为它们会形成闭包。因此即使调用栈为空，事件监听器也不会释放分配给 count 的内存，因为它不知道自己什么时候可能还会用到 count。所以，当我们不再需要事件监听器时，就应该移除它们（被垃圾回收）。页面上的 onClick、onHover、onScroll 等监听器过多会严重拖慢性能。
