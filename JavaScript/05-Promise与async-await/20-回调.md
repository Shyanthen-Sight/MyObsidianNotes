# 第 20 讲：回调（Callback）

> [!abstract] 本讲要点
> - 回调分为两部分：好的一面是在 JavaScript 中编写异步代码的关键；坏的一面会带来回调地狱与控制反转。
> - JavaScript 是同步、单线程的语言，只有一个调用栈，一次只能执行一件事。
> - 通过 `setTimeout` 配合回调，可以延迟某一行代码的执行。
> - 多层嵌套的回调形成回调地狱，也叫「厄运金字塔」，代码难以维护。
> - 控制反转（Inversion of Control）指使用回调时，我们把代码的控制权交给了别人。

## 一、回调的两面

回调（Callback）可以分为两部分：

1. **回调好的一面**：在 JavaScript 中编写异步代码时，回调极其重要。
2. **回调坏的一面**：使用回调会遇到以下问题：
   - 回调地狱（Callback Hell）
   - 控制反转（Inversion of Control）

理解回调坏的一面，对下一讲学习 Promise 极其重要。

> [!note] JavaScript 是同步单线程的
> JavaScript 是同步、单线程的语言。它一次只能做一件事，只有一个调用栈，一次只能执行一件事。我们交给 JavaScript 的任何代码，都会被 JavaScript 引擎快速执行，它不会等待。

```js
console.log("Namaste");
console.log("JavaScript");
console.log("Season 2");
// Namaste
// JavaScript
// Season 2

// 💡 它打印得这么快，是因为「时间、潮水与 JavaScript 都不等任何人」。
```

但如果我们需要延迟某一行的执行，就可以借助回调，怎么做呢？

```js
console.log("Namaste");
setTimeout(function () {
  console.log("JavaScript");
}, 5000);
console.log("Season 2");
// Namaste
// Season 2
// JavaScript

// 💡 这里我们通过 setTimeout 的回调方式，延迟了代码的执行。
```

## 二、电商 Web 应用场景

假设一个电商网站的场景：一位用户正在下单，他往购物车里加了鞋子、裤子和 kurta（一种长衫），现在他要下订单。那么后端的情况可能长这样。

```js
const cart = ["shoes", "pants", "kurta"];
// 下单分为两步
// 1. 创建订单
// 2. 进入支付

// 代码可能长这样：
api.createOrder();
api.proceedToPayment();
```

这里假设只有订单创建成功后，我们才能进入支付，也就是说二者存在依赖关系。那么该如何管理这种依赖？

回调可以救场，怎么做？

```js
api.createOrder(cart, function () {
  api.proceedToPayment();
});
// 💡 这里 `createOrder` API 先创建订单，然后由它负责调用 `api.proceedToPayment()`，这就是回调的思路。
```

再把问题弄复杂一点：如果支付完成后，你还要调用 `api.showOrderSummary()` 展示订单摘要，而它现在又依赖 `api.proceedToPayment()`。

那么我的代码就应该长这样：

```js
api.createOrder(cart, function () {
  api.proceedToPayment(function () {
    api.showOrderSummary();
  });
});
```

那如果之后还要更新钱包，而它又依赖 `showOrderSummary` 呢？

```js
api.createOrder(cart, function () {
  api.proceedToPayment(function () {
    api.showOrderSummary(function () {
      api.updateWallet();
    });
  });
});
// 💡 回调地狱
```

## 三、回调地狱、厄运金字塔与控制反转

当我们有庞大的代码库、多个彼此依赖的 API 时，就会掉进回调地狱。

这些代码很难维护。

这种回调地狱结构也被称为**厄运金字塔（Pyramid of Doom）**。

到这里我们对回调地狱的概念已经比较熟悉了，现在来讨论「控制反转」。要真正理解 Promise 的概念，这一点非常重要。

> [!note] 什么是控制反转
> 控制反转的意思是：当我们使用回调时，就失去了对代码的控制权。

我们用示例代码和注释来理解：

```js
api.createOrder(cart, function () {
  api.proceedToPayment();
});

// 💡 这里我们创建了订单，然后盲目信任 `createOrder` 会去调用 `proceedToPayment`。

// 💡 这很危险，因为 `proceedToPayment` 是代码中的重要部分，而我们却盲目信任 `createOrder` 去调用并处理它。

// 💡 当我们把一个函数作为回调传入时，本质上我们依赖于父函数，指望它负责执行那个函数。这就叫「控制反转」，因为我们依赖那个函数。如果父函数停止工作了呢？如果它是由另一位程序员写的呢？如果回调执行了两次，或者根本没有执行呢？

// 💡 下一讲我们会看到如何解决这类问题。
```

> [!note] 异步编程与回调
> JavaScript 中的异步编程之所以存在，正是因为回调的存在。
