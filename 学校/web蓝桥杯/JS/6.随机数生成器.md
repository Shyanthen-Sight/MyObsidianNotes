# 随机数生成器：`Math.random` 映射区间 + 去重凑数

> [!info] 原题
> 蓝桥云课 · 随机数生成器（题目 1842）
> 第十三届（2022）蓝桥杯大赛 Web 应用与开发 · 第二次线上模拟赛 · 大学组 · 算法实现
> [题目链接](https://www.lanqiao.cn/problems/1842/learning/?page=1&first_category_id=2&tags=JavaScript,%E5%BC%82%E6%AD%A5&tag_relation=union)
>
> 备注：题目页需登录才能看全，本题面依据公开题解与题目说明整理。链接里的 `异步` 只是题库筛选标签，本题实际只考 `Math.random`、取整与数组去重，不涉及 Promise / `async`。

> [!summary] 速记版
> ```js
> const getRandomNum = function (min, max, countNum) {
>   const arr = [];
>   while (arr.length < countNum) {
>     const num = Math.floor(Math.random() * (max - min + 1)) + min;
>     if (!arr.includes(num)) arr.push(num);
>   }
>   return arr;
> };
> module.exports = getRandomNum; // 请勿删除
> ```
> - **区间公式**：`Math.floor(Math.random() * (max - min + 1)) + min`，两端都能取到。
> - **去重**：`includes` 查一下，重复就丢掉，`while` 自然补抽。
> - **循环条件**：盯住 `arr.length < countNum`，不是循环 `countNum` 次。
> - **`module.exports` 必须保留**：判分环境用 Node `require` 这个文件取函数。
> - 常见死法：漏了 `+1`（永远取不到 `max`）、用 `for` 循环不重试（数量不够）、删掉导出。

## 考察内容

- **`Math.random()`**：返回 `[0, 1)` 的伪随机浮点数，含 0、不含 1。
- **区间映射**：把 `[0, 1)` 线性拉伸到 `[min, max]`，再取整。
- **取整函数**：`Math.floor` / `Math.round` / `parseInt` 的差别，为什么这里必须用 `floor`。
- **数组查重**：`includes()` / `indexOf()` / `Set` 三种去重入口。
- **循环终止条件**：抽到重复值时如何"补抽"，保证结果长度正好是 `countNum`。
- **CommonJS 导出**：`module.exports` 与判分环境的关系。

## 三、解法拆解

### 1. 把 `[0, 1)` 映射成 `[min, max]` 的整数

`Math.random()` 只会给你 `0 ≤ x < 1`。要换成区间内的整数，分三步：

```
Math.random()                    →  [0, 1)
× (max - min + 1)                →  [0, max - min + 1)
Math.floor(...)                  →  0, 1, 2, …, max - min
+ min                            →  min, min + 1, …, max
```

以 `min = 1, max = 30` 为例：

| 步骤 | 范围 |
| --- | --- |
| `Math.random()` | `[0, 1)` |
| `× 30`（`30 - 1 + 1`） | `[0, 30)` |
| `Math.floor` | `0 … 29` |
| `+ 1` | `1 … 30` |

```js
const num = Math.floor(Math.random() * (max - min + 1)) + min;
```

**为什么要 `+1`**：`max - min` 只有 29 个整数间隔，`[0, 29)` 向下取整只能到 28，再加 `min` 最多到 29——`30` 永远抽不到。加 1 后长度变成 30，才覆盖 `0 … 29`。

**为什么用 `floor` 不用 `round`**：`Math.round` 会把两端各砍掉一半概率。比如 `Math.round(Math.random() * 10)`，`0` 和 `10` 只有在原值落在 `[-0.5, 0.5)` / `[9.5, 10.5)` 时才出现，概率只有中间数字的一半，分布不均衡。`floor` 把每个小格等分，概率均等。

区间速查：

| 目标 | 写法 |
| --- | --- |
| `[0, 1)` 浮点 | `Math.random()` |
| `[0, n)` 整数 | `Math.floor(Math.random() * n)` |
| `[0, n]` 整数 | `Math.floor(Math.random() * (n + 1))` |
| `[min, max]` 整数 | `Math.floor(Math.random() * (max - min + 1)) + min` |

### 2. 去重：抽到重复的就不收

```js
if (!arr.includes(num)) {
  arr.push(num);
}
```

`includes` 用 SameValueZero 比较，数字直接比大小，正合本题。兼容老环境可以换 `arr.indexOf(num) === -1`，语义一样。

### 3. 循环：长度没到就继续抽

```js
while (arr.length < countNum) {
  const num = Math.floor(Math.random() * (max - min + 1)) + min;
  if (!arr.includes(num)) arr.push(num);
}
```

关键在**循环条件盯的是"结果数组长度"**，不是"抽了几次"。抽到重复值被 `if` 丢掉后，长度没涨，`while` 会继续——这就是"补抽"。如果写成固定循环 `countNum` 次，每次重复都白抽，最终数组会短一截。

### 4. 导出：给判分环境留入口

```js
module.exports = getRandomNum; // 请勿删除
```

判分脚本在 Node 里 `require` 这个文件，拿 `module.exports` 上的函数跑用例。浏览器页面本身不靠它，但删掉它判分就找不到函数。

四步连成一条链：

```
随机浮点 [0,1) → 拉伸取整 → [min,max] 整数
                      ↓
            已存在？── 是 → 丢弃，重抽
                │否
                ↓
            push 进数组
                      ↓
        arr.length < countNum ? 继续 : 返回
```

> [!note] 浏览器控制台里的 `module is not defined`
> `module.exports` 是 CommonJS 语法，浏览器没有 `module` 对象。`index.js` 在 `<head>` 里跑到最后一行会抛 `ReferenceError`，但此时 `getRandomNum` 已经定义完成，后面的内联脚本照常能调用它，页面正常出结果。这条红字不影响做题，也**不要**为了消掉它去删导出。

## 四、完整参考实现

### js/index.js

```js
/**
 * 封装函数，函数名 getRandomNum(min, max, countNum)
 * 生成 min~max 范围的 countNum 个不重复的随机数，存入数组并返回
 */
const getRandomNum = function (min, max, countNum) {
  const arr = [];

  while (arr.length < countNum) {
    const num = Math.floor(Math.random() * (max - min + 1)) + min;
    if (!arr.includes(num)) {
      arr.push(num);
    }
  }

  return arr;
};

module.exports = getRandomNum; // 请勿删除
```

### index.html

```html
<!DOCTYPE html>

      var testArr = getRandomNum(1, 30, 3);

      testArr = getRandomNum(1, 100, 10);
      document.write("<h1>1-100 以内的 10 个随机数：" + testArr + "</h1>");

```

> [!warning] `countNum` 不能超过区间容量
> `max - min + 1` 是可选整数总数。如果 `countNum` 比它还大，`while` 永远凑不齐，直接死循环把页面卡死。题目用例不会这么出，但自己写通用函数时该加一句守卫：
> ```js
> if (countNum > max - min + 1) throw new Error("范围内没有这么多不重复的数");
> ```

## 五、几种等价写法

### 写法 A：`while` + `includes`（推荐）

```js
while (arr.length < countNum) {
  const num = Math.floor(Math.random() * (max - min + 1)) + min;
  if (!arr.includes(num)) arr.push(num);
}
```

最短、意图最清楚：凑够为止，重复就丢。本题标准答案。

### 写法 B：`while` + `indexOf`

```js
while (arr.length < countNum) {
  const num = Math.floor(Math.random() * (max - min + 1)) + min;
  if (arr.indexOf(num) === -1) arr.push(num);
}
```

和 A 等价，只是 `includes` 是 ES2016 才有的，`indexOf` 兼容性更老。

### 写法 C：用 `Set` 去重

```js
const set = new Set();
while (set.size < countNum) {
  set.add(Math.floor(Math.random() * (max - min + 1)) + min);
}
return [...set];
```

`Set` 自动去重，连 `if` 都省了。缺点是最后还要展开成数组，且顺序就是插入顺序。

### 写法 D：先造全集再洗牌（区间密集时更快）

```js
const pool = [];
for (let i = min; i <= max; i++) pool.push(i);

for (let i = pool.length - 1; i > 0; i--) {
  const j = Math.floor(Math.random() * (i + 1));
  [pool[i], pool[j]] = [pool[j], pool[i]];
}

return pool.slice(0, countNum);
```

Fisher–Yates 洗牌，取前 `countNum` 个。当 `countNum` 接近 `max - min + 1` 时，拒绝采样会越来越难抽到新数，这种写法反而稳定在 O(n)。

### 写法 E：`for` 循环 + 撞车回退

```js
for (let i = 0; i < countNum; i++) {
  const num = Math.floor(Math.random() * (max - min + 1)) + min;
  if (arr.includes(num)) {
    i--;              // 撞车了，这次不算，重来
  } else {
    arr.push(num);
  }
}
```

能跑，但可读性最差。**关键是 `i--`**：网上大量"标准答案"漏了这一句，结果生成的数量不足。

### 对比

| 写法 | 是否正确 | 复杂度 | 备注 |
| --- | --- | --- | --- |
| A `while` + `includes` | ✅ | 期望 O(countNum)，密集时退化 | 推荐 |
| B `while` + `indexOf` | ✅ | 同 A | 兼容性更好 |
| C `Set` | ✅ | 同 A | 代码最短 |
| D 洗牌抽样 | ✅ | O(max−min+1) | 区间密集时更稳 |
| E `for` + `i--` | ✅ | 同 A | 别漏 `i--` |
| 固定 `for` 无重试 | ❌ | — | 重复值被丢，数量不足 |

## 六、易错点

> [!warning] 这题的坑不在"会不会随机"，在"区间端点"和"凑够数量"

1. **漏掉 `+1`**
   `Math.random() * (max - min) + min` 取整后最大只能到 `max - 1`，`max` 永远抽不到。本题两组用例都含右端点，抽不到就有概率被判错。

2. **用 `Math.round` 替代 `Math.floor`**
   两端概率减半，分布不均。判分若做大量抽样统计（或单纯要求"能取到 max"），`round` 虽然能取到端点，但概率模型不对；标准写法是 `floor`。

3. **`for` 循环不重试**
   固定循环 `countNum` 次、遇到重复直接跳过，结果数组会短于 `countNum`。要么用 `while (arr.length < countNum)`，要么在 `for` 里 `i--`。

4. **漏 `return arr` 或返回了字符串**
   骨架里已有 `return arr`，别手滑改成 `return arr.join(",")` 或 `console.log`。

5. **删掉 `module.exports`**
   页面能跑，判分拿不到函数。题目特意标注"请勿删除"。

6. **用 `parseInt` 处理数字**
   `parseInt` 会先把数字转成字符串再解析，遇到 `1e-7` 这类科学计数法会解析成 `1`。本题范围通常大于 0 不会触发，但通用写法用 `Math.floor` 更稳。

7. **`countNum` 大于区间容量**
   `getRandomNum(1, 5, 6)` 永远凑不齐，死循环。自己封装通用函数时要加守卫。

8. **改了不该改的文件**
   题面明确"切勿修改文件名称、文件夹路径"。只动 `js/index.js` 的函数体，别重命名、别动 `index.html` 的调用。

9. **把 `min` / `max` 当成"个数"**
   签名是 `(min, max, countNum)`，第三个参数才是数量。`getRandomNum(1, 30, 3)` 是"1 到 30 里取 3 个"，不是"取 1、30、3"。

## 七、评测怎么过

- 只补 `getRandomNum` 函数体，函数名、参数、`module.exports` 都别动。
- 先跑页面：应输出两行，第一行 3 个数、第二行 10 个数，肉眼确认无重复。
- 再跑断言：长度、去重、范围、整数四项全过。
- 保持 Web Server 运行，再点「提交检测」——服务停了系统访问不到页面，会判失败。
- 若结果偶尔少一个数，优先怀疑 `for` 循环没重试；若最大值从不出现，优先怀疑漏了 `+1`。

## 八、一句话总结

> **`Math.floor(Math.random() * (max - min + 1)) + min` 负责"范围内的整数"，`while (arr.length < countNum)` 加 `includes` 查重负责"不重复且够数"，最后 `return arr` 并保留 `module.exports`。** 记住 `+1` 和"盯长度不盯次数"，这题就不会翻车。
