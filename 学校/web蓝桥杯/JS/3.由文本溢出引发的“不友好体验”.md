# 由文本溢出引发的“不友好体验”：JS 定长切割 + 省略号

> [!info] 原题
> 蓝桥云课 · 由文本溢出引发的“不友好体验”（题目 2158）
> 蓝桥杯大赛 Web 应用与开发
> [题目链接](https://www.lanqiao.cn/problems/2158/learning/?page=1&first_category_id=2&tags=CSS3&tag_relation=union)
>
> 备注：本题官方要求 CSS3；本笔记按要求只保留 JavaScript 实现。

> [!summary] 速记版
> ```js
> const MAX_LEN = 22;                       // 两行大约能放的字符数
> const el = document.querySelector('.more2_info_name');
> const tag = el.querySelector('.more2_info_self');   // “新课”标签
>
> const raw = el.textContent.replace(tag.textContent, '').trim();
> el.textContent = raw.slice(0, MAX_LEN) + '…';       // 切割 + 拼省略号
> el.prepend(tag);                                     // 把标签放回最前面
> ```
> - **思路**：先取纯文本 → 按固定长度 `slice` → 去掉超出部分 → 末尾拼 `…`。
> - `MAX_LEN = 22` 不是随便写的：本页实测 22 个字 + `…` 正好两行，23 个就变成三行。
> - `textContent = ...` 会把 `<i>新课</i>` 一起删掉，所以要先拿到标签、切完再 `prepend` 回去。
> - 用 `…`（一个字符）而不是 `...`（三个字符），省下的宽度能多放一个字。
> - 字符数是"数出来"的：`slice` 按 UTF-16 码元切，中文没问题，emoji 要另外处理。

## 考察内容

- **读取文本**：`textContent`、`innerText`、文本节点的区别。
- **字符串处理**：`trim()`、`slice(start, end)`、`+` 拼接。
- **DOM 写回**：`textContent = ...` 的破坏性，以及 `prepend()` 恢复子元素。
- **定长切割的思路**：长度从哪来、为什么是 22、怎么校准。
- **文本与标签混排**：`<p>` 里既有 `<i>` 又有文本时，如何只切文本。
- **边界**：省略号占位、中英文宽度差异、emoji 代理对、内容/宽度变化后的重新校准。

## 一、题目给了什么

### 目标结构

```html
<div class="more2_info">
    <p class="more2_info_name">
        <i class="more2_info_self">新课</i>
        随着前端的发展，UI 框架经历了刀耕火种的时代，层出不穷的 UI 框架让前端再次大放异彩。ElementUI
        作为前端发展史上最为经典的组件库之一，学习并了解它是如何构建的，以及它的源码是如何搭建出 UI 组件的，都将为我们今后的发展与应用提供可借鉴之处！
    </p>
    <div class="more2_info_price more2_info_price_plus more2_info_price_newcomer">
        <div class="mod_price"><i>¥</i><span class="more2_info_price_txt">72.<span
                    class="more2_info_price_txt-decimal">00</span></span></div>
    </div>
</div>
```

### 决定"多长"的几个尺寸

| 项目 | 值 | 说明 |
| --- | --- | --- |
| 卡片宽度 | `190px` | `.more2_item` |
| 左右内边距 | `10px × 2` | 文本实际可用宽度 `170px` |
| 字号 | `14px` | 一个汉字约占 `14px` |
| 行高 | `24px` | 两行 = `48px` |
| 段落高度 | `48px` | 正好两行，超出部分会画到盒外 |
| 原文本长度 | 约 138 个字符 | 排出来约 11 行 |
| 标签宽度 | 约 `38px` | "新课" + 内边距 + 右外边距，占第一行开头 |

> [!important] 定长切割的关键就是算清"一行能放几个字"
> `170 ÷ 14 ≈ 12`，两行约 24 个字。但第一行开头被"新课"标签占掉约 3 个字的位置，末尾还要留 1 个字给省略号——所以实际能保留的字数在 **20～22** 之间，最终以实测为准。

## 二、思路拆解

整个方案只有四步：

```mermaid
flowchart LR
    A["取纯文本<br/>去掉标签文字"] --> B["按长度切<br/>slice(0, 22)"]
    B --> C["末尾拼省略号<br/>+ '…'"]
    C --> D["写回 DOM<br/>并放回标签"]
```

### 第 1 步：取出真正的文本

```js
const el = document.querySelector('.more2_info_name');
const tag = el.querySelector('.more2_info_self');
const raw = el.textContent.replace(tag.textContent, '').trim();
```

- `el.textContent` 会拿到 `<p>` 里所有文字，包括标签里的"新课"。
- 先用 `replace` 把"新课"去掉，剩下的才是要截断的正文。
- `trim()` 去掉源码里换行、缩进留下的首尾空白，否则会占掉字符配额。

### 第 2 步：确定"一定长度"

```js
const MAX_LEN = 22;
```

这个数字来自实测，不是拍脑袋：

- 可用宽度 `170px`，14px 汉字一行约 `12` 个；
- 两行理论容量 `24` 个；
- "新课"标签占第一行约 `38px`，相当于 3 个字；
- 末尾 `…` 还要占 1 个字的宽度；
- `24 - 3 - 1 = 20`，再算上 `UI` 这类窄字符多挤出的约 2 个字，最终约 `22`。

实测（headless Chrome，本页真实样式）：

| 保留字符数（不含 `…`） | 渲染行数 | 段落高度 | 结果 |
| --- | --- | --- | --- |
| 16 ~ 22 | 2 行 | 48px | ✅ 符合要求 |
| 23 | 3 行 | 72px | ❌ 多出一行 |
| 24 及以上 | 3 行 | 72px | ❌ 多出一行 |

所以 `MAX_LEN = 22` 是"刚好塞满两行"的上限；保守一点取 `20` 或 `21` 也能过，只是会早一点出现省略号。

### 第 3 步：切割并拼省略号

```js
const kept = raw.slice(0, MAX_LEN);   // 只留前 22 个字符
el.textContent = kept + '…';          // 超出部分直接丢弃
```

- `slice(0, 22)` 取下标 `0 ~ 21`，共 22 个字符；超出部分不进入结果。
- `slice` 不会修改原字符串，返回新字符串。
- 用 `…` 而不是 `...`：前者是 1 个字符，后者是 3 个，多占两格宽度。
- 如果第 22 个字符是空格，最好先 `replace(/\s+$/, '')` 再去拼省略号，避免出现"空格 + …"。

### 第 4 步：保住"新课"标签

这是最容易翻车的一步。`el.textContent = ...` 会把 `<p>` 的所有子节点**全部替换成一个文本节点**，`<i class="more2_info_self">新课</i>` 会消失。

```js
el.textContent = raw.slice(0, MAX_LEN) + '…';  // 此时 <i> 已经没了
el.prepend(tag);                                // tag 变量还引用着原元素，放回最前面
```

- 赋 `textContent` 之前先把 `tag` 元素保存到变量里；
- 元素从 DOM 移除后，变量仍然引用它，可以再次插入；
- `prepend()` 把它放到第一个子节点位置，恢复"标签在文字前"的顺序。

## 三、完整代码

```js
// 1. 拿到段落和“新课”标签
const el = document.querySelector('.more2_info_name');
const tag = el.querySelector('.more2_info_self');

// 2. 取出纯正文（去掉标签文字和首尾空白）
const raw = el.textContent.replace(tag.textContent, '').trim();

// 3. 定长切割：只保留前 22 个字符，末尾拼省略号
const MAX_LEN = 22;
const kept = raw.slice(0, MAX_LEN).replace(/\s+$/, '');
el.textContent = kept + '…';

// 4. 把标签放回最前面
el.prepend(tag);
```

### 放在哪里

题目 `index.html` 末尾正好有一个 `<script>`：

```html
<script>
    // 请在下方补充代码，使得文本溢出 2 行时使用省略号
    // 上面四步代码放这里
</script>
```

脚本在 `<body>` 末尾，执行时元素已经解析完成，`querySelector` 可以直接拿到 `.more2_info_name`，不需要等 `DOMContentLoaded`。

> [!note] 关于本题的提交
> 这套代码用于理解和练习"定长切割"这一思路。本题官方判分要求使用 CSS3，JS 方案即使视觉结果一致，也不属于官方要求的提交方式。

### 运行结果

截断后的文本：

```text
新课 随着前端的发展，UI 框架经历了刀耕火种的时…
```

- 第一行：`新课` + `随着前端的发展，UI`
- 第二行：`框架经历了刀耕火种的时…`
- 下方 `¥72.00` 完整露出，不再被文字覆盖。

## 四、为什么是"22"而不是"24"

两行理论上是 24 个字，但实际有三个"吃宽度"的因素：

| 因素 | 占位 | 说明 |
| --- | --- | --- |
| "新课"标签 | 约 3 个字宽 | 第一行开头被占掉 |
| 省略号 `…` | 1 个字宽 | 必须算进两行里 |
| 中英文宽度差 | ±若干 | 汉字 14px，英文/数字约一半宽 |

所以 `24 - 3 - 1 ≈ 20` 是保守估计；因为正文里出现了 `UI`、`ElementUI` 这类窄字符，实际能放到 22 个汉字的位置。

> [!tip] 怎么自己校准
> 在 DevTools 控制台里临时跑一个循环，把 `MAX_LEN` 从 18 试到 25，看哪个值开始变成 3 行：
> ```js
> for (let n = 18; n <= 25; n++) {
>   el.textContent = raw.slice(0, n) + '…';
>   console.log(n, el.scrollHeight);
> }
> ```
> `scrollHeight` 从 `48` 跳到 `72` 的那个 `n`，就是上限。

不过要记得：这个循环会不断改掉页面文字，试完刷新页面即可。

## 五、另一种保护标签的写法

如果不喜欢"先删再放回"，可以直接改文本节点的值，完全不动 `<i>`：

```js
const el = document.querySelector('.more2_info_name');

// 只找“非空白的直接文本节点”
const textNode = Array.from(el.childNodes).find(
  n => n.nodeType === Node.TEXT_NODE && n.nodeValue.trim()
);

const raw = textNode.nodeValue.trim();
textNode.nodeValue = raw.slice(0, 22).replace(/\s+$/, '') + '…';
```

区别：

| 写法 | 是否动 `<i>` | 适合场景 |
| --- | --- | --- |
| 摘标签 → 改 `textContent` → `prepend` | 暂时移出再放回 | 文本集中在一个节点，代码直观 |
| 直接改文本节点 `nodeValue` | 完全不动 | 结构简单、文本只在一个文本节点里 |

本题正文只有一个文本节点（`<i>` 后面那一整段），所以两种写法都能用。如果正文被拆成多个文本节点（例如中间夹了 `<span>`），只改第一个节点会把后面的文字留在原地，这时先用 `textContent` 合并再切更稳。

## 六、易错点清单

| 错误 | 后果 | 正确做法 |
| --- | --- | --- |
| 直接把 `el.textContent` 切成 22 个字 | "新课"被算进长度，正文少切 2 个字 | 先 `replace(tag.textContent, '')` |
| 切完直接赋值，不管标签 | `<i>新课</i>` 被删除 | 先保存 `tag`，切完 `prepend` |
| `MAX_LEN` 取 24 或更大 | 变成 3 行，价格再次被压 | 22（本页实测上限） |
| 用 `...` 代替 `…` | 多占 2 个字符宽度，可能挤到第 3 行 | 用单个字符 `…` |
| 不 `trim()` | 首尾空白占配额，截断位置偏早 | `trim()` + 尾部 `replace(/\s+$/, '')` |
| 用 `innerText` 取文本 | 受渲染影响，可能带换行/隐藏内容 | 用 `textContent` |
| 忽略 emoji | `slice` 切在代理对中间，出现乱码 | `Array.from(raw).slice(0, 22).join('')` |
| 改完不检查行数 | 以为 22 一定行，实际字体变了 | 目测/量 `scrollHeight` 验证 |
| 窗口变窄后不重算 | 仍按 22 切，但一行放不下 12 个字 | 固定布局场景才适用；否则按宽度重算 |
| 内容换成英文长单词 | 22 个字符可能只有 1 行或撑破布局 | 英文要按单词边界回退 |

### emoji 的正确切法

```js
const chars = Array.from(raw);          // 按 Unicode 码点切
const kept = chars.slice(0, 22).join('');
```

`'😀'.length` 是 `2`，直接 `slice` 可能只取到半个代理对，渲染成 `�`。本题是中文，用 `slice` 没问题；写通用函数时再升级。

## 七、这个思路的适用边界

| 场景 | 是否适合定长切割 |
| --- | --- |
| 文案固定、宽度固定、字体固定（本题） | ✅ 合适，校准一次即可 |
| 文案会变，但都是中文、同字号 | ⚠️ 大致可用，长度要留余量 |
| 中英文混排、含大量数字/符号 | ⚠️ 字数与宽度不成正比，容易偏 |
| 响应式布局、窗口可缩放 | ❌ 需要按实际宽度重算 |
| 需要保留全文（可复制、可访问） | ❌ 切割会真的删掉内容 |

> [!warning] 定长切割的固有代价
> 被切掉的文字不在 DOM 里了：用户无法选中复制，读屏软件读到的也是残文，搜索引擎抓到的同样是截断后的内容。它解决的是"看起来不溢出"，不是"内容仍然完整"。

## 九、可继续追问的点

- **长度从宽度算**：`MAX_LEN = Math.floor(可用宽度 / 字号) * 2 - 3`，比写死 22 更能适应不同卡片宽度。
- **英文按单词回退**：切完若落在单词中间，向前找到最近的空格，避免 `Elemen…`。
- **先判断是否需要截断**：`if (raw.length > MAX_LEN)` 再切，短文本不补省略号。
- **保留原文**：`el.dataset.fullText = raw`，方便后续"展开全文"或重新计算。
- **`Intl.Segmenter`**：按"字素簇"切分，能正确处理 emoji、组合字符、泰文等复杂文本。
- **与后端配合**：列表接口直接返回摘要字段，前端不用切，也不丢全文。

## 十、记忆口诀

> **取文本、去标签，定长一切二十二；**
> **拼省略、放回签，两行刚好不越界。**

> [!quote] 一句话总结
> **定长切割就是"数够 22 个字，剩下的不要，末尾补 `…`"；难点不在 `slice`，而在算准 22、保住标签、别把省略号挤到第三行。**
