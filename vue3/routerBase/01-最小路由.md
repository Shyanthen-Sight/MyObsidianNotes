# 第 1 关 · 最小可运行路由

> 一句话：一个 Vue 应用 + 一张只有两条记录的路由表 + 一个 `<router-view />`，就构成了路由的最小闭环；缺了 `app.use(router)` 页面会直接空白。

## 一、本关目标

把两个地址映射到两个完全独立的 `.vue` 文件，并验证三件事：

1. `createRouter({ routes })` 负责「地址 → 组件」的对应；
2. `app.use(router)` 把路由能力装进应用；
3. `<router-view />` 是当前匹配组件的渲染出口。

本关**还没有任何链接**，只能在地址栏手动改 `/` 和 `/about` 来观察切换。

### 路由表

```js
const router = createRouter({
  // 独立工程、部署在根路径，所以不用传 base 参数
  history: createWebHistory(),
  routes: [
    { path: '/', component: Home },
    { path: '/about', component: About },
  ],
})
```

## 二、逐文件说明

### `index.html`

- **作用**：整页唯一的 HTML 入口，也是 Vite 的挂载点。
- **关键内容**：

```html
<div id="app"></div>
<script type="module" src="./src/main.js"></script>
```

- **说明**：`#app` 与 `main.js` 里的 `app.mount('#app')` 对应；`type="module"` 让浏览器按 ES 模块加载，Vite 在开发时直接接管这个入口。`lang="zh-CN"` 与 `<title>第 1 关 · 最小路由</title>` 只是演示文案。

### `package.json`

- **作用**：声明本关是独立工程、依赖版本与三个脚本。
- **关键内容**：

```json
{
  "name": "vue-router-step-1",
  "private": true,
  "type": "module",
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  },
  "dependencies": {
    "vue": "^3.5.44",
    "vue-router": "^5.4.0"
  },
  "devDependencies": {
    "@vitejs/plugin-vue": "^6.0.10",
    "vite": "^8.3.5"
  }
}
```

- **说明**：
  - `"type": "module"` 让 `.js` 文件按 ESM 解析，`vite.config.js` 才能直接写 `import`。
  - `"private": true` 防止误发布到 npm。
  - 8 个关卡的依赖完全相同，只有 `name` 从 `vue-router-step-1` 递增。
  - 实际安装版本由 `package-lock.json` 锁定（vue 3.5.44 / vue-router 5.4.0 / vite 8.3.5）。

### `package-lock.json`

- **作用**：npm 自动生成的依赖锁文件，记录整棵依赖树的精确版本、下载地址与完整性校验值。
- **说明**：本仓库解析到 `registry.npmmirror.com` 镜像。它是生成文件，**不要手改**；升级依赖时应通过 `npm install` 重新生成，否则锁文件与 `package.json` 会不一致。

### `vite.config.js`

- **作用**：Vite 构建与开发服务器配置。
- **关键内容**：

```js
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

// 端口固定下来，8 个关卡可以同时开着互相对比
export default defineConfig({
  plugins: [vue()],
  server: { port: 5171 },
})
```

- **说明**：
  - `vue()` 插件负责编译单文件组件（`<template>` / `<script setup>` / `<style>`）。
  - 端口固定为 5171，是为了让 8 个关卡可以同时启动、互相对照；`server.port` 在后续关卡依次递增到 5178。
  - 没有配置 `base`，与本关「部署在根路径」的前提一致。

### `src/main.js`

- **作用**：应用入口，本关最核心的文件——创建路由、注册插件、挂载应用。
- **完整内容**：

```js
import { createApp } from 'vue'
import { createRouter, createWebHistory } from 'vue-router'
import App from './App.vue'
import Home from './pages/Home.vue'
import About from './pages/About.vue'
import './style.css'

const router = createRouter({
  history: createWebHistory(),
  routes: [
    { path: '/', component: Home },
    { path: '/about', component: About },
  ],
})

const app = createApp(App)
app.use(router)
app.mount('#app')
```

- **说明**：
  - `createRouter` 返回路由器实例，`routes` 每条记录至少需要 `path` 和 `component`。
  - `createWebHistory()` 使用 HTML5 History，URL 干净（没有 `#`）；代价是生产环境需要服务器把所有路径回退到 `index.html`。
  - `app.use(router)` 是**关键的一行**：它注册路由插件、注入全局组件 `<router-view>` / `<router-link>`，并提供 `$route` / `$router`。漏掉它，模板里的 `<router-view />` 不会被解析成路由出口。
  - `app.mount('#app')` 必须在 `use(router)` 之后，否则首次渲染时拿不到路由状态。

### `src/App.vue`

- **作用**：根组件，提供顶栏、路由出口与本关说明块。
- **关键模板**：

```vue
<header class="bar">
  <span class="badge">第 1 关</span>
  <strong>最小可运行路由</strong>
  <a class="back" href="/">关卡地图</a>
</header>

<main class="wrap">
  <!-- 地址匹配到哪个组件，就把它渲染在这个位置 -->
  <router-view />

  <section class="note">
    <h2>本步</h2>
    <ul>
      <li><code>createRouter({ routes })</code>：把地址和组件对上</li>
      <li><code>app.use(router)</code>：缺这一句，页面会是空白</li>
      <li><code>&lt;router-view /&gt;</code>：匹配到的组件渲染在这里</li>
    </ul>
    ...
  </section>
</main>
```

- **说明**：
  - 本文件**没有 `<script>`**，纯模板组件；`<router-view />` 由路由插件全局注册，因此不需要 import。
  - 页面切换时 `App.vue` 本身不重建，只有 `<router-view />` 里的内容被替换——这是 SPA 保留状态的基础。
  - 「关卡地图」链接是 `<a href="/">`，但仓库根目录并没有地图页，点击实际回到**本关**首页，并且会整页刷新；后续关卡一直保留这个装饰性链接。

### `src/pages/Home.vue`

- **作用**：`path: '/'` 对应的页面，用来读取并显示当前地址。
- **脚本**：

```js
import { useRoute } from 'vue-router'
const route = useRoute()
```

- **模板要点**：展示 `{{ route.fullPath }}`，并说明「地址栏里的路径由路由表决定」。
- **说明**：
  - `useRoute()` 返回**当前路由的响应式对象**（只读），`fullPath` 包含查询串与 hash；这里用它证明组件确实能感知地址。
  - 页面本身不负责跳转，本关也没有链接，只能改地址栏。

### `src/pages/About.vue`

- **作用**：`path: '/about'` 对应的页面，用代码块回显路由表，帮助对照。
- **说明**：
  - 完全静态，没有脚本；用来强调「两个地址是两个独立的 `.vue` 文件」。
  - 文案里埋了一个伏笔：「路由表里没有 `/contact`，所以访问它会是一片空白——这个坑第 6 关再补」。这正是缺少通配兜底路由时的表现：`<router-view />` 匹配不到任何记录，渲染为空。
  - 注意 Vue 模板中的 `<` 必须转义为 `&lt;`，否则会被当成标签解析。

### `src/style.css`

- **作用**：8 个关卡共用的演示样式，**与路由知识无关**。
- **规模**：267 行，8 份文件 MD5 完全一致。
- **结构**：
  - CSS 变量：`--brand`、`--ink`、`--bg`、`--line` 等设计 token；
  - 基础排版：`body`、`a`、`h1`、`h2`、`code`；

  - 其它：`.btn`、`.code`、`.list`、`.avatar`、`.tag`。
- **说明**：虽然第 1 关还用不到 `router-link-active`、`.subnav`、`.list`，但样式一开始就写全了，后续关卡直接复用，不需要再改 CSS。

## 三、本关要点

- 路由三件套：**路由表**定义映射，**`app.use(router)`** 启用能力，**`<router-view />`** 提供出口。
- `createWebHistory()` 的 URL 干净，但需要服务端 fallback；若部署在子路径，还要给 `createWebHistory()` 传 `base`。
- 没有匹配记录时不会报错，只会渲染空白——这是第 6 关要解决的问题。
- SPA 切换只替换出口内容，根组件不会重建。
