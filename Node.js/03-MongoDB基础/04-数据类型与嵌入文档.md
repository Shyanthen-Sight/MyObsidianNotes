# 数据类型、嵌入文档与数组

> [!abstract] 本篇定位
> 覆盖课程 #59–#61。这三集解决同一个问题：**真实世界的数据不是一张平铺的表**——有日期、有金额、有一对多的从属关系。MongoDB 的答案是 BSON 类型 + 嵌入文档 + 数组，这也是"文档数据库"之所以叫文档的原因。

## 一、BSON 数据类型（#59）

![BSON 类型演示](img/course-m01-bson-types.jpg)
*图 M4-01 · 视频 #59 · mongosh 里 ObjectId / Date 等类型的实际输出*

shell 里常用类型与构造方式（完整表：[BSON Types](https://www.mongodb.com/docs/manual/reference/bson-types/)）：

```javascript
db.types.insertOne({
  id:  ObjectId("6517f33e50a88bf2dd08e46d"),  // ObjectId：默认 _id 类型
  when: new Date("2023-03-01"),               // Date：真日期，可比较可排序
  n:    NumberInt(42),                        // 32 位整数（默认 number 是 double）
  big:  NumberLong("9007199254740993"),       // 64 位整数
  dec:  NumberDecimal("0.1"),                 // 精确十进制（金额推荐）
  rx:   /^a.*z$/,                             // 正则
  bin:  BinData(0, "aGVsbG8=")                // 二进制
})
```

> [!important] 三个最影响业务的类型
> 1. **ObjectId** — 12 字节自带时间戳，天然按创建时间粗略有序；JS 侧拿到的是字符串，查询时要转回 ObjectId（Mongoose 帮你做）
> 2. **Date** — `new Date(...)` 存的是 UTC 毫秒数，`$gte/$lte` 范围查询的前提
> 3. **Decimal128（NumberDecimal）** — 存金额别用默认 double，`0.1 + 0.2 !== 0.3` 的浮点误差在账务场景是事故

## 二、嵌入文档（#60）：关系库"外键"的文档解法

![嵌入文档查询](img/course-m01-embedded.jpg)
*图 M4-02 · 视频 #60 · 嵌套 subscription 对象的整体与点路径查询*

把"从属数据"直接嵌进主文档，而不是拆成两张表 JOIN：

```javascript
db.customer.insertOne({
  name: "Mosh",
  isFeatured: false,
  subscription: {              // 嵌入文档：一个字段本身是个对象
    type: "monthly",
    renewedOn: { day: 01, month: "March", year: 2023 }
  }
})

// 查询整个嵌入对象（值必须整体完全匹配）
db.customer.find({ subscription: { type: "monthly", renewedOn: { day: 01, month: "March", year: 2023 } } })

// 点路径查询：只按子字段过滤（实际开发 99% 用这种）
db.customer.find({ "subscription.type": "monthly" })
```

> [!tip] 嵌入 vs 引用（设计取舍）
> - **嵌入**：数据"整体属于"主文档、一起读写的（订单的明细、文章的评论草稿）→ 查询一次到位，无 JOIN
> - **引用**：多文档共享、独立增删的（作者 vs 所有文章）→ 存 `_id` 引用，查询时手动/`$lookup` 二次查询
> 原则：**一起读写的数据嵌在一起**。Mongoose 的 `populate` 是引用方案的实现，见 [[04-Mongoose实战/05-虚拟属性与中间件]] 后的应用。
> 官方文档：[Schema Design / Embedded Documents](https://www.mongodb.com/docs/manual/core/schema-design/)

## 三、数组字段（#61）

数组能装任何 BSON 值——包括嵌入文档，于是"一对多"有了最轻量的表达：

```javascript
// 数组套嵌入文档
db.customer.insertOne({
  name: "John",
  tags: ["vip", "newsletter"],
  subscription: {
    type: "monthly",
    history: [                      // 数组内的嵌入文档
      { renewedOn: { day: 01, month: "March", year: 2023 } },
      { renewedOn: { day: 01, month: "April", year: 2023 } }
    ]
  }
})

// 查询：点路径照样穿透数组
db.customer.find({ "subscription.history.renewedOn.month": "April" })
db.customer.find({ tags: "vip" })                     // 数组包含即命中
db.customer.find({ tags: { $all: ["vip", "newsletter"] } })  // 全包含
db.customer.find({ tags: { $size: 2 } })              // 数组长度

// 更新数组
db.customer.updateOne({ name: "John" }, { $push: { tags: "premium" } })
db.customer.updateOne({ name: "John" }, { $pull: { tags: "newsletter" } })
db.customer.updateOne({ name: "John" }, { $addToSet: { tags: "vip" } }) // 去重追加
```

官方文档：[Query an Array](https://www.mongodb.com/docs/manual/tutorial/query-arrays/) · [$push](https://www.mongodb.com/docs/manual/reference/operator/update/push/)

> [!warning] 数组不是万能的
> 数组无限增长（如"用户的所有订单"）会让文档超过 **16MB 上限**、拖垮更新性能——"无限增长的关系"应该拆成引用 + 独立集合（课程 #61 也点了这个边界）。

## 四、小结：三层建模心法

| 数据关系 | 表达方式 | 例子 |
| :--- | :--- | :--- |
| 单值 + 类型 | BSON 类型字段 | `birthDate: Date`、`price: Decimal128` |
| 从属、同生命周期 | 嵌入文档 / 嵌入文档数组 | `subscription.history` |
| 共享、无限增长 | `_id` 引用 + 独立集合 | `movies` 引用 `genres` |
