# 全局异常捕获与调试

> [!abstract] 本篇定位
> 错误处理板块收官（#99–#101）。前面所有中间件都只能管**请求生命周期内**的错误；本篇处理更底层的两类：**没人接的 Promise reject** 和**同步未捕获异常**——它们直接威胁进程存活。最后加上调试器技能。

## 一、Unhandled Promise Rejection（#99）

![unhandledRejection 处理](img/course-err04-unhandled.jpg)
*图 E4-01 · 视频 #99 · process.on('unhandledRejection') + 优雅停机*

[[05-错误处理/02-异步错误处理与NotFound|catchAsync]] 能兜住 await 的 Promise，但漏网的（比如某处忘记包装）会触发**进程级**事件：

```javascript
// server.js —— 进程级最后防线
process.on('unhandledRejection', (err) => {
  console.log(err.name, err.message);
  console.log('UNHANDLED REJECTION! 💥 Shutting down...');
  server.close(() => {              // 1. 先让在途请求处理完
    process.exit(1);                // 2. 再退出进程（PM2/Docker 会自动重启拉起）
  });
});
```

> [!important] 为什么"先 close 再 exit"
> 直接 `process.exit(1)` 会砍掉正在处理的请求（用户收到硬断连）。`server.close()` 停止**接受新连接**并等已有请求结束——优雅停机（graceful shutdown）。
> 官方文档：[process: unhandledRejection](https://nodejs.org/api/process.html#event-unhandledrejection)

## 二、Uncaught Exception（同步崩溃）（#100）

![uncaughtException 处理](img/course-err04-uncaught.jpg)
*图 E4-02 · 视频 #100 · process.on('uncaughtException') 与挂在文件最前面的位置*

```javascript
// server.js —— 必须挂在【所有代码之前】，否则崩溃先于监听注册
process.on('uncaughtException', (err) => {
  console.log(err.name, err.message);
  console.log('UNCAUGHT EXCEPTION! 💥 Shutting down...');
  process.exit(1);                  // 同步崩溃后进程状态不可信，不等在途请求，立即退出
});

// Node 15+ 里 unhandledRejection 默认也会崩进程，但显式监听能自己掌控日志与停机方式。
```

**为什么不"捕获后继续跑"**：进程进入未知状态，继续服务可能造成更大破坏——崩掉 + 由进程管理器重启才是正解。重启交给 [[02-Express/05-环境变量与配置|PM2 / Docker restart policy]]。

## 三、三层防线总结

| 层 | 捕获范围 | 机制 |
| :--- | :--- | :--- |
| 控制器 | await 的业务错误 | catchAsync → next(err) |
| 兜底 | 没匹配的路由 | all('*') → AppError |
| 进程 | 漏网 reject / 同步崩溃 | unhandledRejection / uncaughtException → 退出重启 |

## 四、调试 Node 代码（#101）

![VS Code 调试器](img/course-err04-debugger.jpg)
*图 E4-03 · 视频 #101 · launch.json 配置与断点调试*

```json
// .vscode/launch.json
{
  "type": "node",
  "request": "launch",
  "name": "Debug App",
  "program": "${workspaceFolder}/server.js",
  "env": { "NODE_ENV": "development" }
}
```

课程演示流程：F5 启动 → 在 `movieModel.js` / 控制器设断点（F9）→ 请求打进来时**暂停在断点**：
- **Variables 面板**：看 `req.query`、`req.params` 当时的真实值
- **Watch**：盯特定表达式
- **Step Over / Into**（F10/F11）：单步走
- **Debug Console**：断点处执行任意表达式

> [!tip] 遇到"诡异错误"的第一动作
> 与其 console.log 满天飞，不如：复现请求 → 断点停在抛错附近 → 看 Variables → 用 Debug Console 试验修复假设。
> 官方文档：[Node.js Debugging Guide](https://nodejs.org/en/learn/getting-started/debugging)
