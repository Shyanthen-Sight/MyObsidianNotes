# 开发与生产错误与常见错误类型

> [!abstract] 本篇定位
> 覆盖课程 #95–#98。把全局错误中间件升级成"两套模式 + 三种数据库错误的翻译器"：开发环境给程序员看全量堆栈，生产环境只给用户安全的最小信息。

## 一、开发 vs 生产：两套响应（#95/#96）

![sendProdError 代码](img/course-err03-sendprod.jpg)
*图 E3-01 · 视频 #95 · sendErrorDev / sendErrorProd 两个私有函数*

![dev/prod 分支判断](img/course-err03-devprod-switch.jpg)
*图 E3-02 · 视频 #96 · 全局中间件里按 NODE_ENV 走不同分支*

```javascript
// controllers/errorController.js
const sendErrorDev = (err, res) => {
  res.status(err.statusCode).json({
    status: err.status,
    message: err.message,
    stack: err.stack,                 // 开发：给完整堆栈，方便定位
    error: err,                       // 以及完整错误对象
  });
};

const sendErrorProd = (err, res) => {
  if (err.isOperational) {            // 受信的"操作错误"：可以展示给用户
    res.status(err.statusCode).json({ status: err.status, message: err.message });
  } else {
    // 编程错误：详情绝不外泄（可能带库表结构等敏感信息），只给一句通用话术
    console.error('ERROR 💥', err);
    res.status(500).json({ status: 'error', message: 'Something went very wrong!' });
  }
};

module.exports = (err, req, res, next) => {
  err.statusCode = err.statusCode || 500;
  err.status = err.status || 'error';

  if (process.env.NODE_ENV === 'development') sendErrorDev(err, res);
  else                                        sendErrorProd(err, res);
};
```

> [!important] 安全逻辑（这是面试考点）
> `isOperational` 标记（[[05-错误处理/01-默认路由与全局错误处理|AppError]] 里埋的）+ `NODE_ENV` 共同决定"对用户说什么、对日志记什么"。生产环境暴露堆栈 = 把代码结构拱手送人。

## 二、CastError：非法 ID（#96）

```javascript
// 环境变量切换：npm run dev（NODE_ENV=development） / npm run start:prod
// 【全局中间件里，发响应前】做翻译：
if (err.name === 'CastError') {                     // findById('abc') 之类
  err = new AppError(`Invalid ${err.path}: ${err.value}`, 400);
}
```

没有这层翻译，非法 ID 会变成 500 "Something went wrong"——但用户明明只是输错了个 ID，语义上就是 400。

## 三、Duplicate Key：唯一字段冲突（#97）

![重复键错误处理](img/course-err03-duplicate.jpg)
*图 E3-03 · 视频 #97 · E11000 错误码与"该电影名已存在"响应*

```javascript
if (err.code === 11000) {                           // MongoDB 唯一索引冲突
  const value = err.errmsg.match(/(["'])(?:(?=(\\?))\2.)*?\1/)[0]; // 从 errmsg 提取冲突值
  err = new AppError(`Duplicate field value: ${value}. Please use another name!`, 400);
}
```

> [!note] 回忆 [[04-Mongoose实战/06-数据验证器|验证器篇]] 的伏笔
> `unique: true` 不走 ValidationError，报的就是这个 `code: 11000`——所以它必须在**错误层**翻译，而不是在 Schema 层解决。

## 四、ValidationError：字段级校验失败（#98）

![ValidationError 处理](img/course-err03-validation.jpg)
*图 E3-04 · 视频 #98 · 遍历 err.errors 把字段消息拼成一条*

```javascript
if (err.name === 'ValidationError') {
  const errors = Object.values(err.errors).map((el) => el.message);
  err = new AppError(`Invalid input data. ${errors.join('. ')}`, 400);
}
```

`err.errors` 就是 [[04-Mongoose实战/06-数据验证器|验证器篇]] 里逐字段收集的那个对象——错误层把它展平成一条可读消息。

## 五、翻译器全景

| 错误 | 识别特征 | 翻译为 | HTTP |
| :--- | :--- | :--- | :--- |
| 非法 ID | `err.name === 'CastError'` | `Invalid id: xxx` | 400 |
| 唯一冲突 | `err.code === 11000` | `Duplicate field value` | 400 |
| 校验失败 | `err.name === 'ValidationError'` | 字段消息拼接 | 400 |
| 路由不存在 | 兜底路由 AppError | `Can't find /xxx` | 404 |
| 查无记录 | `!doc` 判断 | `with that ID is not found` | 404 |
| 其他 | — | `Something went very wrong!` | 500 |

顺序上：**先翻译（识别分类）→ 再按环境发响应**。
