# Express 05 - 环境变量与配置

> [!info] 本篇覆盖
> 课程 #47 环境变量、#48 配置文件。
> 一句话目标：**让应用"一套代码，多种环境"——开发用一套数据库，生产用另一套；密钥不进代码库。**

---

## 一、为什么需要环境变量（#47）

同一份代码要跑在两种环境里：

| | 开发环境 (development) | 生产环境 (production) |
|:---|:---|:---|
| 数据库 | 本地 / Atlas 测试集群 | 正式集群 |
| 日志 | 详细输出（morgan dev） | 关闭或精简 |
| 错误信息 | 全量暴露便于调试 | 只给通用提示（见 [[01-错误处理架构]]） |
| 端口 | 3000 | 平台分配（Heroku/云主机注入） |

**环境变量 = 从进程外部注入的配置**。把"会随环境变化的值"从代码里抽出去。

## 二、process.env 与 NODE_ENV

![[img/course-e05-env-port.jpg]]
*图 E5-1 · 00:01:51 · 用 process.env 读取端口与环境*

```js
const app = require('./app');

const port = process.env.PORT || 3000;      // 优先用注入的端口，否则 3000
app.listen(port, () => console.log(`Server has started on ${port}...`));
```

`process.env` 是 Node 注入的**环境变量对象**（键值对全是字符串）：

```bash
# 临时注入环境变量启动
NODE_ENV=development PORT=3000 node server.js
```

**`NODE_ENV` 是事实上的行业约定**（不是 Node 强制）——框架与库都靠它判断环境。

## 三、注入方式

### 3.1 npm scripts 里设置（课程的做法）

![[img/course-e05-env-scripts.jpg]]
*图 E5-2 · 00:08:45 · package.json scripts 中按环境注入 NODE_ENV*

```json
{
  "scripts": {
    "start": "NODE_ENV=production node server.js",
    "start:dev": "NODE_ENV=development nodemon server.js",
    "debug": "ND_ENV=development nodemon --inspect server.js"
  }
}
```

```bash
npm run start:dev     # 开发环境
npm start             # 生产环境
```

> [!warning] Windows 的坑
> `NODE_ENV=xxx node app.js` 是 Unix shell 语法，Windows CMD/PowerShell 不认。跨平台解法：用 `cross-env` 包（`cross-env NODE_ENV=production node server.js`）。

### 3.2 .env 配置文件（#48）

环境一多，命令行注入就不现实了。**dotenv** 库从文件读取：

```bash
npm install dotenv
```

课程创建 `config.env`（.env 扩展名是惯例）：

```ini
NODE_ENV=development
PORT=3000
DB_USERNAME=leo
DB_PASSWORD=secret123
JWT_SECRET=my-ultra-secure-json-token-string
JWT_EXPIRES_IN=90d
```

代码最顶部加载（**必须在使用前**）：

```js
const dotenv = require('dotenv');
dotenv.config({ path: './config.env' });    // 文件里的变量全部进入 process.env

const app = require('./app');
const port = process.env.PORT || 3000;
app.listen(port, () => console.log('Server has started...'));
```

> [!danger] .env 文件绝不能进 git
> 里面有数据库密码、JWT 密钥。`.gitignore` 必须包含：
> ```gitignore
> config.env
> .env
> ```
> 泄露后果：任何人可用你的密钥签发合法登录令牌（见 [[01-用户模型与JWT]]）。团队共享配置用 `.env.example`（只留键名不留值）提交。

## 四、配置的最佳实践清单

1. **代码里永远不出现魔法值**：端口、URL、密钥全部走 `process.env`
2. **提供默认值**：`process.env.PORT || 3000`，缺配置也能跑
3. **读取前校验**：关键变量缺失时尽早 fail-fast：
   ```js
   if (!process.env.JWT_SECRET) {
     console.error('FATAL ERROR: JWT_SECRET is not defined');
     process.exit(1);
   }
   ```
4. **云平台的端口注入**：多数云主机把端口写在 `process.env.PORT`——这也是生产代码必须读环境变量的现实原因
5. **类型注意**：环境变量全是字符串，数字比较前要 `Number()`

## 五、常见坑速查

| 坑 | 现象 | 解决 |
|:---|:---|:---|
| dotenv 加载在 require('./app') 之后 | app 里读不到变量 | dotenv.config 放最顶 |
| .env 传上 git | 密钥泄露 | gitignore + 历史清理 |
| 变量值带空格未加引号 | 解析截断 | `JWT_SECRET="a b c"` |
| Windows 注入失败 | `NODE_ENV 不是内部命令` | cross-env |
