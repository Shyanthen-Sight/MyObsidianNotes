## 一、中间件到底是什么（#39）

课程定义：**中间件就是一个能修改请求/响应的函数，站在请求与响应的中间**。

Express 应用的本质：请求进来 → 依次穿过一串中间件 → 到达路由处理器 → 返回响应：

```text
请求 ──► [express.json] ──► [logger] ──► [auth检查] ──► [路由处理器] ──► 响应
```

你其实早就在用了：`app.use(express.json())`（[[02-CRUD接口实现]]）就是中间件——没有它 `req.body` 是 undefined。

### 中间件函数的固定签名

```js
function middleware(request, response, next) {
  // …处理 request / response …
  next();                     // ← 交棒给下一个中间件
}
```

三个参数：

| 参数 | 说明 |
|:---|:---|
| `request` | 请求对象，可在这里加工（如挂上 body） |
| `response` | 响应对象，中间件也可以直接结束响应 |
| `next` | **必须调用**才会进入下一个中间件，否则请求挂起 |

### 注册方式：app.use

```js
app.use(express.json());          // 对所有请求生效
app.use('/api', someMiddleware);  // 只对 /api 开头的路径生效
```

`app.use` 不带路径 = 全局；带路径前缀 = 该前缀下的所有方法都经过它。

> [!warning] 中间件的顺序决定一切
> Express 按注册顺序执行中间件。`express.json()` 必须写在路由**之前**，否则路由拿到请求时 body 还没被解析。调试时"路由处理器没执行"十有八九是前面某个中间件忘调 `next()`。

## 二、自定义中间件（#40）

课程实现的经典 **logger**：

```js
const logger = (request, response, next) => {
  console.log(`${request.method} ${request.url} - ${new Date().toISOString()}`);
  next();
};

app.use(logger);
```

```text
GET /api/v1/movies - 2026-11-13T10:00:00.000Z
```

### 修改请求对象：中间件的隐藏用法

课程还演示了给 `request` **挂自定义属性**，供下游中间件/处理器使用：

```js
const addRequestTime = (request, response, next) => {
  request.requestedAt = new Date().toISOString();   // 挂属性
  next();
};

app.get('/api/v1/movies', addRequestTime, (request, response) => {
  console.log(request.requestedAt);   // 下游可以直接用
  response.json(movies);
});
```

这就是 Express 生态几乎所有中间件库的工作方式（如 `request.body`、`request.user` 都是上游中间件挂上去的）。

> [!tip] 中间件的三种用途
> 1. **处理请求**：解析 body（express.json）、解析 cookie
> 2. **产生副作用**：日志（morgan）、限流
> 3. **给请求挂数据**：认证后的 `request.user`（[[02-路由保护与权限]] 的核心手法）

## 三、第三方中间件：Morgan（#41）

```bash
npm install morgan      # HTTP 请求日志中间件
```

```js
const morgan = require('morgan');
app.use(morgan('dev'));           // 'dev' 是输出格式
```

```text
GET /api/v1/movies 200 5.309 ms - 39
POST /api/v1/movies 201 4.807 ms - 148
GET /api/v1/movies/3 404 1.652 ms - 59
```

一行代码获得：方法、路径、状态码、耗时、响应大小——开发期调试利器。

选型建议（常用第三方中间件）：

## 四、中间件 vs 路由处理器

课程一语道破：**路由处理器也是中间件**——只是签名里可以不写 `next`（它是流水线的最后一站）：

```js
app.get('/api/v1/movies',
  addRequestTime,          // 中间件 1
  (request, response) => { // 处理器（最后一个中间件）
    response.json(movies);
  }
);
```

区别只有两点：处理器通常**必须**调用 `response.end/send/json` 结束响应；中间件通常**必须**调用 `next()` 继续传递。两者都忘调 → 请求挂起。

### 中间件栈的完整心智模型

```text
app.use(express.json())          ← 全局层
app.use(morgan('dev'))           ← 全局层
router.param('id', checkID)      ← 参数层（见 [[04-路由模块化与静态文件]]）
app.post('/x', validate, create) ← 路由层（多中间件链）
```

从全局到局部，请求像穿过洋葱一样层层经过。

## 五、常见坑速查

| 坑 | 现象 | 解决 |
|:---|:---|:---|
| 忘调 `next()` | 请求永远挂起 | 每条路径都要 next 或 end |
| 中间件注册在路由之后 | 路由收到的数据没被处理 | 全局中间件放最前 |
| `app.use(logger)` 放在静态文件后 | 静态请求没日志 | 按需调整顺序 |
| 中间件里抛异常 | 500 或进程崩溃 | 用错误处理中间件，见 [[01-错误处理架构]] |
