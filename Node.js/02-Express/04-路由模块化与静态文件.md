# Express 04 - 路由模块化与静态文件

> [!info] 本篇覆盖
> 课程 #42 挂载路由、#43 路由模块、#44 param 中间件、#45 链式中间件、#46 静态文件。
> 一句话目标：**把单文件 app.js 拆成可维护的工程结构，并让服务器能直接对外提供静态资源。**

---

## 一、为什么需要 Router（#42）

当所有路由都堆在 `app.js`：

```js
app.get('/api/v1/movies', ...)
app.post('/api/v1/movies', ...)
app.get('/api/v1/users', ...)      // 资源一多，文件爆炸
```

**Express 的解法：每个资源一个 Router（迷你应用）**，再挂载到主应用上。

```js
const moviesRouter = express.Router();      // 创建迷你路由实例

moviesRouter.route('/')
  .get(getAllMovies)
  .post(createMovie);

moviesRouter.route('/:id')
  .get(getMovie)
  .patch(updateMovie)
  .delete(deleteMovie);

module.exports = moviesRouter;
```

主应用挂载：

```js
const moviesRouter = require('./routes/moviesRoute');
app.use('/api/v1/movies', moviesRouter);    // 前缀 + 路由模块
```

`app.use(prefix, router)` 的语义：**router 内部写相对路径，前缀由主应用拼接**。

> [!tip] 为什么用 `route()` 链式写法
> `moviesRouter.route('/:id')` 把同一路径的 GET/PATCH/DELETE 聚合在一起，避免重复写 `/api/v1/movies/:id` 四次，也让"同一资源的操作方法"在视觉上成组。

## 二、拆分成路由模块（#43）

课程的重构步骤（每一步都值得学）：

```text
CINEFLEX PROJECT/
├── controllers/
│   └── moviesController.js      ← 业务逻辑（getAllMovies / createMovie …）
├── routes/
│   └── moviesRoute.js           ← 只负责 URL → controller 映射
├── models/                      ← 数据模型（Mongoose 阶段出现）
├── app.js                       ← 组装：中间件 + 挂载路由
└── server.js                    ← 启动服务器
```

`routes/moviesRoute.js`：

```js
const express = require('express');
const moviesController = require('../controllers/moviesController');

const router = express.Router();

router.route('/')
  .get(moviesController.getAllMovies)
  .post(moviesController.createMovie);

router.route('/:id')
  .get(moviesController.getMovie)
  .patch(moviesController.updateMovie)
  .delete(moviesController.deleteMovie);

module.exports = router;
```

这是 [[04-Mongoose实战/01-连接数据库与Schema与Model]] 里 MVC 架构的**路由层**：路由只做分发，不写业务。

## 三、param 中间件（#44）

![[img/course-e04-param-middleware.jpg]]
*图 E4-1 · 00:02:25 · router.param('id', …) 校验路由参数*

**param 中间件 = 只对某个路由参数生效的中间件**。场景：所有 `/:id` 路由都要先校验 id 合法性，不必在每个处理器里重复写。

```js
router.param('id', (request, response, next, value) => {
  // 注意：参数顺序是 (req, res, next, value)，不是 (req, res, next)
  console.log(`Movie ID is ${value}`);
  next();
});
```

课程中的实际版本（校验是否为合法数字 id）：

```js
exports.checkID = (request, response, next, value) => {
  const id = Number(value);
  const movie = movies.find(el => el.id === id);
  if (!movie) {
    return response.status(404).json({
      status: 'fail',
      message: `No movie found with ID ${value}`,
    });
  }
  request.movie = movie;         // 顺手挂到请求上，下游直接用
  next();
};
```

然后在路由文件里 `router.param('id', moviesController.checkID)`——**所有带 `:id` 的路由自动获得校验**，包括 GET / PATCH / DELETE。

> [!tip] param 中间件的签名陷阱
> 普通中间件是 `(req, res, next)`；**param 中间件是 `(req, res, next, value)`**——第四个参数才是 URL 里的值。忘了 value 就会拿到 `undefined`。

## 四、链式中间件（#45）

![[img/course-e04-chaining.jpg]]
*图 E4-2 · 00:10:06 · 一个路由挂多个中间件：先校验 body，再创建*

一条路由可以挂**任意多个**中间件，按顺序执行：

```js
router.route('/')
  .post(moviesController.validateBody, moviesController.createMovie);
//     ↑ 先校验请求体              ↑ 校验通过才执行创建
```

```js
exports.validateBody = (request, response, next) => {
  if (!request.body.name || !request.body.releaseYear) {
    return response.status(400).json({ status: 'fail', message: 'Not a valid movie data' });
  }
  next();                        // 通过 → 交给 createMovie
};
```

这就是"**校验与业务分离**"：validateBody 只管判断，createMovie 只管写入。Express 5 里这类校验中间件还可直接抛错交给全局错误处理（见 [[05-错误处理/01-默认路由与全局错误处理]]）。

## 五、静态文件（#46）

![[img/course-e04-static-mounted.jpg]]
*图 E4-3 · 00:05:56 · app.use(express.static('public')) 与完整 app.js 结构*

**静态文件** = 文件系统里躺着、不经过路由逻辑、直接对外提供的资源：HTML、CSS、JS、图片、字体。

```js
app.use(express.static('public'));       // public/ 目录变成网站根目录
```

```text
public/
├── templates/
│   └── demo.html          → 访问 /templates/demo.html
├── css/
│   └── style.css          → 访问 /css/style.css
└── img/
    └── logo.png           → 访问 /img/logo.png
```

访问 `http://localhost:3000/templates/demo.html` 直接拿到文件内容，**无需写任何路由**。

细节：

| 需求 | 写法 |
|:---|:---|
| 换 URL 前缀 | `app.use('/static', express.static('public'))` → `/static/css/style.css` |
| 多个静态目录 | 多次调用 `app.use(express.static(...))`，按顺序查找 |
| 找不到文件 | 自动 `next()`，可被后续 404 兜底接住 |

> [!warning] 静态文件与路由顺序
> 静态中间件通通常放**最前面**（在 logger 之后），否则每次请求都要先穿过一堆路由判断。同时注意：`public` 里不要放 `.env`、源码等敏感文件——静态目录下的所有文件都是公开可下载的。
