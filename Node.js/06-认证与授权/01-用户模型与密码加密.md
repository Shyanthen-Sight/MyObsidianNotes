# 用户模型与密码加密

> [!abstract] 本篇定位
> 认证与授权板块开篇（#102–#104）。建 User Model + 用 **bcrypt** 哈希密码。核心原则：**数据库里永远不能出现明文密码**。

## 一、User Schema 的安全字段设计（#102）

![User Schema 代码](img/course-auth01-user-schema.jpg)
*图 A1-01 · 视频 #102 · name/email/password/passwordConfirm/role 与 validate 校验*

```javascript
const userSchema = new mongoose.Schema({
  name: {
    type: String,
    required: [true, 'Please enter your name!'],
  },
  email: {
    type: String,
    required: [true, 'Please enter an email!'],
    unique: true,                                     // 唯一 → 冲突报 E11000（[[05-错误处理/03-开发与生产错误与常见错误类型]]）
    lowercase: true,
    validate: [validator.isEmail, 'Please enter a valid email!'],  // validator 库做邮箱格式
  },
  password: {
    type: String,
    required: [true, 'Please enter a password!'],
    minlength: 8,
    select: false,        // ★ 关键：任何 find() 查询默认【不返回】该字段
  },
  passwordConfirm: {
    type: String,
    required: [true, 'Please confirm your password!'],
    validate: {                       // 注意 this 可用 → 只在 create/save 时跑
      validator: function (el) { return el === this.password; },
      message: 'Passwords are not the same!',
    },
  },
  role: { type: String, enum: ['user', 'admin'], default: 'user' },
});
```

> [!important] 两个关键决策
> 1. **`passwordConfirm` 不存库**：它只是表单二次确认用的验证器靶子，用 [[04-Mongoose实战/05-虚拟属性与中间件|中间件]] 删掉（见下）
> 2. **`select: false`**：密码不随普通查询返回，杜绝"接口顺手带出密码"这类事故。登录时显式 `.select('+password')`。

## 二、`pre('save')` 里加密密码（#104）

bcrypt 现场在 #104 演示（注册请求 → 返回的文档里 password 已是哈希）。原理与代码：

```javascript
const bcrypt = require('bcryptjs');

userSchema.pre('save', async function (next) {
  if (!this.isModified('password')) return next();  // 只有密码真变了才重新加密

  this.password = await bcrypt.hash(this.password, 12);  // 12 = cost factor，越高越慢越安全
  this.passwordConfirm = undefined;                 // 删除确认字段，不会落库
  next();
});
```

要点：
- **异步哈希**（bcryptjs 的 async 版本）——哈希故意很慢（CPU 密集），必须放异步线程，回顾 [[01-Node.js基础/03-构建HTTP服务器|Node 不适合 CPU 密集的警告]]
- `isModified('password')` 保证**更新用户名等操作不会把已哈希的密码再哈希一遍**
- `undefined` 赋值 = save 时该字段不会被写入（JSON 序列化时也会消失）

bcrypt 相关文档：[bcryptjs on npm](https://www.npmjs.com/package/bcryptjs)（课程用 bcryptjs，纯 JS 实现，Windows 免编译；原生 [bcrypt](https://www.npmjs.com/package/bcrypt) 性能更好）

## 三、验证密码：比对而不是"解密"（#104）

哈希不可逆，验证用的是 bcrypt 提供的比对函数：

```javascript
// 实例方法：挂在所有 user 文档上（[[04-Mongoose实战/05-虚拟属性与中间件]] 的 Schema 方法）
userSchema.methods.correctPassword = async function (candidatePassword, userPassword) {
  return await bcrypt.compare(candidatePassword, userPassword);
  // true = 明文与哈希匹配。注意：这里必须传【从库里取出的哈希】
};
```

> [!warning] bcrypt.compare 的参数顺序
> 第一个参数是**用户输入的明文**，第二个是**库里存的哈希**。bcrypt 从哈希串里解析出盐和 cost，用同样参数重算一遍再比对——所以盐不需要单独存。

## 四、注册接口预演（#103/#104）

![signup Postman 现场](img/course-auth01-signup-postman.jpg)
*图 A1-02 · 视频 #104 · Postman 发送注册请求，响应中 password 已是哈希*

```javascript
exports.signup = async (req, res, next) => {
  // 不直接 req.body！只挑安全字段，防"我把 role 改成 admin"的越权提交
  const newUser = await User.create({
    name: req.body.name,
    email: req.body.email,
    password: req.body.password,
    passwordConfirm: req.body.passwordConfirm,
  });
  res.status(201).json({ status: 'success', data: { user: newUser } });
  // newUser.password 为 undefined（select:false + 哈希后也只回 name/email/role）
};
```

> [!danger] Mass Assignment 越权
> `User.create(req.body)` 会让恶意用户顺手提交 `role: "admin"`、`passwordResetToken` 等字段——**永远白名单式挑字段**。完整 signup 带 JWT 的版本在 [[06-认证与授权/02-JWT原理与登录注册]]。
