# 路由保护与用户权限

> [!abstract] 本篇定位
> 覆盖课程 #108–#111。认证解决"你是谁"，**授权**解决"你能干什么"。本篇实现两道中间件：`protect`（没有有效令牌就进不来）和 `restrictTo`（角色不够就做不了），最后用 Postman 变量把调试流程自动化。

## 一、protect 中间件四步走（#108–#109）

![protect 中间件完整代码](img/course-auth03-protect-code.jpg)
*图 A3-01 · 视频 #109 · protect：取令牌 → 验签 → 查用户 → 核对密码改动*

```javascript
exports.protect = asyncError(async (req, res, next) => {
  // 1) 取令牌：Authorization: Bearer xxx
  let token;
  if (req.headers.authorization && req.headers.authorization.startsWith('Bearer')) {
    token = req.headers.authorization.split(' ')[1];
  }
  if (!token) {
    return next(new AppError('You are not logged in!', 401));
  }

  // 2) 验签（异步回调式）：签名对不上 / 已过期都会进 err
  const decoded = await util.promisify(jwt.verify)(token, process.env.JWT_SECRET);
  // decoded = { id: '5c8...', iat: ..., exp: ... }

  // 3) 用 id 查当前用户 —— 令牌有效 ≠ 用户还在
  const currentUser = await User.findById(decoded.id);
  if (!currentUser) {
    return next(new AppError('The user belonging to this token no longer exists.', 401));
  }

  // 4) 用户在签发令牌【之后】改过密码吗？（changedPasswordAfter 见下）
  if (currentUser.changedPasswordAfter(decoded.iat)) {
    return next(new AppError('User recently changed password! Please log in again.', 401));
  }

  req.user = currentUser;        // ★ 把用户挂进请求，后续中间件/控制器都能用
  next();
});
```

> [!important] 每一步为什么必要
> | 步骤 | 防什么 |
> | :--- | :--- |
> | 无令牌 → 401 | 匿名访问 |
> | 验签 | 伪造令牌 / 过期令牌 |
> | 查库 | 用户已注销/删除但令牌未过期 |
> | 密码时间核对 | 令牌泄露后用户改密码想作废旧令牌 |

### changedPasswordAfter（iwt 的 iat 对比）

```javascript
userSchema.methods.changedPasswordAfter = function (JWTTimestamp) {
  if (this.passwordChangedAt) {
    const changedTimestamp = parseInt(this.passwordChangedAt.getTime() / 1000, 10);
    return JWTTimestamp < changedTimestamp;   // 令牌签发早于密码修改 → 旧令牌作废
  }
  return false;
};
```

配套地，在 User Schema 的 `pre('save')`（[[06-认证与授权/01-用户模型与密码加密|密码加密篇]]）里，密码被修改时写入 `passwordChangedAt`。

## 二、把中间件挂到路由（#108）

```javascript
// routes/movieRoutes.js
const authController = require('./../controllers/authController');

// 中间件链：先 protect 再控制器 —— 同一资源对所有角色统一保护
router
  .route('/')
  .get(authController.protect, movieController.getAllMovies)
  .post(authController.protect, movieController.createMovie);
```

## 三、restrictTo：按角色收窄（#111）

```javascript
// 高阶函数：参数是允许的角色，返回真正的中间件（[[05-错误处理/02-异步错误处理与NotFound|catchAsync 同款套路]]）
exports.restrictTo = (...roles) => {
  return (req, res, next) => {
    if (!roles.includes(req.user.role)) {           // req.user 由 protect 塞进来
      return next(new AppError('You do not have permission to perform this action', 403));
    }
    next();
  };
};

// 使用：普通用户 GET 可以，DELETE 只有 admin
router
  .route('/:id')
  .get(authController.protect, movieController.getMovie)
  .delete(authController.protect,
          authController.restrictTo('admin'),
          movieController.deleteMovie);
```

> [!warning] 顺序不能颠倒
> `restrictTo` 依赖 `req.user.role`，而它只在 `protect` 之后才有——**protect 必须在前**。401（没登录）与 403（登录了但没权限）状态码语义不同，各自对应第一道、第二道闸门。

## 四、Postman 自动化：New Folder 的 Authorization（#110）

![Postman 集合级鉴权变量](img/course-auth03-postman-vars.jpg)
*图 A3-03 · 视频 #110 · 文件夹级 Bearer Token 与 {{token}} 变量引用*

每个请求手贴 token 太痛苦。课程的做法：
1. 在集合/文件夹级 **Authorization** 选 Bearer Token，值填 `{{token}}`
2. login 请求的 **Tests 脚本**里：`pm.environment.set("token", pm.response.json().token)` 自动存变量
3. 此后文件夹内所有请求自动带最新令牌；登录一次，全接口可用

> [!tip] 课程在 #110 的完整工作流
> signup → 自动存 token → 访问受保护接口 → 尝试越权（user 调 DELETE）→ 看到预期 403。**API 测试也是 API 设计的一部分**。
