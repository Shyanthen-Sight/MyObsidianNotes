# 账户自助管理

> [!abstract] 本篇定位
> 覆盖课程 #115–#117（依据课程字幕整理，无视频截图）。登录用户对自己账户的三件事：**改密码、改资料、注销**。课程在这里完成了一次重要的控制器重构——把"用户自己的事"从 authController 迁到独立的 userController。

## 一、updatePassword：登录状态改密（#115）

与 [[06-认证与授权/04-密码重置与邮件发送|resetPassword]] 的区别：改密是**已知旧密码的主动行为**，不需要邮件、不需要令牌，但需要 `protect` 在前。

```javascript
exports.updatePassword = asyncError(async (req, res, next) => {
  // 1) 从库中取用户（要拿到 select:false 的密码字段做比对）
  const user = await User.findById(req.user.id).select('+password');

  // 2) 验证旧密码（[[06-认证与授权/01-用户模型与密码加密|correctPassword]]）
  if (!(await user.correctPassword(req.body.passwordCurrent, user.password))) {
    return next(new AppError('Your current password is wrong.', 401));
  }

  // 3) 设新密码并 save —— 触发 pre('save') 加密 + passwordChangedAt 更新
  user.password = req.body.password;
  user.passwordConfirm = req.body.passwordConfirm;
  await user.save();

  // 4) 重新签发 JWT（密码改了，让旧令牌尽快失效）
  const token = signToken(user._id);
  res.status(200).json({ status: 'success', token });
});
```

> [!important] 为什么用 `save` 不用 `findByIdAndUpdate`
> 上一板块学过：`findByIdAndUpdate` **不跑 save 钩子**——bcrypt 加密在 `pre('save')` 里，用它更新会把**明文密码**写进库。密码相关操作一律 `doc.save()`。

## 二、updateMe：改资料（#116）

课程重构：updatePassword/updateMe/deleteMe 都移入 **userController.js**（认证=token 签发/校验归 authController；用户自己的事归 userController——[[04-Mongoose实战/02-MVC架构与Express实现CRUD|MVC 分层思想]]）。

```javascript
// 过滤器：req.body 里只挑允许改的字段（防越权改 role/password）
const filterObj = (obj, ...allowedFields) => {
  const newObj = {};
  Object.keys(obj).forEach((el) => {
    if (allowedFields.includes(el)) newObj[el] = obj[el];
  });
  return newObj;
};

exports.updateMe = asyncError(async (req, res, next) => {
  // 1) 改密码请走 updatePassword —— 需要验证旧密码 + 重新哈希，不能绕过
  if (req.body.password || req.body.passwordConfirm) {
    return next(new AppError('This route is not for password updates. Please use /updateMyPassword.', 400));
  }

  // 2) 白名单过滤后更新（此处才适合 findByIdAndUpdate：不涉及哈希钩子）
  const filteredBody = filterObj(req.body, 'name', 'email');
  const updatedUser = await User.findByIdAndUpdate(req.user.id, filteredBody, {
    new: true, runValidators: true,
  });

  res.status(200).json({ status: 'success', data: { user: updatedUser } });
});
```

## 三、deleteMe：软删除/注销（#117）

**用户"注销"≠ 物理删库**：审计、封禁历史、数据恢复都依赖记录存在。课程用 `active` 标志位实现软删除：

```javascript
// User Schema 新增
active: { type: Boolean, default: true, select: false },   // 不进 API 输出

// userController
exports.deleteMe = asyncError(async (req, res, next) => {
  await User.findByIdAndUpdate(req.user.id, { active: false });
  res.status(204).json({ status: 'success', data: null });   // 204 无内容（[[04-Mongoose实战/02-MVC架构与Express实现CRUD|DELETE 惯例]]）
});

// User Schema 查询中间件：所有 find 类查询自动排除已注销用户
userSchema.pre(/^find/, function (next) {
  this.find({ active: { $ne: false } });
  next();
});
```

> [!success] 软删除三件套
> 1. `active` 字段（默认 true、select:false）
> 2. delete 接口只改标志位
> 3. 全局查询钩子把 `active: false` 挡在一切读取之外（[[04-Mongoose实战/05-虚拟属性与中间件|Query Middleware]]）
> 真正的物理删除留给 admin 后台（`restrictTo('admin')`，[[06-认证与授权/03-路由保护与权限]]）。

## 四、路由汇总

```javascript
// routes/userRoutes.js
router.post('/signup',      authController.signup);
router.post('/login',       authController.login);
router.post('/forgotPassword', authController.forgotPassword);
router.patch('/resetPassword/:token', authController.resetPassword);

// 下面全部需要登录
router.patch('/updateMyPassword', authController.protect, userController.updatePassword);
router.patch('/updateMe',         authController.protect, userController.updateMe);
router.delete('/deleteMe',        authController.protect, userController.deleteMe);
```
