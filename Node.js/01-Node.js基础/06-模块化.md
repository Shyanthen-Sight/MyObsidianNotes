# 06 - 模块化

> [!info] 本篇覆盖
> 课程 #19 创建自定义模块。篇幅虽短，却是 Node 工程化的基石。
> 一句话目标：**把代码拆进文件、用 `module.exports` 对外发布、用 `require` 引入使用。**

---

## 一、为什么要模块化

上一章的 `replaceProducts` 还挤在 `app.js` 里。问题：

1. `app.js` 越来越长，路由逻辑和渲染逻辑混在一起
2. 函数在多处复制粘贴，改一处漏三处
3. 无法复用到其他项目

**模块 = 把一段功能封装进独立文件，对外只暴露接口。**

Node 的模块化思想：**每个文件就是一个私有作用域**——文件里定义的变量、函数默认外界都看不到，想公开必须显式导出。

## 二、require：三种加载目标

![[img/course-06-require-module.jpg]]
*图 06-1 · 00:03:52 · require 的三种来源（注意 `./modules/replaceModule` 自动补全）*

```js
// ① 内置核心模块：只写名字
const fs = require('fs');
const events = require('events');

// ② 自己写的模块：必须 ./ 开头的相对路径
const replaceModule = require('./modules/replaceModule');

// ③ 第三方包（来自 npm）：只写包名
const express = require('express');
```

三种目标的解析规则：

| 写法 | 查找位置 |
|:---|:---|
| `require('fs')` | Node 内置模块 |
| `require('express')` | 逐级向上找 `node_modules/express` |
| `require('./modules/x')` | 相对当前文件路径，按 `x.js → x.json → x/index.js` 顺序解析 |

> [!warning] 最常见的报错
> 自己的模块**忘写 `./`** → Node 以为是 npm 包 → `Error: Cannot find module 'replaceModule'`。

## 三、module.exports 与 exports

### 3.1 导出（modules/replaceModule.js）

```js
function replaceProducts(template, product) {
  let output = template.replace('{{%IMAGE%}}', product.productImage);
  // …其余字段替换
  return output;
}

module.exports = replaceProducts;       // 对外只发布这一个函数
```

### 3.2 引入（app.js）

```js
const replaceProducts = require('./modules/replaceModule');
// require 的返回值就是对方 module.exports 的内容
```

### 3.3 `module.exports` vs `exports`

每个模块顶部其实有一段隐藏包装（详见 [[09-Node架构与事件循环]]）：

```js
(function (exports, require, module, __filename, __dirname) {
  // 你的代码被包在这里
});
```

`exports` 只是 `module.exports` 的快捷引用，所以两者通常等价：

```js
exports.replaceProducts = replaceProducts;    // ✅ 挂属性
module.exports = { replaceProducts };         // ✅ 整体替换
exports = replaceProducts;                    // ❌ 失效！只是重绑了局部变量
```

> [!danger] 一条铁律
> 要**整体导出**（函数、类、单个值）只能用 `module.exports = …`；`exports` 只适合挂属性。两者混用后以 `module.exports` 为准。

## 四、实战：拆出渲染模块

拆分后的项目结构：

```text
NODE JS BASICS/
├── app.js                      # 只剩服务器与路由逻辑
├── data/
│   └── product.json
├── modules/
│   └── replaceModule.js        # 渲染卡片的可复用函数
└── template/
    ├── index.html
    └── product.html
```

```js
// app.js
const replaceModule = require('./modules/replaceModule');

if (pathname === '/product') {
  const product = products[query.id];
  response.end(replaceModule(productDetailHtml, product));
}
```

这个结构正是 [[01-建模与MVC]] 里 **MVC 架构**的雏形：路由 / 业务 / 数据各居其位。

## 五、ESM：现代模块系统（延伸）

课程使用 **CommonJS**（`require`/`module.exports`）。现代 Node（及浏览器生态）标准是 **ESM**：

| | CommonJS | ESM |
|:---|:---|:---|
| 导入 | `const fs = require('fs')` | `import fs from 'node:fs'` |
| 导出 | `module.exports = …` | `export default …` / `export const …` |
| 启用方式 | 默认 | 文件后缀 `.mjs` 或 package.json 里 `"type": "module"` |
| 特性 | 动态 require | 静态分析、Tree-shaking、顶层 await |

官方文档：[CommonJS](https://nodejs.org/docs/latest/api/modules.html) · [ESM](https://nodejs.org/docs/latest/api/esm.html)。本课程全程 CommonJS，但看到别人项目用 ESM 不要慌——**概念一一对应，只是语法不同**。

## 六、常见坑速查

| 坑 | 现象 | 解决 |
|:---|:---|:---|
| 自定义模块忘写 `./` | `Cannot find module` | 相对路径必须 `./` 或 `../` |
| `exports = xxx` | 引入方拿到 `{}` | 用 `module.exports = xxx` |
| 循环引用 A↔B | 拿到不完整对象 | 抽出公共依赖到第三个模块 |
| require 想导入 JSON | 每次都是新读取 | `require('./data.json')` 直接可用（会缓存） |
