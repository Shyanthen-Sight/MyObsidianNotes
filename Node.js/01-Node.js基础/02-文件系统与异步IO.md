# 02 - 文件系统与异步 IO

## 一、同步读写：最直观的方式（#05）

### 1.1 三件套 API

```js
const fs = require('fs');

// 读（第二个参数给编码，返回字符串；不给则返回 Buffer）
let text = fs.readFileSync('./files/input.txt', 'utf-8');
console.log(text);

// 写（覆盖整个文件）
fs.writeFileSync('./files/output.txt', `${text} \nDate created: ${new Date()}`);

// 追加（在文件末尾续写）
fs.appendFileSync('./files/output.txt', '\nAppended line');
```

![[img/course-02-sync-write.jpg]]
*图 02-1 · 00:08:10 · writeFileSync + appendFileSync 及终端输出*

### 1.2 必须注意的两个细节

1. **编码参数决定返回类型**

| 写法 | 返回值 |
|:---|:---|
| `fs.readFileSync(p, 'utf-8')` | 字符串 |
| `fs.readFileSync(p)` | `Buffer`（原始二进制，需 `.toString()`） |

2. **`writeFileSync` 是覆盖写**，不是追加；追加用 `appendFileSync` 或带 `'a'` 标志位（见[官方 fs 文档的文件系统标志表](https://nodejs.org/docs/latest/api/fs.html#file-system-flags)）。

### 1.3 同步 = 阻塞

`readFileSync` 执行期间，**整个 Node 进程卡在这一行**，什么都干不了。小脚本无所谓，服务器里是灾难——这正是下一节要讲的。

## 二、为什么必须异步（#06）

![[img/course-02-why-async.jpg]]
*图 02-2 · 00:07:30 · Why Asynchronous：单线程 + 后台线程*

课程的核心图景：

- Node 是 **SINGLE THREAD**（单线程）：同一时刻只执行一段你的 JS 代码
- 但耗时操作（读文件、查网络）被丢给 **BACKGROUND**（libuv 的线程池）执行
- 执行完成后通过**回调**通知主线程 → 这就是 **Non-blocking IO Model**

> [!warning] 课程强调的两个易混概念
> 1. **Callbacks ≠ Asynchronous**：有回调不一定异步（如 `array.map(cb)` 是同步回调）
> 2. **异步 ≠ 多线程执行你的代码**：你的 JS 代码始终单线程，"多线程"发生在 Node 底层（libuv）

事件循环如何调度这些回调，见 [[09-Node架构与事件循环]]。

## 三、异步读写：err-first 回调（#07）

### 3.1 基本用法

```js
fs.readFile('./files/input.txt', 'utf-8', (error, data) => {
  if (error) {
    console.log('Reading file...', error);
    return;
  }
  console.log(data);
});
console.log('Reading file...');   // ← 这行先于回调输出！
```

![[img/course-02-async-error.jpg]]
*图 02-3 · 00:08:15 · 文件路径不存在时的 ENOENT 错误现场*

### 3.2 err-first 约定

Node 生态所有异步回调的**统一约定**：**第一个参数永远是 error**。

- 成功：`error` 为 `null` / `undefined`，数据在第二个参数
- 失败：`error` 是 `Error` 对象（含 `errno`、`code`、`syscall`、`path` 等字段）

```text
[Error: ENOENT: no such file or directory, open 'D:\...\files\input123.txt'] {
  errno: -4058,
  code: 'ENOENT',      ← 判断错误类型就看它
  syscall: 'open',
  path: 'D:\\NodeCourse\\NODE JS BASICS\\files\\input123.txt'
}
```

### 3.3 执行顺序陷阱

```js
console.log('1');
fs.readFile('./files/input.txt', 'utf-8', (err, data) => {
  console.log('3');   // 回调最后执行
});
console.log('2');     // 同步代码先跑完
// 输出：1 2 3
```

异步 API 是"**发起**"而非"**等待**"——发起后主线程立刻往下走，回调等事件循环调度。

### 3.4 回调地狱（Callback Hell）

![[img/course-02-callback-nesting.jpg]]
*图 02-4 · 00:12:45 · 一层套一层的异步代码*

多个有依赖的异步操作会层层嵌套：

```js
fs.readFile('./files/start.txt', 'utf-8', (err, data1) => {
  fs.readFile(`./files/${data1}.txt`, 'utf-8', (err, data2) => {
    fs.appendFile('./files/output.txt', `${data1}\n${data2}\n`, (err) => {
      console.log('done');
    });
  });
});
```

缩进越来越深、错误处理重复三次、难以维护——这就是著名的 **Callback Hell**。课程后面通过[[03-构建HTTP服务器|重构]]逐步解耦；现代解法是 Promise / `async-await`，官方推荐直接用 [fs promises API](https://nodejs.org/docs/latest/api/fs.html#promises-api)：

```js
// 现代 Node（课程之后年份）的推荐写法，效果完全等价
const fs = require('node:fs/promises');

const data1 = await fs.readFile('./files/start.txt', 'utf-8');
const data2 = await fs.readFile(`./files/${data1}.txt`, 'utf-8');
await fs.appendFile('./files/output.txt', `${data1}\n${data2}\n`);
```

## 四、同步 / 异步 API 对照表

| 操作 | 同步（阻塞） | 异步（回调） | 现代 Promise |
|:---|:---|:---|:---|
| 读 | `readFileSync` | `readFile` | `fs.promises.readFile` |
| 覆盖写 | `writeFileSync` | `writeFile` | `fs.promises.writeFile` |
| 追加写 | `appendFileSync` | `appendFile` | `fs.promises.appendFile` |
| 重命名 | `renameSync` | `rename` | `fs.promises.rename` |
| 删除 | `unlinkSync` | `unlink` | `fs.promises.unlink` |

> [!danger] 生产环境铁律
> 服务器代码里**禁止同步 fs 方法**——一个慢磁盘上的 `readFileSync` 会卡死所有并发请求。同步方法只用于：启动时的配置读取、一次性脚本。

## 五、常见坑速查

| 坑 | 现象 | 解决 |
|:---|:---|:---|
| 忘写 `'utf-8'` | 输出 `<Buffer 48 65 ...>` | 加编码参数或 `.toString()` |
| 回调里没判 error | 程序崩溃 `throw err` | 永远先 `if (error) return …` |
| 想在回调外拿数据 | `let x; fs.readFile(…, (e,d)=>{x=d}); console.log(x)` 得 `undefined` | 异步数据只能在回调/Promise 内使用 |
| 异步循环里读多个文件 | 顺序不可预测 | 用 Promise.all 或 for…of + await |
