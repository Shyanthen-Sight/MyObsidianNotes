## 一、什么是路由（#11）

### 1.1 URL 的本质：资源定位

![[img/course-04-resource-url.jpg]]
*图 04-1 · 00:04:52 · Resource based URL*

```
www.nodeapp.com/home    ← home 就是"资源路径"，不是文件名
```

传统网站 URL 指向**文件**（`/files/about.html`）；现代 Web 的 URL 指向**资源**（resource-based URL），由服务器决定"这个路径返回什么内容"。同一个路径对浏览器返回 HTML、对 App 返回 JSON——**内容协商**。

### 1.2 路由 = 映射关系

**路由（Routing）就是"URL → 处理逻辑"的映射表**：

```
/        → 首页
/about   → 关于页
/contact → 联系页
其他     → 404
```

Express 中的路由器见 [[01-Express入门与RESTful设计]]；REST 风格下"同一个资源不同动作"见 [[02-CRUD接口实现]]。

## 二、手写路由（#12）

![[img/course-04-route-code.jpg]]
*图 04-2 · 00:05:14 · 用 path 判断实现路由（注意 VS Code 自动补全 res 方法）*

```js
const http = require('http');
const fs = require('fs');
const html = fs.readFileSync('./template/index.html', 'utf-8');

const server = http.createServer((request, response) => {
  const path = request.url.toLowerCase();

  if (path === '/' || path === '/home') {
    response.end(html.replace('{{CONTENT}}', 'You are in Home page'));
  } else if (path === '/about') {
    response.end(html.replace('{{CONTENT}}', 'You are in About page'));
  } else if (path === '/contact') {
    response.end(html.replace('{{CONTENT}}', 'You are in Contact page'));
  } else {
    response.writeHead(404, { 'Content-Type': 'text/html' });
    response.end(html.replace('{{CONTENT}}', 'Error 404: Page Not found!'));
  }
});

server.listen(8000, '127.0.0.1', () => console.log('Server has started!'));
```

三个工程细节：

1. `request.url.toLowerCase()` —— URL 大小写不敏感处理
2. **必须处理 else 分支**，否则未知路径请求会挂起直到超时
3. 404 要显式设置状态码 `writeHead(404, …)`，否则默认 200

> [!tip] 这段代码的问题
> 每个请求都执行 `fs.readFileSync` 读模板 → 同步阻塞 + 重复 IO。生产做法是**启动时读一次缓存到内存**，或者用 Express 的模板引擎。课程 #16 会继续演进这段代码。

## 四、响应头：告诉浏览器"这是什么"（#14）

### 4.1 为什么需要 Content-Type

响应体只是一串字节，浏览器靠 **Content-Type** 决定怎么解析：

| Content-Type | 浏览器行为 |
|:---|:---|
| `text/html` | 按 HTML 渲染 |
| `application/json` | 按 JSON 解析（前端 `response.json()` 才能用） |
| `text/plain` | 纯文本 |
| `image/png` | 当图片显示 |

> [!danger] 课程里最经典的坑
> 返回了 HTML 内容却没设置 `Content-Type: text/html`，浏览器把它当纯文本——**页面显示出一堆标签源码**。

### 4.2 writeHead：一次设置状态码 + 头

![[img/course-04-writehead.jpg]]
*图 04-5 · 00:05:57 · response.writeHead 设置状态码与 Content-Type*

```js
response.writeHead(200, {
  'Content-Type': 'text/html',
});
response.end(html.replace('{{CONTENT}}', 'Hello world!'));
```

`writeHead(statusCode, headers)` 等价于 `statusCode = 200` + `setHeader(...)` 的合写，且**必须在 `end()` 之前调用**。

常用状态码速记：

| 码 | 含义 |
|:---|:---|
| 200 | OK |
| 201 | Created（创建成功，POST 用） |
| 404 | Not Found |
| 500 | 服务器内部错误 |

状态码全景见 [MDN HTTP 状态码](https://developer.mozilla.org/zh-CN/docs/Web/HTTP/Status)。

## 五、常见坑速查

| 坑 | 现象 | 解决 |
|:---|:---|:---|
| 忘写 else 分支 | 未知路径浏览器一直转圈 | 补 404 兜底 |
| 没设 Content-Type | HTML 显示成源码 | `writeHead` 设置类型 |
| `writeHead` 写在 `end` 之后 | `ERR_HTTP_HEADERS_SENT` 崩溃 | 顺序：writeHead → write/end |
| URL 带查询串时路由失配 | `/about?x=1` 不等于 `/about` | 先用 `URL` 解析分离路径，见 [[05-JSON与查询字符串]] |
