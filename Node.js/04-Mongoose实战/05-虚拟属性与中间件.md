# 虚拟属性与 Mongoose 中间件

> [!abstract] 本篇定位
> 覆盖课程 #84–#87。两个"自动化"利器：**虚拟属性**——数据库没存、响应里却有的字段；**中间件（Hooks）**——save/query/aggregate 前后自动执行的钩子。它们是让业务逻辑住进 Model 层（[[04-Mongoose实战/02-MVC架构与Express实现CRUD|MVC 的 M]]）的工具。

## 一、虚拟属性 Virtual Properties（#84）

![虚拟属性 Schema 代码](img/course-mg05-virtual-schema.jpg)
*图 G5-01 · 视频 #84 · movieSchema：relDates/genres 虚拟字段与 totalGenres 逻辑*

数据库存的是 `releaseDate`（Date）和 `genres`（数组），API 想直接给 `durationInHour`、`totalGenres`——**不落库、动态算**的字段就是虚拟属性：

```javascript
const movieSchema = new mongoose.Schema({
  name:        { type: String, required: true },
  duration:    { type: Number, required: true },
  description: { type: String },
  ratings:     { type: Number },
  totalGenres: { type: Number },
  releaseDate: { type: Date },
  genres:      { type: [String], required: true },
}, {
  toJSON: { virtuals: true },       // ★ 不加这个，JSON 响应里看不到虚拟字段！
  toObject: { virtuals: true },
});

movieSchema.virtual('durationInHour').get(function () {
  return (this.duration / 60).toFixed(1);          // this = 当前文档
});

movieSchema.virtual('relDatesGenres')...           // 组合 releaseDate 与 genres 的展示串
```

要点：
- **不能被查询**：`find({ durationInHour: 2 })` 会报错——库里根本没这个字段；它只在读写文档对象时存在
- `get/set` 都可以定义，官方文档：[Virtuals](https://mongoosejs.com/docs/guide.html#virtuals)
- 常见用途：全名（姓+名）、派生价格（含税价）、API 兼容字段

## 二、Document Middleware（#85）：盯住 `save`

![Document Middleware 代码](img/course-mg05-doc-middleware.jpg)
*图 G5-02 · 视频 #85 · `pre('save')` 前计算 totalGenres、`post('save')` 打日志*

```javascript
// pre：文档保存【前】——最经典的用途是密码加密（[[06-认证与授权/01-用户模型与密码加密]]）
movieSchema.pre('save', function (next) {
  this.totalGenres = this.genres.length;    // this 指向被保存的文档
  next();                                   // ★ 忘了 next() 整个请求会挂起
});

// post：保存【后】（拿到的是已落库的文档，且 post 里不能再改 this）
movieSchema.post('save', function (doc, next) {
  const message = `New movie with name ${doc.name} has been created by ${doc.createdAt}`;
  console.log(message);
  next();
});
```

> [!important] 钩子的适用范围
> `pre('save')` 只在 `doc.save()` / `create()` 时触发；`findByIdAndUpdate` 等直接更新方法**不走** save 钩子——这正是下一节 Query Middleware 的存在意义。

## 三、Query Middleware（#86）：盯住查询

![Query Middleware 代码](img/course-mg05-query-middleware.jpg)
*图 G5-03 · 视频 #86 · `pre(/^find/)` 统一处理所有 find 类查询*

```javascript
// /^find/ 匹配 find/findOne/findOneAndUpdate… 所有以 find 开头的查询
movieSchema.pre(/^find/, function (next) {
  this.find({ releaseDate: { $lte: Date.now() } })   // this = Query 对象，可链式加条件
      .select('-private');                           // 顺便隐藏不想暴露的字段
  next();
});

// 给特定查询挂独享逻辑
movieSchema.post('findOne', function (doc, next) {
  console.log(`Fetched ${doc?.name}`);
  next();
});
```

典型用途：软删除过滤、按用户隔离数据、统计查询次数——**业务规则不写进每个控制器，写一次全生效**。

## 四、Aggregation Middleware（#87）：盯住管道

![Aggregation Middleware 代码](img/course-mg05-agg-middleware.jpg)
*图 G5-04 · 视频 #87 · `pre('aggregate')` 往管道头部插 $match，并对比统计输出*

```javascript
movieSchema.pre('aggregate', function (next) {
  // this.pipeline() 是当前聚合的 stage 数组
  this.pipeline().unshift({ $match: { ratings: { $gte: 3.0 } } });
  next();
});
```

因为 [[04-Mongoose实战/04-聚合管道|聚合返回的不是文档]]，不走 save/query 钩子，所以聚合的前置过滤必须用这第三个钩子——三类中间件正好覆盖三种数据通道。

## 五、三类钩子总览

| 类型 | 监听对象 | this 指向 | 典型用途 |
| :--- | :--- | :--- | :--- |
| Document | `save` / `validate` | 文档 | 字段加工、**密码加密** |
| Query | `find*` 等 | Query 对象 | 软删过滤、权限隔离 |
| Aggregate | `aggregate` | 管道 | 全局前置 `$match` |

官方文档：[Mongoose Middleware](https://mongoosejs.com/docs/middleware.html)
