# 数据验证器（Built-in 与 Custom）

> [!abstract] 本篇定位
> 覆盖课程 #88–#89，第四板块收官。Schema 不只是"声明字段类型"，还能**拒绝脏数据**：内建验证器开箱即用，自定义验证器处理一切业务规则。验证失败的统一出口在 [[05-错误处理/03-开发与生产错误与常见错误类型|错误处理板块]]。

## 一、内建验证器（#88）

![内建验证器报错现场](img/course-mg06-builtin-validators.jpg)
*图 G6-01 · 视频 #88 · Postman POST 违规数据时收到 "Name must not be greater than 100 characters"*

```javascript
const movieSchema = new mongoose.Schema({
  name: {
    type: String,
    required: [true, 'Name is required field!'],       // 必填 + 自定义消息
    unique: true,                                       // 唯一索引（底层是 MongoDB，不是验证器）
    trim: true,                                         // 存前去首尾空格
    maxlength: [100, 'Movie name must not have more than 100 characters'],
    minlength: [3, 'Movie name must have at least 3 characters'],
  },
  description: { type: String, trim: true, required: true },
  duration:   { type: Number, required: [true, 'Duration is required field!'] },
  ratings:    {
    type: Number,
    validate: { validator: v => v <= 10, message: 'Ratings should be less than or equal 10' },
  },
});
```

按类型速查（官方：[Validation](https://mongoosejs.com/docs/validation.html)）：

| 类型 | 内建验证器 |
| :--- | :--- |
| String | `required` `enum` `match`(正则) `minlength` `maxlength` `trim` `lowercase/uppercase` |
| Number | `required` `min` `max` `enum` |
| Date | `required` `min` `max` |
| 所有 | `validate`（自定义）、`default` |

> [!important] `unique` 的真相
> 它**不是验证器**——Mongoose 只是把它转成 MongoDB 的唯一索引。因此它的报错不是 `ValidationError` 而是 `E11000 duplicate key`，处理方式完全不同（见 [[05-错误处理/03-开发与生产错误与常见错误类型]]）。

验证时机：
- `save()` / `create()` 前自动跑（`pre('validate')` 之后）
- `findByIdAndUpdate` **默认不跑**，要 `{ runValidators: true }`（[[04-Mongoose实战/02-MVC架构与Express实现CRUD|见 CRUD 篇]]）
- `Model.validate()` 可手动触发

## 二、自定义验证器（#89）

![自定义验证器代码](img/course-mg06-custom-validators.jpg)
*图 G6-02 · 视频 #89 · ratings 的 validator 函数与异步自定义验证*

```javascript
ratings: {
  type: Number,
  min: [1, 'Ratings must be above 1.0'],
  max: [10, 'Ratings must be below 10.0'],
  validate: {
    validator: (val) => val <= 10 && val >= 1,     // 返回 false = 校验失败
    message: 'Ratings must be below 10 and above 1',
  },
},

// 更复杂的业务规则：genres 非空且每项都不重复
genres: {
  type: [String],
  required: true,
  validate: {
    validator: (arr) => arr && arr.length > 0 && new Set(arr).size === arr.length,
    message: 'Genres must be provided and non-duplicated',
  },
},
```

要点：
- validator 返回 `true/false`（或 Promise → **异步验证**，比如查库确认邮箱没被注册，[[06-认证与授权/01-用户模型与密码加密|用户模块]] 实战）
- 失败时 `ValidationError` 的 `errors` 对象里按字段收集 `{ message, value, path }`——全局错误处理靠它生成友好响应
- 也可以在 SchemaType 的 `validate` 数组里挂多个验证器，逐个执行

## 三、验证结果长什么样

```javascript
// testMovie.save() 失败时 catch 到的 err：
// ValidationError: Movie validation failed:
//   name: Movie name must have at least 3 characters
//   ratings: Ratings must be below 10 and above 1
err.errors.ratings.message   // 逐字段取消息
err.errors.ratings.value     // 被拒绝的值
err.errors.ratings.path      // 字段名
```
